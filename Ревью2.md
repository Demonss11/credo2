## Критично

### 1. `publish` не защищает себя от невалидного `contract.version`

**Локация:** `lib.rs::publish`

```rust
pub fn publish(repo, rule, contract: &CheckContract, version_raw: &str, ...) -> Result<...> {
    let version = Semver::parse(version_raw)?;
    let vstr = version.to_string();
    let path = format!("checks/{}/{}", rule.name, vstr);
    // ...
    checksum: checksum_of(rule, contract)?,  // ← contract.version = что дал вызывающий
```

Работает только потому, что `mcp.rs` нормализует контракт заранее. Любой другой вызывающий (CLI, тест, будущий инструмент) забудет — и получит `path = .../1.0.0/`, `meta.version = "1.0.0"`, `contract.version = "v1.0.0"`. `list_from_ref` это **не поймает** (проверяется только `meta.version == path`).

**Фикс — внутри `publish`:**

```rust
pub fn publish(
    repo: &Path,
    rule: &Rule,
    contract: &CheckContract,
    version_raw: &str,
    published_by: &str,
) -> Result<PublishOutcome> {
    ensure_repo(repo)?;
    let version = Semver::parse(version_raw)
        .map_err(|e| anyhow!("невалидная версия {version_raw:?}: {e}"))?;
    let vstr = version.to_string();

    // Контракт — производное от версии; не доверяем вызывающему.
    let mut contract = contract.clone();
    contract.version = vstr.clone();
    let contract = &contract;

    // дальше всё как было, но с нормализованным contract
    let path = format!("checks/{}/{}", rule.name, vstr);
    // ...
    checksum: checksum_of(rule, contract)?,
```

Тогда `mcp.rs::publish` упрощается — достаточно передать `contract_from_rule(&rule, version_raw)`, `publish` сделает нормализацию.

Добавь страховочный тест:

```rust
#[test]
fn publish_normalizes_contract_version() {
    let t = tmp_repo();
    let r = rule_with("x");
    let raw = contract_from_rule(&r, "v1.0.0"); // сырой, с префиксом
    publish(t.path(), &r, &raw, "v1.0.0", "t").unwrap();
    merge_branch(t.path(), "publish/CreditAgeMin-1.0.0");

    let c = &list_from_ref(t.path(), "main").unwrap()[0];
    assert_eq!(c.contract.version, "1.0.0");
    assert_eq!(c.version, "1.0.0");
    assert_eq!(c.meta.version, "1.0.0");
}
```

### 2. Регрессия: интеграционные тесты публикации потеряны

В прошлой версии были:
- `rejects_duplicate_version`
- `rejects_downgrade`
- `rejects_contract_change_without_major`
- `allows_major_bump_with_contract_change`
- `allows_patch_without_contract_change`
- `meta_version_matches_path`
- `manifest_hash_is_deterministic`

Сейчас в `lib.rs::tests` только `manifest_hash_changes_on_deprecation`. **Ядро бизнес-логики (валидация publish) не покрыто.** Это самая важная регрессия в этой итерации.

Верни их. Заодно закрой пробел, который тесты ловили бы:

```rust
#[cfg(test)]
mod tests {
    use super::*;
    use crate::core::{Action, Condition, Value, contract_from_rule, parse_rule};

    fn tmp_repo() -> tempfile::TempDir {
        let t = tempfile::tempdir().unwrap();
        ensure_repo(t.path()).unwrap();
        t
    }

    fn rule_with(name: &str, field: &str) -> Rule {
        parse_rule(&format!(
            "Правило {name} {{ Если ({field} < 21) {{ Решение = Отказ; Причина = \"x\"; }} }}"
        )).unwrap()
    }

    fn merge_branch(repo: &Path, branch: &str) {
        // publish() создаёт ветку как child of main → fast-forward
        let commit = rev_parse(repo, branch).unwrap();
        update_ref(repo, "refs/heads/main", &commit).unwrap();
    }

    #[test]
    fn rejects_duplicate_version() {
        let t = tmp_repo();
        let r = rule_with("CreditAgeMin", "Возраст");
        let c = contract_from_rule(&r, "1.0.0");
        publish(t.path(), &r, &c, "1.0.0", "t").unwrap();
        merge_branch(t.path(), "publish/CreditAgeMin-1.0.0");

        let err = publish(t.path(), &r, &c, "1.0.0", "t").unwrap_err();
        assert!(err.to_string().contains("уже существует"));
    }

    #[test]
    fn rejects_downgrade() {
        let t = tmp_repo();
        let r = rule_with("CreditAgeMin", "Возраст");
        publish(t.path(), &r, &contract_from_rule(&r, "1.0.0"), "1.0.0", "t").unwrap();
        merge_branch(t.path(), "publish/CreditAgeMin-1.0.0");

        let err = publish(t.path(), &r, &contract_from_rule(&r, "0.9.0"), "0.9.0", "t").unwrap_err();
        assert!(err.to_string().contains("не больше максимальной"));
        assert!(err.to_string().contains("downgrade запрещён"));
    }

    #[test]
    fn rejects_contract_change_without_major() {
        let t = tmp_repo();
        let r1 = rule_with("CreditAgeMin", "Возраст");
        publish(t.path(), &r1, &contract_from_rule(&r1, "1.0.0"), "1.0.0", "t").unwrap();
        merge_branch(t.path(), "publish/CreditAgeMin-1.0.0");

        let r2 = rule_with("CreditAgeMin", "Доход");
        let err = publish(t.path(), &r2, &contract_from_rule(&r2, "1.1.0"), "1.1.0", "t").unwrap_err();
        assert!(err.to_string().contains("контракт изменился"));
        assert!(err.to_string().contains("MAJOR"));
    }

    #[test]
    fn allows_major_bump_with_contract_change() {
        let t = tmp_repo();
        let r1 = rule_with("CreditAgeMin", "Возраст");
        publish(t.path(), &r1, &contract_from_rule(&r1, "1.0.0"), "1.0.0", "t").unwrap();
        merge_branch(t.path(), "publish/CreditAgeMin-1.0.0");

        let r2 = rule_with("CreditAgeMin", "Доход");
        publish(t.path(), &r2, &contract_from_rule(&r2, "2.0.0"), "2.0.0", "t").unwrap();
    }

    #[test]
    fn allows_patch_without_contract_change() {
        let t = tmp_repo();
        let r = rule_with("CreditAgeMin", "Возраст");
        publish(t.path(), &r, &contract_from_rule(&r, "1.0.0"), "1.0.0", "t").unwrap();
        merge_branch(t.path(), "publish/CreditAgeMin-1.0.0");
        publish(t.path(), &r, &contract_from_rule(&r, "1.0.1"), "1.0.1", "t").unwrap();
    }

    #[test]
    fn meta_version_matches_path() {
        let t = tmp_repo();
        let r = rule_with("CreditAgeMin", "Возраст");
        publish(t.path(), &r, &contract_from_rule(&r, "1.0.0"), "1.0.0", "t").unwrap();
        merge_branch(t.path(), "publish/CreditAgeMin-1.0.0");
        let checks = list_from_ref(t.path(), "main").unwrap();
        assert_eq!(checks.len(), 1);
        assert_eq!(checks[0].meta.version, checks[0].version);
        assert_eq!(checks[0].meta.name, checks[0].name);
        assert!(checks[0].meta.checksum.starts_with("sha256:"));
    }

    #[test]
    fn merge_preserves_other_checks() {
        let t = tmp_repo();
        let r1 = rule_with("CreditAgeMin", "Возраст");
        publish(t.path(), &r1, &contract_from_rule(&r1, "1.0.0"), "1.0.0", "t").unwrap();
        merge_branch(t.path(), "publish/CreditAgeMin-1.0.0");

        let r2 = rule_with("OtherCheck", "Сумма");
        publish(t.path(), &r2, &contract_from_rule(&r2, "1.0.0"), "1.0.0", "t").unwrap();
        merge_branch(t.path(), "publish/OtherCheck-1.0.0");

        let checks = list_from_ref(t.path(), "main").unwrap();
        assert_eq!(checks.len(), 2); // ← ловит squash-merge
    }

    #[test]
    fn create_ref_prevents_double_publish() {
        let t = tmp_repo();
        let r = rule_with("CreditAgeMin", "Возраст");
        publish(t.path(), &r, &contract_from_rule(&r, "1.0.0"), "1.0.0", "t").unwrap();
        // Второй раз та же ветка — должна упасть

        assert!(err.to_string().contains("уже существует") || err.to_string().contains("ветка"));
    }
}
```

## Important

### 3. `ensure_repo` — неверный маркер bare

**Локация:** `lib.rs::ensure_repo`

```rust
if repo.join("HEAD").exists() { return Ok(()); }
```

`HEAD` есть и в рабочем репозитории. Если кто-то укажет на рабочий репо — функция молча продолжит.

**Фикс:**

```rust
pub fn ensure_repo(repo: &Path) -> Result<()> {
    let is_bare = repo.join("objects").is_dir()
        && repo.join("refs").is_dir()
        && !repo.join(".git").exists();
    if is_bare { return Ok(()); }
    // ...
}
```

### 4. `Semver::parse` пропускает пустые сегменты в pre/build

**Локация:** `core.rs::Semver::parse`

`1.0.0-.rc` → split `-` даёт pre=`".rc"`, байтовая проверка проходит. По спеке — идентификатор не может начинаться с точки. То же для `1.0.0-rc.` (заканчивается точкой) и `1.0.0-rc..1` (пустой сегмент в середине).

**Фикс — после байтовой проверки:**

```rust
for seg in b.split('.') {
    if seg.is_empty() {
        bail!("пустой идентификатор в pre-release");
    }
}
```

Аналогично для build.

Тесты:

```rust
#[test] fn rejects_leading_dot_in_pre() { assert!(Semver::parse("1.0.0-.rc").is_err()); }
#[test] fn rejects_trailing_dot_in_pre() { assert!(Semver::parse("1.0.0-rc.").is_err()); }
#[test] fn rejects_empty_segment_in_pre() { assert!(Semver::parse("1.0.0-rc..1").is_err()); }
```

### 5. `write_manifest_to_main` — лишний `hash_blob -w`

```rust
if let Ok(existing) = show_file(repo, "main", "manifest.json") {
    let existing_sha = hash_blob(repo, &existing)?;  // ← пишет существующий blob ещё раз
    if existing_sha == new_sha { return Ok(None); }
}
```

`hash_blob` пишет объект в БД. Для сравнения это избыточно.

**Фикс:**

```rust
if let Ok(existing_sha) = rev_parse(repo, "main:manifest.json") {
    if existing_sha == new_sha { return Ok(None); }
}
```

`rev-parse main:manifest.json` возвращает SHA blob напрямую.

### 6. `manifest.json` в main всё ещё никем не читается

`ServiceCache::read_state` снова дёргает `list_from_ref(repo, "main")`, а не `show_file(repo, "main", "manifest.json")`. Манифест персистится, но используется только как audit trail. Это всё ещё гибрид.

**Решить сейчас:**

- **(а)** Убрать `write_manifest_to_main` и `check.rebuild_manifest` — манифест генерится в памяти, `service_hash` — часть ответа REST, не часть хранилища.
- **(б)** Сделать манифест источником истины и читать его в `read_state`, оставив `list_from_ref` только для наполнения `checks` в кэше.

Я рекомендую (а): меньше кода, нет риска расхождения, `main` остаётся единственным источником.

### 7. `check.publish` — `next_step` вводит в заблуждение

```
"Откройте PR из '...' в 'main' репозитория {}. После мержа вызовите check.rebuild_manifest."
```

В bare-репо нет remote, нет PR. Мерж — локальный `update-ref`. И при выборе (а) из #6 `rebuild_manifest` не нужен.

**Правь на:**

```
"Ветка '{branch}' создана в {repo}. Смержить: \
 `git -C <repo> update-ref refs/heads/main $(git -C <repo> rev-parse <branch>)`. \
 REST подхватит автоматически в течение 2 с."
```

## Minor

### 8. `+build` в пути хранилища

`Semver::to_string()` включает `+build`. `publish ... "1.2.3+build.7"` создаст путь `checks/Name/1.2.3+build.7/`. Ни Docker, ни npm, ни Maven так не делают.

**Фикс — добавить `as_storage()`:**

```rust
impl Semver {
    pub fn as_storage(&self) -> String {
        let base = format!("{}.{}.{}", self.major, self.minor, self.patch);
        match &self.pre {
            Some(p) => format!("{base}-{p}"),
            None => base,
        }
        // build игнорируется
    }
}
```

И в `publish` использовать `version.as_storage()` для пути и `meta.version`.

### 9. `Draft.contract` — балласт

Устанавливается в `make_draft` с версией `"0.0.0"` и никогда не обновляется. При `check.get_draft` клиент видит фиктивный контракт. Удали поле — `contract` должен генериться на лету там, где нужен.

### 10. Leading zeros в numeric сегментах

`Semver::parse("01.2.3")` → `Ok(1.2.3)`. Спека semver запрещает leading zeros в numeric identifiers.

```rust
fn parse_num(s: &str) -> Result<u64> {
    if s.is_empty() || !s.bytes().all(|b| b.is_ascii_digit()) {
        bail!("компонент не число: {s:?}");
    }
    if s.len() > 1 && s.starts_with('0') {
        bail!("leading zero: {s:?}");
    }
    s.parse().map_err(|_| anyhow!("компонент слишком велик"))
}
```

### 11. Pre-release lexicographic — всё ещё TODO

`rc10 < rc2` лексикографически. Игнорируемый тест фиксирует проблему. ~20 строк на числовое сравнение по сегментам — стоит сделать сразу, чтобы не возвращаться.

### 12. `check.rebuild_manifest` возвращает `service_hash` без гарантии записи

```rust
async fn rebuild_manifest_inner(&self) -> anyhow::Result<String> {
    self.cache.reload().await?;
    let manifest = self.cache.manifest().await;
    // ...
    write_manifest_to_main(&repo, &m).await??; // ← Ok(None) если не изменилось
    Ok(manifest.service_hash)
}
```

Если `write_manifest_to_main` вернул `Ok(None)` (нечего писать), клиент всё равно видит `status: ok` и `service_hash`. Семантически ок, но стоит вернуть `{ written: bool }` — для диагностики.
