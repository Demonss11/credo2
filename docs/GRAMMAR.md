# GRAMMAR — каноническая грамматика DAR v0.1

> Нормативный документ; единственный источник истины по синтаксису DSL v0.1.
> Иные описания языка (`concept.md`, `SPECIFICATION.md`, фичи) — производные; при
> расхождении действует настоящий файл.

## 1. Синтаксис правила v0.1

```ebnf
Правило   ::= "Правило" Пробел Имя Пробел Блок ;
Имя       ::= Letter { Letter | Digit | "_" } ;   (* в т.ч. кириллица \w+ *)
Блок      ::= "{" { WS } Если БлокУсловия { WS} "}" ;
Если      ::= "Если" { WS } "(" { WS }
              Поле { WS } Оператор { WS } Значение { WS } ")" ;
Поле      ::= Ident { "." Ident } ;               (* напр. Клиент.Возраст *)
Оператор  ::= "<" | ">" | "==" | "!=" ;           (* v0.1: без <= >= *)
Значение  ::= Число | Строка ;
Число     ::= ["-"] Digit { Digit } [ "." Digit { Digit } ] ;
Строка    ::= '"' { ЛюбойСимволКроме'"' } '"' ;
БлокУсловия ::= "{" { WS } Решение "=" Имя ";"
                [ { WS } Причина "=" Строка ";" ] { WS} "}" ;
Решение   ::= "Решение" ;
Причина   ::= "Причина" ;
Комментарий ::= "//" до конца строки ;             (* игнорируется *)
```

Пример (канонический):

```dar
// Правило возрастного ценза
Правило МинимальныйВозраст {
  Если (Клиент.Возраст < 21) {
    Решение = Отказ;
    Причина = "Возраст меньше 21";
  }
}
```

## 2. Ограничения v0.1 (regex-минимум)

| # | Ограничение | Последствие |
|---|---|---|
| 1 | Одно правило в файле | Конвейеры — вне v0.1 ([`D18`](decisions/D18-pipelines-out-lsp-mvp.md)) |
| 2 | Одно сравнение в `Если (...)` | Нет `И`/`ИЛИ`, скобочных групп |
| 3 | Операторы только `< > == !=` | `<=`/`>=` — план v0.2 |
| 4 | Нет ключевых слов `Тогда`, `Приоритет`, doc-блоков `:::` | См. §4 |
| 5 | `Причина` опциональна (пустая строка по умолчанию) | — |
| 6 | Числа — `f64` ([`D13`](decisions/D13-f64-mvp-decimal-v02.md)), строки — в двойных кавычках | `Decimal` в v0.2 |
| 7 | Ошибки парсинга — текстовые (`String`): «Не найдено имя правила», «Не найдено условие», «Не найдено решение» | Типизированные ошибки и позиции — план v0.2 |
| 8 | Комментарии вырезаются парсером, но не анализируются | code=doc через Notebook, не язык |

## 3. Стратегия LSP-совместимости

Парсер MVP — regex-минимум (`dar-core::parse_rule`); лексер и полноценный AST в
v0.1 не входят. Грамматика v0.1 — подмножество целевого языка, а работа с `.dar`
идёт только через `parse_rule`, поэтому MVP-парсер не противоречит планируемому
LSP — [`D16`](decisions/D16-dsl-canon-regex-mvp.md),
[`D6`](decisions/D6-lsp-degradation.md).

## 4. Ключевые слова: статусы

| Ключевое слово | v0.1 | Источник | Примечание |
|---|---|---|---|
| `Правило` | ✅ | здесь, `SPECIFICATION.md` | — |
| `Если` | ✅ | здесь, `SPECIFICATION.md` | — |
| `Решение` | ✅ | здесь, `SPECIFICATION.md` | — |
| `Причина` | ✅ | здесь | обязательна в explain-фичах, опц. в v0.1 |
| `Тогда` | ❌ | `concept.md` | отклонено: действие выражено `Решение=` |
| `Приоритет` | ❌ | фичи | вне MVP, вернётся с конвейерами ([`D17`](decisions/D17-priority-out-of-mvp.md)) |
| `:::` doc-блоки | ❌ | `concept.md` (видение) | отклонено: вместо них `//` ([`D1`](decisions/D1-comment-syntax.md)) |

([`D17`](decisions/D17-priority-out-of-mvp.md),
[`D18`](decisions/D18-pipelines-out-lsp-mvp.md)), полный набор диагностик LSP
