## Контекст

`SPECIFICATION.md` §4.2 фиксировал порт 8080, тогда как код (`src/main.rs`)
использовал `127.0.0.1:8080` по умолчанию и не поднимал REST, если не передан
`--rest`/`--addr`; фичи запуск не описывали. Нужно было снять расхождение
формулировки SPEC и зафиксировать канон запуска. Полный контекст —
[Q27](../questions/Q27.md).

## Решение

1. **Адрес REST по умолчанию — `127.0.0.1:8080`.** Порт 8080 зафиксирован вместе
   с хостом; `127.0.0.1` (loopback) — безопасное значение по умолчанию.
2. **REST поднимается только по явному флагу:** `--rest` (адрес по умолчанию)
   или `--addr <ADDR>` (включает REST на указанном адресе). **Без флагов —
   штатный режим «только MCP (stdio)».** Приоритет флагов:
   `--no-rest` > `--addr` > `--rest`.
3. **Наружное развёртывание — через `--addr`** (например,
   `--addr 0.0.0.0:8080`); отдельного конфига/переменной порта в MVP нет.
4. **Режим «только MCP» согласуется с Notebook-сценариями** ([Q30](../questions/Q30.md),
   решение [D29](D29-notebook-mcp-transport.md): локальный stdio-процесс) и
   является режимом демо по умолчанию.
5. **Следствие для кода: правок не требуется** — реализация совпадает с
   принятым решением.

  `--addr <ADDR>` → MCP + REST на `<ADDR>`; `--no-rest` → только MCP),

## Альтернативы

- **REST по умолчанию, без флага** — отклонено: неявно открывает порт и
  противоречит штатному stdio-only режиму Notebook-демо (Q30).
- **Адрес по умолчанию `0.0.0.0:8080`** — отклонено: loopback безопаснее;
  наружное развёртывание задаётся явным `--addr`.
- **Отдельный конфиг/переменная порта в MVP** — отклонено: YAGNI, флагов
  `--rest`/`--addr` достаточно; конфиг может вернуться пост-MVP.
