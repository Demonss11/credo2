# D50: DoD `validator` по составу пакета — cargo только при изменениях кода

- **Статус:** accepted
- **Дата:** 2026-09-29
- **Resolves:** [Q55](../questions/Q55.md)
- **Спека:** [`SPECIFICATION.md`](../SPECIFICATION.md) §10, решение №50
- **Affects:** [`review.md`](../../.opencode/rules/review.md) §«Порог
  существенности»; [`validator.md`](../../.opencode/agents/validator.md)
  (чек-лист «Документы и агенты», строка про счётчики
  `docs/features/README.md`); [`BRIEF.md`](../BRIEF.md) §5.7
- **Tasks:** — (см. «Сверка с кодом»)

## Контекст

При приёмке docs-пакетов переноса журнала (Q2/Q3, Q4, Q5/Q6) `validator`
запускал `cargo fmt --check` и `cargo test --test features_inventory`, хотя
`src/**`/`tests/**` не менялись, — лишний расход шагов и токенов роли (бюджет
`steps` — [D44](../decisions/D44-run5-refinements.md)). Причиной послужило
расхождение трёх действующих текстов канона:

- [`review.md`](../../.opencode/rules/review.md) §«Порог существенности»
  (стр. 28–33): механические docs-правки → **адресная** проверка изменённых
  файлов, cargo не упомянут;
- [`validator.md`](../../.opencode/agents/validator.md) (стр. 87):
  «счётчики `docs/features/README.md` согласованы **с тестом**
  `features_inventory`» — читается как обязательный cargo-прогон;
- [`BRIEF.md`](../BRIEF.md) §5.7: DoD прототипа (`cargo fmt --check`,
  `cargo clippy …`, `cargo test --all`) без оговорки про docs-пакеты.

Полный контекст — [Q55](../questions/Q55.md), лента
`service-dod-scope.md` (`.opencode/mail/**`).

## Решение

1. **Пакет без изменений `src/**`, `tests/**`, `Cargo.toml`** — cargo-прогоны у
   `validator` **не выполняются**. Приёмка — адресной проверкой изменённых
   документов (живость ссылок, отсутствие дублей канона по Q41, согласованность
   статусов и полей [BRIEF](../BRIEF.md) §5.7).
   *(уточнено 29.09.2026 при аудите: перечень дополнен `Cargo.toml` — зона
   `coder`; `review.md`/`BRIEF.md` синхронизированы)*
2. **Исключение — правки счётчиков или состава сценариев
   `docs/features/**`** (числа счётчиков, список файлов, блоки `Сценарий:`
   / `Структура сценария:`): тогда выполняется **адресный**
   `cargo test --test features_inventory`. Для остальных docs-правок (статусы,
   CHANGELOG, ссылки, строки §10, TRACEABILITY) — только адресная проверка,
   cargo не запускается.
3. **Полный DoD** (`cargo fmt --check`, `cargo clippy --all-targets --
   -D warnings`, `cargo test --all`) остаётся обязательным у кодовых пакетов
   (изменения `src/**`, `tests/**`, `Cargo.toml`; `Cargo.toml` — зона `coder`) —
   правило не меняется.
4. **Синхронизация канона** (вносит сервисная сессия / `docs-writer`, не
   `migrator`): `review.md` §«Порог существенности» — оговорка про состав
   пакета; `validator.md` чек-лист «Документы и агенты» — строка про счётчики
   формулируется как триггер `features_inventory`, а не общий cargo-прогон;
   `BRIEF.md` §5.7 — DoD прототипа с оговоркой про docs-пакеты.
   Синхронизация выполнена 29.09.2026; перечень состава пакета в `review.md` и
   `BRIEF.md` включает `Cargo.toml` (см. «Сверка с кодом»).

## Следствия

- Экономия шагов и токенов `validator` на docs-пакетах (бюджет `steps`,
  [D44](../decisions/D44-run5-refinements.md)); приёмка docs идёт быстрее.
- Полный DoD сохраняется у кодовых пакетов — покрытие продукта не снижается.
- Машинная проверка счётчиков `features_inventory` выполняется при реальных
  правках счётчиков/состава сценариев и в полном DoD; адресный прогон —
  по-прежнему только `validator`.
- Расхождение трёх текстов канона устраняется правками `review.md`,
  `validator.md`, `BRIEF.md` §5.7 (отдельными шагами после журнала); до их
  внесения формулировки остаются историческими (выполнено 29.09.2026 — см. ниже).
- Синхронизация канона выполнена 29.09.2026: `review.md` §«Порог
  существенности» (стр. 29, 35), `validator.md` чек-лист «Документы и агенты»
  (стр. 87–89) и `BRIEF.md` §5.7 (стр. 253) включают `Cargo.toml` в перечень
  состава пакета (уточнение при аудите).

## Сверка с кодом

Вердикт: ⚪ **не применимо** — решение процессное/документное, продуктовое
поведение и код `src/**` не меняет (образцы — [D44](../decisions/D44-run5-refinements.md),
[D49](../decisions/D49-validator-branch-contains.md)).

Что проверено (29.09.2026, файлами): расхождение трёх действующих текстов —
[`review.md`](../../.opencode/rules/review.md) (стр. 28–33: docs → адресная
проверка, cargo не упомянут), [`validator.md`](../../.opencode/agents/validator.md)
(стр. 87: «счётчики … согласованы с тестом `features_inventory`»),
[`BRIEF.md`](../BRIEF.md) §5.7 (DoD без оговорки про docs-пакеты); факты
прогонов — лента
`service-dod-scope.md` (`.opencode/mail/**`).
Уточнение при аудите (29.09.2026): перечень состава пакета в `review.md`
§«Порог существенности» (стр. 29, 35), `validator.md` (стр. 87–89) и
`BRIEF.md` §5.7 (стр. 253) включает `Cargo.toml` — расхождение снято.
После внесения правок (выполнено 29.09.2026; сервисная сессия / `docs-writer`) —
адресные проверки
изменённых текстов и, если потребуется, `cargo test --test features_inventory`
на приёмке (выполняет `validator`). `cargo` при подготовке записи не
запускался. Задач не требуется: канон вносят сервисная сессия владельца и
`docs-writer`; продуктовый код и `tests/**` не затрагиваются.

## Альтернативы

- **Оставить как есть** (вариант (а) [Q55](../questions/Q55.md)) — cargo-прогоны
  на docs-пакетах без изменений кода. Отклонено: расход бюджета роли без пользы,
  регрессий при неизменных `src/tests`/`Cargo.toml` быть не может.
- **Полностью без cargo при отсутствии изменений `src/tests`/`Cargo.toml`**
  (вариант (б)) —
  просто, но при реальных правках счётчиков `docs/features/**` машинная сверка
  с [`tests/features_inventory.rs`](../../tests/features_inventory.rs) не
  выполняется, рассинхрон сводки и теста не ловится. Отклонено: вариант (в)
  сохраняет проверку там, где она проверяет артефакт.
