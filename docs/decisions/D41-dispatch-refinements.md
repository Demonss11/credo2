## Контекст

Пилот Run 3 (T-03, итерации 1–2) на цикле диспетчера
([D39](D39-loop-dispatcher.md)) дошёл до приёмки, но выявил процессные
расхождения: исключение роли из маршрута M без канонической формы (F1),
семантика матчинга прав и «узкие команды» (F4/A3), отставание
`current_state.yaml` (F5), текстовые вопросы владельцу и незафиксированный
канал (F8/F12), пропуск файла в git-пакете (F9), неописанное частичное
исполнение пакета и override владельца (F10), финальный re-plan без записи
`progress.yaml` (F13), плюс предложения W7 §2–§4 и ответы владельца §8.
Полный контекст — [Q46](../questions/Q46.md),
[`memorandum-W6-run3.md`](../analysis/memorandum-W6-run3.md),
[`memorandum-W6-run3-it2.md`](../analysis/memorandum-W6-run3-it2.md),
[`W7-preRUN4_T-03.md`](../analysis/W7-preRUN4_T-03.md).

## Решение

1. **Маршрут M** (F1): `analyst` вправе исключить роль из маршрута — для S
   штатно; для M с письменным обоснованием в досье (`route_exclusions`: роль и
   чем закрыты её риски); для L — полный маршрут, исключений нет.
2. **Узкие команды** (F4/A3): команды одиночные (без `;`, `|`, `>`, `2>`,
   `&&`); команда отклонена — сузить до ближайшего allow-паттерна; сужение
   невозможно — `surface_to_user`. Расширение allow-листов — только после
   research-шага (T-13, F4).
3. **Git-пакет — сверка перед гейтом** (F9): до `surface_to_user` `analyst`
   сверяет `package.add_paths` со снимком `git status --porcelain`;
   расхождение — re-plan до гейта; `lead` пакет не расширяет.
4. **Частичное исполнение/override владельца** (F10): владелец может
   отменить/сузить подтверждённый пакет; выполненная часть фиксируется
   (`cancelled_by_owner`/`deferred`), остаток — в `next_action` (`package` +
   `resume_hint`); возобновление — новым подтверждением; `complete` — только
   после полного closeout; `git` идемпотентен (повторный add/commit не
   выполняется).
5. **`surface_to_user` — всегда `question`** (F8): 1–3 вопроса, 2–4 варианта,
   один `(Recommended)`; каждая запись в `progress.yaml` содержит
   `channel: question|text` (F12).
6. **Авторитет состояния** (F5): `receipts.yaml` — авторитет;
   `current_state.yaml` — снимок на момент последнего re-plan (поле `as_of`);
   статусный ответ владельцу — по `receipts.yaml`.
7. **Финализация записи действия** (F13): действие завершено только после
   записи в `progress.yaml`; при приближении к лимиту шагов — сначала запись,
   затем остановка.
8. **Порог меморандума** (W7 §3.1): меморандум — при ≥ 3 существенных находках
   или при закрытии прогона; одиночные находки — в реестр находок.
9. **Реестр находок** (W7 §4.1): `docs/analysis/findings-registry.md` — ID
   находок берутся оттуда, не локальные F-номера.
10. **Pre-flight чек-лист** (W7 §4.2): `docs/analysis/run-checklist.md` — ≤ 10
    строк перед прогоном (ветка чистая; `state/` переинициализирован;
    `debug agents` — роли резолвятся; `.gitignore` соответствует политике;
    отчёты прошлых прогонов на месте; нет незакоммиченного канона).
11. **Терминология** (W7 §4.3): `iteration` — rework-цикл задачи; `session` —
    один запуск `lead`.
12. **Политика mail/memory** (W7 §2.1, ответ §8.1): подтверждается текущая —
    mail и memory трекаются как рабочие данные, `state/` вне git; §2.2: memory
    — «знание роли» (паттерны, грабли, ссылки), чекпойнты задач — в `state/`;
    cap ленты (W7 §2.3): секции `## iteration N`, сплит при ~300+ строках.
13. **Синхронизация GRAMMAR §7** (F11): сообщение парсера — единственный
    источник строки ошибки; [`GRAMMAR.md`](../GRAMMAR.md) §7 синхронизируется
    отдельной docs-задачей после прогона (правка канона языка — вне границ M) —
    [T-14](../tasks/T-14-grammar-message-sync/README.md).

## Следствия

- Run 4 (T-03 заново) идёт по уточнённому канону: маршрут M с обоснованными
  исключениями, узкие команды, сверка пакета перед гейтом, фиксация канала и
  состояния;
- вводятся артефакты `docs/analysis/findings-registry.md` и
  `docs/analysis/run-checklist.md` (создание — T-13);
- шаблон досье и памяти обновляются в T-13; GRAMMAR §7 — [T-14](../tasks/T-14-grammar-message-sync/README.md);
- пункт W7 §6 #17 (автопроверка списков команд) **снят** — уже в каноне с
  [T-12](../tasks/T-12-agent-loop/README.md) (`review.md`, `auditor.md`,
  `AGENTS.md`, `agents-audit.feature`);
- полный канон процесса — [`AGENTS.md`](../../AGENTS.md) §Рабочая группа
  агентов (ссылка, без дублей — Q41).

## Альтернативы

- **Реестр находок без правки канона** (вариант (а) [Q46](../questions/Q46.md)) —
  расхождения повторятся в Run 4. Отклонено.
- **Разрозненные точечные правки по каждой находке** (вариант (б)) — дрейф
  «инструкция ↔ права» (риск Н3 из T-11). Отклонено.
- **Массовое расширение allow-листов до research (F4)** — гадание без факта
  семантики матчинга. Отклонено: сначала research-шаг, затем правки.
- **Изменение политики mail/memory** (memory вне git) — противоречит v2.1,
  требует `git rm --cached`, теряет знание ролей при клоне. Отклонено
  (W7 §8.1).
