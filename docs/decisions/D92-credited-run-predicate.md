# D92: Зачётный прогон — ядро-предикат чистоты (F26/F27/F15)

- **Статус:** accepted
- **Дата:** 2026-10-03
- **Resolves:** [Q89](../questions/Q89.md)
- **Спека:** —
- **Affects:** [`state-schema.md`](../../.opencode/rules/state-schema.md) (раздел
  «Зачётный прогон»)
- **Tasks:** [T-15](../tasks/T-15-mcp-ready-process/README.md) (фаза C, строка
  реестра `C17`; прогонные проверки `B1-F26`/`B1-F27`/`B1-F15`)

## Контекст

Прогонные проверки фазы B — `F26` (S/M-прогон + fast path S), `F27` (прогон с
ведущим `lead`), `F15` (первый живой `rework`) — ждут **чистого** прогона
(карточка [T-15](../tasks/T-15-mcp-ready-process/README.md), §«Прогонные
проверки…»). Формального определения «чистоты» не было: на разборах она
трактовалась задним числом (T-24: 4 упора лимита `lead`, 8 вызовов `analyst`,
~69 мин — «не чистый»), критерий готовности оставался непрозрачным.

Обсуждение ролей 03.10.2026 (сервисная операция r14, лента) свело предмет к
ядру-предикату, машинной проверке и неретроактивности. Решения владельца
03.10.2026: место — `state-schema.md`; ядро — вариант аналитика; без
ретроактивного зачёта. Полный контекст — [Q89](../questions/Q89.md). Правки
канона (`.opencode/**`) — зона сервисной сессии; решение лишь канонизирует их
состав.

## Решение

1. **Зачётный прогон** — прогон, удовлетворяющий ядру:
   1. ведущий — `lead` (атрибуция верна);
   2. нет упоров лимитов `steps` ни у одной роли;
   3. нет незапланированных прерываний владельца (каждый `owner_response`
      соответствует `surface_to_user`, стоявшему в плане участка (`next[]`);
      ответов вне плана и «продолжай» нет);
   4. нет ручных восстановлений (пустые финалы, backfill-записи, ручная
      реконструкция).
2. **Не дефекты зачёта:** плановые гейты, `owner_override`-решения,
   обязательный rework `validator` (`-rN`), CCSN-шаг удаления ветки,
   session-commit.
3. **Проверка машинная** — по `progress.yaml`; экспорт сессии
   (`.opencode/scripts/session-analysis/`) и `.opencode/scripts/metrics-report.mjs`;
   вердикт «зачёт/незачёт» — записью.
4. **Не ретроактивно** — зачёт только прогонам после принятия решения
   (решение владельца 03.10.2026).

## Следствия

- Критерий готовности фазы B (`F26`/`F27`/`F15`) становится перечислимым и
  проверяемым машинно, а не усмотрением на разборе.
- Второй источник критерия не появляется: ядро живёт в `state-schema.md`
  (Q41); правка канона — единственное место изменения.
- Прогоны до принятия решения (в т. ч. T-24/T-16/T-25) не зачитываются
  задним числом; остаток чистого S-прогона сохраняется.
- Правки процесса (`.opencode/**`) — зона сервисной сессии; продуктовый код
  `src/**` и контракты CREDO не затрагиваются.

- **Проза в `dispatch-loop.md` (усмотрение)** — отклонена: описание словами
