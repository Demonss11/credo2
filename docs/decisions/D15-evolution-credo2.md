# D15: Эволюция `credo2`, а не greenfield

- **Статус:** accepted
- **Дата:** 2026-09-24
- **Resolves:** [Q1](../questions/Q1.md)
- **Спека:** [`SPECIFICATION.md`](../SPECIFICATION.md) §10, решение №15
- **Affects:** [`features/README.md`](../features/README.md) (шапка «Стратегия
  реализации»); `SPECIFICATION.md` §5, §8, §10
- **Tasks:** [T-10](../tasks/T-10-workspace-phase-0/README.md) (Фаза 0, план)

## Контекст

SPEC описывал целевой монорепозиторий `dar/` и план с Фазы 1 как задание «с нуля»,
хотя уже существовал работающий прототип `credo2` (MCP, REST, git-публикация,
regex-парсер), частично покрывавший Фазу 1 и Фазу 4. Нужно было выбрать: начинать
заново, эволюционировать прототип или подстроить SPEC под монолит.

## Решение

Вариант **(б) — эволюция `credo2`**, не greenfield. Монорепозиторий `dar/` из SPEC —
целевая структура, к которой `credo2` перестраивается поэтапно: сначала выделение
`dar-core` и `credo-server` из текущего крейта, `lsp-dar` и `notebook/` — новые
крейты в том же workspace. Greenfield-ветка отклонена.

## Следствия

- `SPECIFICATION.md`: заметка «Статус реализации» после заголовка; §5 переименован
  в «Целевая структура монорепозитория» с текущим маппингом
  (`credo2::core → crates/dar-core`, `credo2::{mcp, rest} → crates/credo-server`);
  §8 — Фазы 1 и 4 помечены как частично закрытые прототипом, план переведён
  в режим «эволюция»; §10 — добавлено решение №15.
- `features/README.md` (шапка): требования верифицируются на эволюционирующем
  `credo2`, а не на отдельном greenfield-проекте.
- Языковые решения принимаются в контексте regex-базы `credo2` — следствие
  для Q3/Q4 (см. Q3).
- Проверенное поведение (MCP/REST/git-контур) сохраняется; рефакторинг в workspace
  идёт без изменения поведения (Фаза 0).

## Сверка с кодом

Вердикт: ⚪ **не применимо** — решение о стратегии развития, конкретных контрактов
и поведения не меняет; кода, который бы ему «соответствовал», в этом решении нет.

Что проверено: раскладка прототипа и целевой структуры сверена по
`SPECIFICATION.md` §5 (`credo2::core → crates/dar-core`,
`credo2::{mcp, rest} → crates/credo-server`); поведение прототипа зафиксировано
зелёными тестами (`cargo test --all` — 60/60 на 2026-09-26). Расхождений,
требующих задачи, нет.

Структурный рефакторинг Фазы 0 (выделение workspace без изменения поведения) —
плановая работа `SPECIFICATION.md` §8; по решению владельца поставлена **первым
приоритетом** и оформлена задачей
[T-10](../tasks/T-10-workspace-phase-0/README.md) (P0, статус ⬜). Поведение при
переносе не меняется.

## Альтернативы

- (а) **greenfield по SPEC** — рабочий прототип покрывает Фазу 4 и часть Фазы 1;
  переписывание с нуля выбрасывает проверенное поведение MCP/REST/git.
- (в) **`credo2` остаётся монолитом, SPEC переписывается под него** — отказ
  от целевой структуры монорепозитория, противоречит плану выделения
  `dar-core`/`lsp-dar`/`notebook`.
