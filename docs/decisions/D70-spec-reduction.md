## Контекст

[`SPECIFICATION.md`](../SPECIFICATION.md) — 924 строки; значительная часть
дублирует канон, закреплённый в журнале и правилах («один факт — один канон»,
[D60](D60-docs-ownership-sync.md)): §4.4/§4.5 (~140 строк REST/MCP-кодов и
контрактов) дублируют [D25](D25-rest-error-envelope.md)/[D26](D26-rest-auth-x-api-key.md)/
[D53](D53-error-messages-language.md)/[D34](D34-mcp-tool-contracts.md); §5 (дерево
монорепо) — [D15](D15-evolution-credo2.md); §7 (поток/жизненный цикл) —
[D54](D54-source-of-truth-flow.md)/[D28](D28-two-git-contours.md); §1.3.1
(«Макдоналдс», 48 строк) — ADR-001 и [D22](D22-rest-paths-canon.md); §9 (DoD)
повторяет [`../../AGENTS.md`](../../AGENTS.md) §Сборка и
[`../../.opencode/rules/review.md`](../../.opencode/rules/review.md)
([D50](D50-dod-by-package-scope.md)); §10 (68 строк таблицы) держит колонку
«Обоснование» рядом с D-файлами — второй канон формулировок. После [D69](D69-retro-decisions.md)
все решения §10 покрыты D-файлами, и таблица §10 стала избыточной. Полный
контекст — [Q66](../questions/Q66.md).

## Решение

1. **Сжать дубли до ссылок на D** по карте разведки: §4.4/§4.5, §5, §7, §1.3.1;
   §9 → 3 строки + ссылка на [`../../AGENTS.md`](../../AGENTS.md) §Сборка и
   [D50](D50-dod-by-package-scope.md). Ориентир — ≈390–400 строк (без жёсткой
   цифры); §6 (указатель) и §11 (глоссарий, [D52](D52-glossary-terms-canon.md))
   **не трогать**.
2. **Таблица §10 удаляется** (включая колонку «Обоснование»). Раздел §10 —
   короткий указатель: «Принятые решения — журнал `decisions/`; сквозная
   нумерация `Dn` (исторически совпадала с № строки §10); связи/жизненный цикл —
   [`TRACEABILITY.md`](../TRACEABILITY.md)».
3. **Обновить упоминания «§10 — краткий канон»:** шапка SPEC §10, таблица канонов
   в [D60](D60-docs-ownership-sync.md), заметка в
   [`decisions/README.md`](README.md). Ссылки «Спека: §10 №N» в **существующих**
   D — **исторические, не переписываются**; для **новых** D поле `Спека` — только
   уточняемые разделы SPEC, иначе `—`.
4. **Карточка [T-18](../tasks/T-18-docs-journal-test/README.md):** проверку «у D —
   строка §10» заменить на «у D — запись в [`decisions/README.md`](README.md);
   §10-адреса — исторические» (исполнение — вместе с правкой).
5. **Проверить провенанс §1.3.1** при переносе (сомнение разведки: §1.3.1
   называет источником Q20 ↔ [D22](D22-rest-paths-canon.md) — «канон REST-путей»;
   при несоответствии — поправить ссылку на ADR/актуальный источник).

## Следствия

- SPEC становится указателем на канон: формулировки решений — в
  `docs/decisions/`, связи — в [`TRACEABILITY.md`](../TRACEABILITY.md).
- Пропадает второй канон формулировок (§10-таблица) — устранён источник
  расхождений SPEC ↔ журнал.
- Ссылки «§10, №N» в ретро-D ([D69](D69-retro-decisions.md)) и существующих D —
  исторические, сохраняются как провенанс.
- Правка [T-18](../tasks/T-18-docs-journal-test/README.md) входит в исполнение
  этого решения (тест ещё не написан).

прототипа не меняет.

- **Объём и дубли:** [`SPECIFICATION.md`](../SPECIFICATION.md) — 924 строки;
  перечисленные разделы (§1.3.1, §4.4/§4.5, §5, §7, §9, §10) — по карте разведки

- **§10 покрыт D-файлами:** после [D69](D69-retro-decisions.md) у строк № 1–13 и
  № 14–68 есть D-файлы; непокрытых строк §10 нет.
- **Провенанс §1.3.1:** [`SPECIFICATION.md`](../SPECIFICATION.md) `:50–52`

  [D22](D22-rest-paths-canon.md) — «канон REST-путей»; проверка — пункт 5 решения
  (исполнение).

`cargo` не запускался (§5.3, [D50](D50-dod-by-package-scope.md)): решение
документное, кода не меняет; адресный прогон не требуется.

**Задач не требуется:** правки — документные (SPEC, сводки, карточка T-18),
исполняются сервисной сессией по тексту решения; кода прототипа не касаются.

## Альтернативы

- **§10-индекс вместо удаления** (№ + строка + ссылка; «Обоснование» — в D) —
  отклонено владельцем: таблица дублирует журнал; проще указатель.
- **Мягко — только §4 и §10** — отклонено: дубли есть и в §1.3.1/§5/§7/§9.
- **Жёстко до ~300 строк** — отклонено: без жёсткой цифры, ориентир ≈390–400.
