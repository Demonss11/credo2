# D36: Массовый прогон (batch) — вне MVP, пост-MVP/v0.2

- **Статус:** accepted
- **Дата:** 2026-09-26
- **Resolves:** [Q24](../questions/Q24.md)
- **Спека:** [`SPECIFICATION.md`](../SPECIFICATION.md) §10, решение №36
- **Affects:** [`SPECIFICATION.md`](../SPECIFICATION.md) §4.4 (MVP-минимум REST),
  §10; [`features/batch.feature`](../features/batch.feature) (целевое состояние,
  шапочный комментарий об отсрочке — зона `docs-writer`);
  [`features/README.md`](../features/README.md) (раздел «Отложено», ⏸/⏳);
  [`../../src/rest.rs`](../../src/rest.rs), [`../../src/mcp.rs`](../../src/mcp.rs)

- **Tasks:** — (решение об отсрочке; см. «Сверка с кодом»)

## Контекст

`batch.feature` описывал `{"заявки": [...]}` на тот же `POST .../evaluate` с
агрегатом «статистика/всего/отказано/одобрено»; схема запроса/ответа не была
описана, ключи русские — вразрез с машинным контрактом API (Q11). Нужно было
решить: отдельный эндпоинт или перегрузка `evaluate`, и вводить ли агрегацию в
MVP. Полный контекст — [Q24](../questions/Q24.md).

## Решение

1. **Массовый прогон (batch) — вне MVP**, пост-MVP/v0.2.
2. **Обоснование:** в v0.1 единица исполнения — атомарный `evaluate` (принцип
   атомарной композиции, [D22](D22-rest-paths-canon.md)): полный прогон
   оркестрируется клиентом по манифесту (цикл по `active`-версиям → цикл
   атомарных `evaluate`, [D23](D23-get-checks-manifest.md)), серверный агрегат
   не требуется; сценария пакетного прогона в демо нет — YAGNI; схема batch
   (ключи, агрегаты, частичные ошибки) не стабилизирована.
3. **Направление на v0.2 (если вернёмся):** отдельный эндпоинт
   `POST /checks/{name}/versions/{version}/batch` — **не** перегрузка
   `evaluate` (путь с параметрами из [D22](D22-rest-paths-canon.md) не
   меняется); ключи латиницей (`applications`, `stats`), русские — только
   текстовые значения ([D53](D53-error-messages-language.md)); ошибки
   транспорта — конверт [D25](D25-rest-error-envelope.md), частичные ошибки —
   целевое состояние `batch.feature`.

## Следствия

- В [`../../src/rest.rs`](../../src/rest.rs) и [`../../src/mcp.rs`](../../src/mcp.rs)

  меняется (3 сценария, backend) — меняется только статус/приоритет файла в
  [`features/README.md`](../features/README.md) (раздел «Отложено», ⏸/⏳).
- `SPECIFICATION.md` §4.4 (таблица MVP-минимума) относит batch к отложенному;
  §10 пополнен решением №36.
- Ссылка в архиве `OPEN_QUESTIONS.md` (упоминание batch) закрыта переносом

## Сверка с кодом

Вердикт: ⚪ **не применимо** — решение об отсрочке (процесс/границы MVP); кода
не добавляется, вердикт о реализации к коду не относится. Задач не порождает.

Что проверено (чтением, 29.09.2026), чем подтверждено:

- **Batch-эндпоинта в REST нет:** [`src/rest.rs`](../../src/rest.rs) — таблица
  маршрутов `app(...)` (19–31): `GET /health`, `/docs`, `/openapi.json`,
  `/version`, `GET /checks`, `GET /checks/{name}/versions`,
  `GET /checks/{name}/versions/{version}`, `POST /checks/{name}/evaluate`,
  `POST /checks/{name}/versions/{version}/evaluate`. Маршрута `.../batch` нет.
- **Batch-инструмента/полей в коде нет:** поиск по `src/` (`batch`,
  `applications`, `stats`, `explain_client`) — совпадений нет.
- **Требование — целевое состояние:** [`features/batch.feature`](../features/batch.feature)
  (шапка 1–8) — «ОТЛОЖЕНО до v0.2 (решение Q24, 2026-09-26): массовый прогон
  вне MVP; в REST/MCP ничего не добавляется»; схемы помечены целевым
  состоянием.
- **Статус требования:** [`features/README.md`](../features/README.md) (раздел
  «Отложено», строка 275) — [`batch.feature`](../features/batch.feature),
  3 сценария, статус ⏸, приоритет ⏳, «пост-MVP (Q24)».

`cargo` не запускался (§5.3, [D50](D50-dod-by-package-scope.md)): решение не
меняет код, адресный прогон не требуется.

**Задач не требуется:** решение фиксирует границу MVP (отсрочку); в периметре
MVP расхождений нет — кода нет и не планируется, требование уже помечено ⏸/⏳,
счётчики `features/` не меняются. Обратный комментарий `# Dn (Qx)` в шапке
фичи — зона `docs-writer` (§5.6), отдельной задачи по коду не требует.

## Альтернативы

- **Перегрузить `evaluate` набором заявок** — отклонено: ломает атомарную
  композицию (сервер начинает агрегировать решения) и канон пути
  [D22](D22-rest-paths-canon.md); агрегация нужна клиенту, не серверу.
- **Ввести batch в MVP** — отклонено: пакетного сценария в демо нет (YAGNI),
  схема не стабилизирована.
- **Оставить схему с русскими ключами** — отклонено: противоречит принципу
  машинного/человеческого разделения ([D53](D53-error-messages-language.md)).
