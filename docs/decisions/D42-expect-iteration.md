# D42: Run 4 — `expect` в терминах hard rules; `iteration` — только rework

## Контекст

Run 4 (T-03 заново) дал две находки уровня канона процесса: F14 — `expect` плана
шире канона роли `tester` (штатные `cargo check`/`cargo fmt --check` читались как
нарушение запрета), F15 — дрейф `iteration`: номер участка плана использовался как
значение `iteration` при `rework: 0`. Полный контекст — [Q47](../questions/Q47.md),
[`memorandum-W8-run4.md`](../analysis/memorandum-W8-run4.md) §4.2, §5.1.

## Решение

1. **`expect` — в терминах hard rules.** Брифы/ожидания формулируют запреты
   буквально: «`cargo test` не запускался». Штатные команды роли (`tester`:
   `cargo check`, `cargo fmt --check`) нарушением ожидания не считаются; «cargo
   не запускался» — неверная формулировка (источник F14/F35).
2. **`iteration` — только rework-цикл (механика).** Старт `1`; вердикт `rework`
   открывает следующий цикл — квитанция вердикта и все записи раунда ведут новое
   значение. Фиксация — `next_action`/`current_state` на re-plan rework-участка
   (до dispatch `coder -rN`, пишет `analyst`), `progress` — зеркало (`lead`),
   квитанции — `validator`. Соотношения: `-rN` = `iteration` повторной приёмки;
   `rework = iteration − 1`; счётчик один. Номер участка плана — не `iteration`,
   а `progress_marker`/`resume_hint` («участок №n»).
3. **Чистая проверка инкремента — на первом rework** (F15): Run 4 и Run 5
   инкремент фактически не исполняли (значение не менялось), поэтому механика
   п. 2 остаётся формально непроверенной — отметка в реестре находок.

## Следствия

- `expect` в планах и брифы ролей формулируются буквально, со ссылкой на hard
  rules; снимается класс ошибок F14/F35.
- `iteration` перестаёт нести номер участка; участки адресуются
  `progress_marker`/`resume_hint`. Соответствие `-rN` ↔ `iteration` ↔ `rework`
  фиксируется одним счётчиком.
- Требуется наблюдение на первом реальном `rework` (инкремент `1 → 2`);
  при обнаружении дрейфа — реестр находок и повторное решение.

периметра. Задач не требуется: канон внесён сервисной сессией 28.09.2026;
чистая проверка инкремента `iteration` — наблюдение при первом `rework` (F15), не
задача к коду.

## Альтернативы

- **Оставить формулировки как есть** (вариант (а) [Q47](../questions/Q47.md)) —
  F14/F15 воспроизвелись бы в следующих прогонах. Отклонено.
- **Ввести отдельное поле под номер участка** (вариант (б)) — дублирует
  `progress_marker`/`resume_hint`, расширяет формат состояния без нужды.
  Отклонено.
