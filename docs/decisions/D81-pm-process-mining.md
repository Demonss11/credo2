## Контекст

Черновик владельца `.opencode/scripts/pm/mine_agents.py` (557 строк, вне git)
читает `state/current/*`, но не читает `mail/` (реальный event log вызовов ролей),
путает очередь `next_action` (ключ `next`), не учитывает `accepted_with_notes`;
зависимости (pandas/networkx/matplotlib/plotly/pm4py) под Python 3.14 — риск колёс;
у ролей нет прав `uv` — инструмент служебной зоны. Полный контекст, варианты и
список улучшений — досье (архив git) и вопрос [Q77](../questions/Q77.md).

## Решение

1. **Проект:** uv-проект `.opencode/scripts/pm`: `pyproject.toml` + `uv.lock`
   (в git), пакет `src/pm_agents/`, CLI `pm-agents`, `tests/` (pytest),
   `README.md`, локальный `.gitignore` (`.venv/`, `__pycache__/`, `*.egg-info`).
2. **Зависимости слоями:** core — `pyyaml` (+stdlib csv/json) → метрики/CSV/JSON/
   markdown; extra `viz` — `networkx` + `matplotlib` + `plotly` → PNG/HTML; extra
   `pm4py` — опциональный. `seaborn` не используется.
3. **Источники:** `progress` + `receipts` + `next_action` (обязательные) + `mail/`
   (tolerant-enrichment). Кейс = `task`/имя ленты; неизвестные → `unknown-<idx>`
   (не подставлять текущую задачу); активность = `role` (dispatch/re-plan) либо
   `action`; порядок = (`at`-дата, глобальный счётчик); выводы о секундных
   задержках не делаются.
4. **Метрики и артефакты:** DFG (все/популярные), варианты, heatmap, Sankey HTML,
   частоты, `metrics.json`, `dfg_edges.csv`, `variants.csv`, `summary.md`; приёмка
   учитывает `accepted_with_notes`; несовпадения `expect_match` — счётчик.
5. **Место:** запуск — владелец/сервисная сессия (`uv run`); артефакты — вне
   репозитория (`%TEMP%\opencode\pm-<дата>\`, как `session-analysis`); в git —
   только итоговый отчёт `docs/analysis/`.
6. **Права ролей не меняются** (у ролей нет `uv`/`node`; роли читают готовые
   отчёты).
7. **Строка `pm/` — в карту `AGENTS.md`** (`.opencode/scripts/`), вносит сервисная
   сессия; протокол волны: `migrator` (Q77/D81) → сервисная сессия (код) →
   `auditor` → `validator` → `git`. Улучшения черновика — по списку досье
   (архив git), выполняются этой волной.

## Следствия

- Черновик `mine_agents.py` заменяется проектом `pm/`; дефекты (see досье,
  пп. 1–15: `next`-очередь, `accepted_with_notes`, `unknown-<idx>`, `at` без
  времени, lazy-импорты/`--no-viz`, BOM, `summary.md`, `variants`-порядок,
  `--source`/`--since`/`--exclude-service`) устраняются волной.
- Инструмент процесса отделён от продукта (`src/**`, `tests/**`, `Cargo.toml` не
  затронуты) и от канона ролей (права не расширяются).
- Артефакты анализа не засоряют репозиторий (вне git); в git — сводный отчёт.
- Открытый пункт: MCP-интеграция `pm` (связка с [T-15](../tasks/T-15-mcp-ready-process/README.md)) —
  отдельной задачей, вне периметра этого решения.
- **Обновление 30.09.2026:** уточняет п.5 (место артефактов) и вводит
  накопительный архив событий; код вносится сервисной сессией параллельно
  (служебная зона, задачи `T-XX` не требуются):
  - **артефакты прогонов `pm`** — `.opencode/scripts/pm/output/` (одна папка,
    файлы прогона перезаписываются; вне git — локальный `.gitignore`), вместо
    `%TEMP%\opencode\pm-<дата>\`; открытый пункт досье (архив git)
    «Дефолт вывода: temp vs `pm/output/`» закрыт;
  - **накопительный архив событий** — `output/events.jsonl` (JSONL): при каждом
    прогоне источники читаются заново, события сливаются с архивом по
    стабильному ключу (источник, кейс, роль/действие, дата, итерация,
    результат/статус, `expect_match` + номер повтора) — без дублей; повторный
    прогон на тех же данных добавляет 0 событий (идемпотентность); позиционные
    псевдокейсы `progress` без `task` (`unknown-<idx>`) в ключ не входят
    (`archive.py`, `_identity`: `case = ""`) — усечение журнала дублей не
    плодит;
  - **фильтры среза** `--source`/`--since`/`--exclude-service` действуют только
    на срез отчёта и архив не режут; **флаги** `--archive PATH` и `--no-archive`;
  - **снимок лент в `clean-logs.mjs`** — перед удалением лент best-effort
    снимок `uv run pm-agents --no-viz` (opt-out `--no-snapshot`), чтобы ленты,
    не скармливавшиеся `pm`, не терялись; снимок выполняет сам скрипт
    транзитивно из пакета очистки (вызов `uv` внутри `clean-logs`, в т.ч.
    когда его запускает роль `git`); права ролей при этом не меняются; сбой
    снимка (в т.ч. отсутствие `uv`) — только предупреждение, очистка
    продолжается; правило
    [`git-workflow.md`](../../.opencode/rules/git-workflow.md)
    §«Подтверждение и очистка логов» уже дополнено сервисной сессией; строка
    [`AGENTS.md`](../../AGENTS.md) про `clean-logs.mjs` дополнена сервисной
    сессией;
  - досье решения не правится (архив git); [`TRACEABILITY.md`](../TRACEABILITY.md) и
    каталоги не меняются (номер `D` и статус — без изменений; новых `Q`/`D` нет).
- **Обновление 30.09.2026 (нумерация):** дополняет накопительный архив (выше)
  сквозной нумерацией событий — решение владельца (30.09.2026, гейт
  планирования); код вносится сервисной сессией параллельно (служебная зона,
  задачи `T-XX` не требуются):
  - **сквозная нумерация событий** — у каждого события архива
    `output/events.jsonl` есть номер `n`: присваивается при первом попадании в
    архив и не меняется; нумерация сквозная по всему архиву (не по кейсам);
    после очистки лент (`clean-logs.mjs`) новые события продолжают нумерацию с
    последнего заархивированного +1; снимок лент перед удалением нумерует их до
    удаления, при `--no-snapshot` или сбое снимка удалённые ленты в архив не
    попадают — нумерация продолжается от последнего заархивированного;
  - **выгрузка** — `output/events.csv` — пронумерованный журнал (№; дата;
    источник; кейс; активность; роль; действие; результат; итерация;
    `expect_match`) в порядке отчёта;
  - **`clean-logs.mjs`** — после снимка печатает, с какого номера продолжится
    нумерация событий;
  - **бэкфилл** — архив без номеров (текущий, 412 событий) разово нумеруется по
    порядку при первом прогоне новой версии; удаление файла архива сбрасывает
    нумерацию;
  - досье решения не правится (архив git);
    [`TRACEABILITY.md`](../TRACEABILITY.md) и каталоги не меняются
    (номер `D`, статус и `Affects` — без изменений; новых `Q`/`D` нет).
