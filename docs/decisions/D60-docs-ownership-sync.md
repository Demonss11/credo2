## Контекст

Статусы и цифры дублировались между SPEC и `features/README.md`; корневой
`DECISIONS.md` вёл ADR-001/ADR-002, но покрывал не все решения; `AGENTS.md` был
актуализирован под `credo2`. Не было ответа «кто владелец документа и где живёт
факт». Полный контекст — [Q41](../questions/Q41.md). Решение связано с каноном
меток/чисел ([Q5](../questions/Q5.md),
[D19](D19-statuses-priorities-canon.md)) и проверяемостью фич
([Q40](../questions/Q40.md), [D20](D20-features-docs-dod.md)).

## Решение

Принята политика **«один факт — один канон»** (Q41).

**Роли документов** (при расхождении канон — из этой таблицы):

| Документ | Канон чего |
|---|---|
| [`SPECIFICATION.md`](../SPECIFICATION.md) | целевая архитектура; §10 — краткие формулировки решений |
| [`questions/`](../questions/) + [`decisions/`](../decisions/) (журнал; исторически — [`OPEN_QUESTIONS.md`](../OPEN_QUESTIONS.md)) | полный контекст «вопрос → решение» |
| [`features/README.md`](../features/README.md) | **единственный** канон статусов, приоритетов и счётчиков сценариев ([Q5](../questions/Q5.md)/[Q40](../questions/Q40.md)) |
| [`GRAMMAR.md`](../GRAMMAR.md) | канон языка v0.1 (EBNF включён, [Q2](../questions/Q2.md)) |
| `DECISIONS.md` (корень рабочего пространства) | реестр **сквозных архитектурных** ADR (кратко + источники) |
| `concept.md`, `SCOPE.md`, `NON_GOALS.md`, `ROADMAP.md`, `open-questions.md` | рамки и продуктовые вопросы DAR (не технические детали CREDO) |
| [`AGENTS.md`](../../AGENTS.md) (корень `credo2`) | операционная инструкция агентам |
| [`CHANGELOG.md`](../CHANGELOG.md), `CONFORMANCE/` | хронология прототипа; принципы тестов соответствия |
| [`tasks/`](../tasks/) | реестр задач по коду: сводка + папка на задачу (не норматив) |

**Правила:**

- **Статусы и числа — только в `features/README.md`.** SPEC их не дублирует
  (§6.1 ссылается на README; актуальность проверяет
  [`tests/features_inventory.rs`](../../tests/features_inventory.rs)), ручная
  сверка не нужна.
- **Новое решение** при закрытии вопроса: краткая строка в SPEC §10; полный
  контекст — в журнале `questions/` + `decisions/`; если решение
  сквозное/архитектурное — дополнительно ADR в корневом `DECISIONS.md`.
- **Расхождение с кодом** фиксируется явно: статус 🟡 требования в
  `features/README.md` и задача в `tasks/`; «молчаливых» расхождений нет.
- **`AGENTS.md`** описывает текущую сборку прототипа (как собрать и вызвать);
  канон требований и контрактов — SPEC/журнал; при расхождении приоритет у
  канона.
- **Корневые DAR-документы** (`concept.md`, `SCOPE.md`, `NON_GOALS.md`,
  `ROADMAP.md`, `open-questions.md`, заглушки `GRAMMAR.md`/`EBNF.md`) — вне
  периметра текущей работы над прототипом; канон языка для прототипа —
  [`GRAMMAR.md`](../GRAMMAR.md); корневые документы обновляются после демо
  (решение 2026-09-26).

## Следствия

- **Выполнено (2026-09-26):** SPEC §6.1 — числа убраны, ссылка на README и
  тест; SPEC §10 — шапка «краткий канон / контекст / ADR»; корневой
  `DECISIONS.md` — ADR-003 «Владение документами и синхронизация»; `AGENTS.md` —
  раздел «Документы и решения» и корректные ссылки. Фичи и счётчики не
  менялись (актуальные числа — в `features/README.md`).
- Политика служит рамкой для журнала Q/D: сводки `questions/README.md` и
  `decisions/README.md` — рабочие, **не канон**; текст решения живёт в
  `Dn-*.md`, формулировка — в SPEC §10, связи — в `TRACEABILITY.md`.
- Сквозные решения дополнительно получают ADR; при переносе журнала D-файл
  ссылается на ADR, не дублируя его.
- Решение не меняет код прототипа; его «потребители» — документы и процесс
  (`docs-writer`/`migrator`).

## Сверка с кодом

Вердикт: ⚪ **не применимо** (процесс/документы) — решения о владении
документами код продукта не касаются; сверка документная: проверено отражение
политики в SPEC/`AGENTS.md`/`docs/README.md` и внешний ADR-003.

Что проверено (чтением, 29.09.2026), чем подтверждено:

- **SPEC §6.1 — ✅:** [`SPECIFICATION.md`](../SPECIFICATION.md) «Инвентаризация
  требований» (`:645–653`) ссылается на `features/README.md` как канон, числа не
  дублирует, актуальность проверяет `tests/features_inventory.rs` (Q40).
- **SPEC §10 — ✅ (шапка отражает политику):**
  [`SPECIFICATION.md`](../SPECIFICATION.md) §10 (`:811–820`) — «краткий канон
  решений», полный контекст в журнале `questions/` + `decisions/`, сквозные —
  ADR в корневом `DECISIONS.md`, статусы/приоритеты/счётчики — только в
  `features/README.md`.
- **`AGENTS.md` — ✅:** §«Документы и решения» воспроизводит таблицу ролей и
  правило «один факт — один канон» (политика Q41), не дублируя канон.
- **`docs/README.md` — ✅:** карта канонов помечена «(политика Q41: „один факт —
  один канон“)» (`:27`), корневой `DECISIONS.md` указан как «сквозные
  архитектурные ADR» (`:37`).
- **ADR-003 (внешний) — ⚪ не проверялся чтением:** корневой `DECISIONS.md`
  лежит вне рабочего пространства репозитория (`../../DECISIONS.md` от корня
  `credo2`), доступ к внешнему каталогу закрыт правами (попытка чтения 29.09.2026
  отклонена `external_directory`). Существование ADR-003 подтверждается
  следствием в [Q41](../questions/Q41.md) (`:51–55`), ссылкой в шапке SPEC §10
  (`:817`) и `docs/README.md:37`; сам файл не правится (внешняя рамка,
  см. §«Внешние рамки» `AGENTS.md`).

`cargo` не запускался (§5.3, [D50](D50-dod-by-package-scope.md)): решение
документное, кода не касается; адресный прогон не требуется.

**Задач не требуется:** политика и её следствия — документные, кода прототипа
не меняют; машинная часть (проверка чисел фич) уже покрыта
`tests/features_inventory.rs` ([Q40](../questions/Q40.md),
[D20](D20-features-docs-dod.md)). [`tasks/README.md`](../tasks/README.md) к
политике не привязан (правки шапок `docs/**` — зона `docs-writer`, не задача по
коду).

## Альтернативы

- **Дублирующие таблицы и ручная синхронизация** — отклонено: расхождения
  «✅ vs 🔴» и устаревшие числа воспроизводились при каждом изменении
  требований (конкретный случай — SPEC §6.1, [D19](D19-statuses-priorities-canon.md)).
- **Единый документ (SPEC как канон всего)** — отклонено: смешивает целевую
  архитектуру, решения и статусы требований; противоречит уже принятому канону
  меток в `features/README.md` ([D19](D19-statuses-priorities-canon.md)).
- **Оставить корневые DAR-документы в периметре правок прототипа** — отклонено:
  их уровень — рабочее пространство DAR, не технические детали `credo2`; обновление
  после демо (решение 2026-09-26).
