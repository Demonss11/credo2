## Контекст

До-журнальное решение (строка №11 [`SPECIFICATION.md`](../SPECIFICATION.md) §10).
Формулировка: «WASM: сначала нативный, потом браузер»; обоснование: «Упрощение
старта». Ретроспективное оформление — [D69](D69-retro-decisions.md).

## Решение

Порядок поставки: **сначала нативный** бинарник (текущий `credo2.exe`), затем —
браузерная сборка через WASM. Браузерный вариант — v0.2, вне MVP.

## Следствия

- В MVP — только нативный сервер; браузерного исполнения нет.
- Требование отслеживается фичей [`wasm.feature`](../features/wasm.feature) (v0.2).

## Сверка с кодом

Вердикт: ⬜ **не реализовано** (отложено, v0.2 — ожидаемо).

- **WASM-сборки нет:** репозиторий собирает нативный `credo2.exe`
  (`cargo build --release`, `AGENTS.md` §Сборка); `wasm32`-цели/артефакта нет.
- **Требование зафиксировано:** [`features/wasm.feature`](../features/wasm.feature)
  ⬜, 4 сценария, приоритет 🟢 ([`features/README.md`](../features/README.md) `:271`).

`cargo` не запускался (§5.3, [D50](D50-dod-by-package-scope.md)): ретро-оформление,
кода не меняет.

**Задач не требуется:** решение задаёт порядок поставки и откладывает WASM в
v0.2; отслеживается фичей [`wasm.feature`](../features/wasm.feature).

## Альтернативы

Историей не зафиксированы; «сразу в браузер» отклонено ради упрощения старта.
