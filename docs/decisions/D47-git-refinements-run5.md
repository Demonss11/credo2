## Контекст

Разбор сессии `git` Run 5 дал F37: предписанный порядок удаления ветки падал на
устаревшем upstream (3/3). Разбор сессии `tester` дал F38: наблюдение
«неоднородного» матчинга `git -C`, противоречащее канону T-13. Полный контекст —
[Q52](../questions/Q52.md); меморандум W8, том 2 §2, §4.15, §4.16 (архив — git).

## Решение

1. **Порядок удаления ветки** (F37): `git push origin --delete
   feature/T-XX-<слаг>` → `git branch -d feature/T-XX-<слаг>`. `branch -d` может
   отказать из-за устаревшего upstream (коммит задачи в ветку не пушился) — тогда
   сначала удаляется remote (порядок выше — рабочий, T-12/T-13/T-04).
2. **Матчинг `git -C`** (F38): пробы 28.09.2026 (дочерняя сессия `tester`, 10
   команд) показали **единообразное** отклонение `-C` (абсолютный POSIX/Windows,
   `-C .`, повтор) и прохождение команд без `-C`. Канон T-13 верен, правка
   `review.md` не требуется; наблюдение Run 5 не воспроизвелось (вероятно,
   неточность записи разбора). Правило в силе: `git -C` не использовать, рабочая
   директория — полем `workdir`; запись добавлена в память `tester`.
3. **Место хешей closeout** (F37-доп.): отчёт `git` + `progress.yaml` (в ленте/
   памяти хешей может не быть — записи делаются до коммита).

## Следствия

- Завершение ветки идемпотентно и без импровизации: remote удаляется первым.
- Неопределённость `git -C` снята: матчинг однороден, расширять allow-листы не
  нужно; `tester` хранит правило «без `-C`, `workdir` полем».
- Хеши closeout фиксируются в отчёте `git` и `progress.yaml`.

## Сверка с кодом

Вердикт: ⚪ **не применимо** — решение процессное и правовое, продуктовое
поведение не меняет. Подтверждено: F38 — проба 28.09.2026, §1 (10 команд:
`-C` отклоняется единообразно, без `-C` проходит; воспроизводимо);
порядок удаления — [`git-workflow.md`](../../.opencode/rules/git-workflow.md)
(стр. 82); канон T-13 (`.opencode/rules/review.md` / справочник прав) —
подтверждён. `cargo` не запускался. Задач не требуется: канон внесён сервисной
сессией 28.09.2026; обновление карточки T-15 (F26) — зона `docs-writer`.

## Альтернативы

- **Оставить прежний порядок `branch -d` → `push --delete`** (вариант (а)
  [Q52](../questions/Q52.md)) — 3/3 отказа и ручная импровизация в каждом
  завершении. Отклонено.
- **Разрешить `git -C` в allow-листах** (вариант (в)) — гадание против факта
  однородного отказа. Отклонено.
