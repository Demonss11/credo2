## Контекст

`publish.feature` требует отклонять публикацию без тестирования и при
несовпадении контрольной суммы после последнего теста; ни учёта тестов, ни
такой проверки в коде не было, SPEC этого не описывал. Полный контекст —
[Q16](../questions/Q16.md).

## Решение

1. **Требование сохраняется:** готовность к публикации — факт успешного
   `check.test` на черновике, а не наличие файла теста.
2. **Метка теста живёт в черновике** (`.credo/sandbox.json`): сервер хранит
   `last_test_checksum` и `tested_at`; успешный `check.test` обновляет их,
   записывая `last_test_checksum = source_hash` на момент теста.
3. **Публикация отклоняется** без успешного теста и при несовпадении
   контрольной суммы (черновик изменён после теста); отказ — код
   `publish_failed` (Q29/§4.5).
4. **Канонические файлы тестов** (`tests/*.тест`, code=doc) — вне MVP (Q34);
   «быстрые прогоны» живут в локальном кэше
   `.dar-notebook/results-cache.json` (вне git; зона Notebook, v0.2).

## Следствия

- Черновик получает вычисляемую метку `test_valid`
  (`last_test_checksum == source_hash`), которая сама становится ложной при
  изменении текста: отдельного сброса не требуется.
- Гейт публикации опирается на факт прогона, а не на файл; тесты не засоряют
  workspace-репозиторий.
- `draft.feature`/`publish.feature`/`test_draft.feature` приводятся к метке
  тестирования в черновике (учёт ведёт сервер, не UI-черновик); SPEC
  §4.2/§4.3 и §10 (решение №32) — правки `docs-writer`.
- Задача [T-02](../tasks/T-02-test-gate/README.md) — реализовать учёт и гейт;
  от неё зависит [T-05](../tasks/T-05-mcp-success-schemas/README.md)
  (схемы успеха `check.test`).

## Сверка с кодом

Вердикт: 🟡 **расхождение** — учёт метки теста уже реализован, гейт
публикации — нет.

Что проверено (чтением кода и юнит-тестов, 29.09.2026), чем подтверждено:

- **Поля черновика — ✅:** [`src/lib.rs`](../../src/lib.rs) — `Draft` хранит
  `last_test_checksum`/`tested_at` (746–750), `make_draft` сохраняет метки
  при перезаписи и пересчитывает `source_hash` (850–874); `is_stale`
  (813–822).
- **`check.test` обновляет метку — ✅:** [`src/mcp.rs`](../../src/mcp.rs)
  `test(...)` (214–262): после успешного `evaluate_rule` пишет
  `last_test_checksum = source_hash` и `tested_at` (238–248) и возвращает их
  в ответе (250–261). Метка `test_valid = last_test_checksum == source_hash`
  вычисляется в `draft_json` (439–453). Юнит-тесты `src/mcp.rs` (849–858) и
  `test_valid_false_after_source_change_q29_inv4` (862–883).
- **Гейт `check.publish` — ⬜ не реализовано:**
  [`src/mcp.rs`](../../src/mcp.rs) `publish(...)` (282–342) не читает
  `last_test_checksum`/`tested_at` и не отклоняет публикацию без теста или
  при расхождении; [`src/lib.rs`](../../src/lib.rs) `publish(...)` (321–409)
  проверяет только semver-дубликат/downgrade/MAJOR. Сценарии
  `publish.feature` «Запрет публикации без тестирования» и «Отклонение
  публикации при несовпадении контрольной суммы» (56–70) ещё не выполнимы.
  → задача [T-02](../tasks/T-02-test-gate/README.md) (P1).
- **Кэш `.dar-notebook/results-cache.json`:** в репозитории отсутствует —
  зона Notebook (Q19/Q34, v0.2), вне периметра этой сверки.

`cargo` не запускался (§5.3, [D50](D50-dod-by-package-scope.md)): сверено
чтением кода и юнит-тестов; адресный прогон не требуется (правок код не
порождает).

**Задач новых не требуется:** расхождение в периметре MVP покрыто

## Альтернативы

- **Снять требование гейта** — отклонено: банковский контур требует, чтобы
  публиковалась проверенная версия; список тестов в `.dar-notebook/` (Q34)
  этого не заменяет.
- **Хранить метку в самом `.dar`-файле** — отклонено: метка — состояние
  прогона конкретного черновика, а не свойство исходника; файл был бы
  испорчен служебными данными.
- **Сбрасывать метку при любом `check.create`** — отклонено: `test_valid`
  вычисляется из `source_hash`, сброс был бы дублирующим состоянием.
- **Файлы `tests/*.тест` в MVP** — вне объёма (Q34, code=doc, v0.2).
