## Контекст

Разбор прогонов T-16/T-25 (02.10.2026) дал данные по трём пунктам программы
T-15 (фаза C) — вход развилок P1/P2/P3. Процесс доработки C9/C12 (D88) улучшил
метрики, но вскрыл:

- **Ветка дочерней задачи от `develop` при незакоммиченном родителе (F80):**
  T-25 (S, снятие D65-адресов) стартовала при пустой ветке T-16 → пакеты
  неразделимы, совмещённый closeout T-16+T-25 (F43).
- **Пересборка отложенного пакета (F81):** T-16 git «отложено владельцем» →
  новая сессия заново разобрала закрытие, решение пересматривалось 3×.
- **Незакрытые процесс-артефакты на первом git-вызове (F82):** обе
  `branch_start` по грязному дереву (25 M + 7 ??); в combined-пакете
  исключались чужие пути (F43).

Владелец на открытии сервисной операции 03.10.2026 (лента r11) выбрал вариант
(A) — весь пакет P1+P2+P3. Полный контекст — [Q86](../questions/Q86.md).
Правки процесса (`.opencode/**`, `AGENTS.md`) — зона сервисной сессии и
вносятся отдельно; решение лишь канонизирует их состав.

## Решение

1. **P1 — топология веток дочерних задач.** Задача-фикс/зависимость от
   незакрытой задачи (общее дерево/файлы) ветвится **от ветки родителя** (или
   той же веткой отдельным коммитом); родитель без коммитов — сначала фиксация
   результата родителя, затем дочерняя работа; при пересечении файлов/хунков —
   **один пакет**. `analyst` при планировании проверяет ветки/грязное дерево и
   фиксирует «дочерняя от T-XX, пакет общий». Права `analyst` — read-only
   `git branch -a *`, `git branch --list *`, `git rev-parse *` (уточнение D87:
   расширение обосновано проверкой in-flight задач). Основание — F80/F43.
2. **P2 — заморозка решений.** `awaiting_user`/`deferred_by_owner` по пакету —
   стоп-фактор: новый session не пересобирает закрытие; первый `analyst`-вызов
   новой сессии явно сверяет отложенный пакет (продолжаем как было / ждём /
   отменено) и продолжает идемпотентно, без пересборки схемы. Основание — F81.
3. **P3 — session-commit (первый инкремент C3).** На границе сессии (штатной
   или вынужденной) `lead` инициирует процесс-коммит (ленты, память, `state/`)
   ролью `git` по «постоянному» пакету: подтверждение один раз на прогон (запись
   в ленте), идемпотентность (повтор пропускается), catch-up при обрыве;
   продуктовые изменения не входят. Остаток C3 (`process/runN`, теги
   `session/runN-sM`, фасад `/git/checkpoint`) — отдельным решением. Основание —
   F82/F43.

## Следствия

- Пакеты родителя и дочерней задачи не смешиваются случайно: ветвление от
  родителя (или общий пакет) снимает «неразделимость» (F80/F43).
- Отложенное решение переживает границу сессии: новый session не пересобирает
  закрытие, а сверяет и продолжает идемпотентно (F81).
- Процесс-артефакты не остаются незакоммиченными к первому `branch_start`
  новой задачи: процесс-коммит на границе сессии (F82).
- Права `analyst` расширяются read-only git-командами проверки in-flight задач
  (уточнение D87).
- Правки процесса (`.opencode/**`, `AGENTS.md`) — зона сервисной сессии;
  продуктовый код `src/**` и контракты не затрагиваются.

## Альтернативы

- **Оставить как есть** (ветвление от `develop`, пересборка отложенного пакета,
  процесс-артефакты вне коммита) — отклонено: неразделимые пакеты и совмещённый
  closeout (F80/F43), пересмотр закрытия 3× в новой сессии (F81), грязное дерево
  на `branch_start` (F82).
- **Частичный пакет** — отклонено: пункты связаны (общие файлы/дерево; F80–F82);
  частичное принятие оставляет корневой источник коллизий.
