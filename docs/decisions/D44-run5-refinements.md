## Контекст

Run 5 (T-04, класс L) дал девять находок уровня канона процесса:
F17/F32 (бриф противоречил канону; цитаты не сверены), F18 (упоры в `steps`),
F19 (`git branch -vv` вне allowlist), F24 (срезанный вывод без протокола),
F25 (сплит лент не сработал), F34 (бюджет чтения `analyst`), F35 (память `coder`
противоречила канону роли), F36 (нет протокола эскалации при затыке). Полный
контекст — [Q49](../questions/Q49.md);
меморандум W8, том 2 §2, §4.3–§4.5, §4.9–§4.14 (архив — git).

## Решение

1. **Бриф ↔ канон** (F17/F32): требование брифа/ожидания, противоречащее канону
   (сценарий/SPEC/решение), — стоп-фактор; исполнитель возвращает scope-вопрос,
   `analyst` сверяет канон: снимает требование (восстановление канона) или заводит
   Q/D. Тихая реализация «как в брифе» при расхождении с каноном запрещена.
   `analyst` при записи брифа проверяет цитаты канона (файл и пункт/строки) и
   сверяет требования с `permissions` роли; формулировки запретов — буквально по
   hard rules («`cargo test` не запускался», не «cargo не запускался»).
2. **`steps`** (F18): `tester` 28 → **36**, `coder` 44 → **52**. Бюджет — на вызов
   сессии; авто-продолжение после обрыва шагов его не сбрасывает, продолжение тем
   же `sessionID` даёт свежий. Отчёт/чекпойнт — до тяжёлой проверки (порядок R5).
   Подтверждённые лимиты без изменений: `validator` 36, `auditor` 32, `git` 28.
3. **Allowlist `git`** (F19): добавлена строка
   `- { action: shell, resource: "git branch -vv", effect: allow }`.
4. **Срезанный вывод** (F24, B1 → норма): маркер `…[token-guard] срез: опущено
   ~N байт` означает **неполный** вывод; при зависимости решения от опущенного —
   повтори команду с сужением (`rg -m`, offset/limit, фильтр) или дочитай файл;
   факт среза — в отчёт. Правило — в `AGENTS.md` §«Гигиена и чтение».
5. **Сплит лент** (F25): лента — секции `## iteration N`; порог ~300 строк
   проверяет `analyst` на каждом re-plan и при закрытии задачи; при превышении —
   новый том `T-XX-rN.md` со ссылкой-указателем. Служебные ленты — тот же порядок
   (сервисная сессия или `lead`).
6. **Бюджет чтения `analyst`** (F34): поднят **10 → 12** файлов за вызов.
7. **Эскалация при затыке** (F36, для всех ролей): реальный затык — нет права на
   нужный инструмент, инструмент нештатен, требование брифа вне прав роли, тупик
   после 2–3 попыток — останавливает работу: верни вопрос вызвавшему (что нужно,
   зачем, что пробовал, что мешает). Обходной путь вместо эскалации запрещён;
   цепочка — до владельца. Эскалация — норма, а не сбой.
8. **R2-формулировки и «память роли ↔ канон»** (F35): память `coder` исправлена
   (`cargo test` не запускается (R2); штатные — `cargo fmt --check`, `cargo check`,
   `cargo clippy --all-targets -- -D warnings`; RA — вспомогательный, не замена
   cargo). Правило «память роли не противоречит канону роли; расхождение — находка
   (память правит сервисная сессия, аудит фиксирует)» — в `AGENTS.md` §«Память и
   почта»; микропроверка «память ↔ канон» — в чек-лист `auditor` и `review.md`.

## Следствия

- Run 6 (когда состоится) идёт по уточнённому канону: расхождение брифа с каноном
  ловится на планировании, затык эскалируется, срезанный вывод не используется
  вслепую, ленты ограничены по объёму.
- Память роли признана подчинённой канону роли; исправление памяти `coder`
  снимает перерасход шагов (F35).
- Калибровка `steps` подтверждается будущими прогонами; при новом упоре — реестр.

## Альтернативы

- **Точечные правки без свода** (вариант (а) [Q49](../questions/Q49.md)) — дрейф
  «инструкция ↔ права». Отклонено.
- **Только реестр, без правки канона** (вариант (в)) — у ролей нет протокола на
  расхождение брифа и затык, расхождения воспроизведутся. Отклонено.
- **Массовое расширение allow-листов** — гадание без факта семантики матчинга
  (F38 показал, что матчинг однороден); расширяется одна доказанная команда
  (F19). Отклонено.
