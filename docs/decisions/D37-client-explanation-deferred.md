## Контекст

`client_explanation.feature` не определял, куда обращаться (REST? MCP?), какие
поля, откуда берётся «основание — политика кредитования» и порядок причин «по
приоритету». Нужно было решить: вводить ли отдельный инструмент/эндпоинт
клиентского объяснения в MVP и на каком сырье он строится. Полный контекст —
[Q25](../questions/Q25.md).

## Решение

1. **Клиентское объяснение — вне MVP**, пост-MVP/v0.2; в `credo2` не вводится
   MCP-инструмент `check.explain_client`.
2. **Обоснование (зависимости сценариев):** шаблон и «основание — политика
   кредитования» — банковский юридический текст, источника нет ни в
   `CheckContract`, ни в SPEC (в целевом состоянии — БД/справочники, Q37, или
   расширение контракта); «Заявка одобрена» — клиентская формулировка из
   `decision`-id, словарь задаёт банк ([D21](D21-core-semantics-v01.md), Q10);
   несколько причин и порядок — конвейеры и `Приоритет`, вне MVP
   ([D17](D17-priority-out-of-mvp.md), Q36); потребителя в MVP нет — агент в
   чате пересказывает `Explanation` и без отдельного инструмента (Q31).
3. **MVP-сырьё для клиентского текста — `Explanation`**
   ([D21](D21-core-semantics-v01.md) / Q42: русские `decision`/`reason`),
   рендер клиентского текста — задача потребителя.
4. **Направление на v0.2 (если вернёмся):** MCP-инструмент
   `check.explain_client` для оператора (шаблоны и «политика» — из
   БД/справочников, Q37), маппинг `decision` → клиентская формулировка —
   банковский словарь (Q10), мультипричины и порядок — конвейеры (Q4/Q36); для
   внешнего конвейера возможен REST-рендер — решить тогда. «Шаблон из
   контракта» в текущем виде невозможен: требует расширения схемы
   `CheckContract` — отдельное решение v0.2.

## Альтернативы

- **Ввести `check.explain_client` в MVP** — отклонено: источника шаблона и
  «политики кредитования» нет (нужны БД/справочники, Q37; расширение
  `CheckContract`), «шаблон из контракта» невозможен без изменения схемы.
- **REST-рендер клиентского текста в MVP** — отклонено: та же нехватка
  источника шаблона и потребителя; YAGNI.
- **Отдать сырьё `Explanation` как клиентский текст** — отклонено: `Explanation`
  технический (`decision`/`reason` — русские, но не клиентские формулировки);
  рендер — задача потребителя.
