## Контекст

`lsp.feature` требовал подсказок `Клиент.Возраст`, `Клиент.Доход` **с типом
поля**; откуда берутся схемы полей и словари решений, ни `SPECIFICATION.md`, ни
фичи не говорили. Каталог `tables/` упоминался в SPEC §4.3 и
`notebook_ui.feature`, но формат таблиц не был определён, а
[`GRAMMAR.md`](../GRAMMAR.md) синтаксиса таблиц не вводил. Полный контекст —
[Q37](../questions/Q37.md). Решение связано с составом LSP
([Q38](../questions/Q38.md), [D18](D18-pipelines-out-lsp-mvp.md): completion
полям — v0.2), словарём решений ([Q10](../questions/Q10.md),
[D21](D21-core-semantics-v01.md)) и раскладкой workspace
([Q34](../questions/Q34.md), [D32](D32-test-gate-mvp.md)).

## Решение

1. **Архитектурный источник схемы полей и словарей — БД** (пользовательские и
   системные таблицы). В MVP БД = `HashMap`, явной схемы нет; векторная БД —
   отложена (после MVP).
2. **Каталог `tables/` — рудимент, полностью исключается:** данные приходят из
   БД, а не из `.dar`-файлов таблиц. Убран из
   [`SPECIFICATION.md`](../SPECIFICATION.md) §4.3,
   [`notebook_ui.feature`](../features/notebook_ui.feature),
   [`lsp.feature`](../features/lsp.feature); синтаксис таблиц в
   [`GRAMMAR.md`](../GRAMMAR.md) **не вводится**.
3. **Автодополнение MVP — два источника:**
   - ключевые слова языка: `Правило`, `Если`, `Решение`, `Причина`
     (статический список из [`GRAMMAR.md`](../GRAMMAR.md) §4);
   - эвристика по открытым файлам: все слова с точкой (например,
     `Клиент.Возраст`), встреченные в тексте.
4. **Типы полей в MVP не подсказываются** (явной схемы нет). Целевая
   траектория — строгая статическая типизация; схема колонок берётся из БД
   ([Q9](../questions/Q9.md), [D21](D21-core-semantics-v01.md): в MVP типы
   проверяются на исполнении).
5. **Словарь решений** для автодополнения `Решение = ` — системная таблица
   решений банка в БД (пользователь расширяет свободно, набор не ограничен).
   В MVP — демо-конфиг, имитирующий системную таблицу решений, заполненную
   пользователем банка (включая нестандартные решения из реальной практики,
   не только «Одобрить/Отказать»). Фиксированный набор в коде ядра **не
   хардкодится** ([Q10](../questions/Q10.md), [D21](D21-core-semantics-v01.md)).
6. **Векторная БД — отложена (после MVP).** Абстракция источника данных
   (trait) сейчас не закладывается; `evaluate_rule` работает с `HashMap`
   напрямую. Переход на БД — отдельная задача.

## Следствия

- **Канон языка:** `GRAMMAR.md` синтаксиса таблиц не получает (данные — из БД);
  список ключевых слов §4 не меняется, служит статическим источником
  автодополнения.
- **Требования:** `lsp.feature` — автодополнение опирается на ключевые слова и
  слова с точкой из открытых файлов; типы полей не подсказываются; словарь
  решений — демо-конфиг (не хардкод ядра). `notebook_ui.feature` — каталог
  `tables/` не создаётся. Число файлов/сценариев не менялось (актуальные числа —
  в `features/README.md`).
- **SPEC:** §4.3 освобождён от `tables/` (нота Q37), §3.3 фиксирует состав MVP
  (поля — вне MVP), §10 — решение №33.
- **Отсрочки:** векторная БД, trait-абстракция источника данных, строгая
  типизация полей и completion полям — пост-MVP/v0.2 (переход на БД — отдельная
  задача).
- **Разграничение:** автодополнение — крейт `lsp-dar` (Фаза 2), вне кода
  прототипа `credo2`; `dar-core`/`credo-server` решения не затрагивают.

## Сверка с кодом

(БД) и состав автодополнения LSP (`lsp-dar`, Фаза 2), которых в коде прототипа
`credo2` нет; сверка документная. Проверен след в коде (каталог `tables/`,
`HashMap`, словарь решений) и отражение в SPEC/фичах.

  совпадений не дал.

## Альтернативы

- **Ввести `tables/` с форматом для схемы полей** — отклонено: данные должны
  приходить из БД (пользовательские и системные таблицы), а не из
  `.dar`-файлов; формат таблиц не определён и потребовал бы расширения языка и
  парсера.
- **Брать схему из контракта опубликованных проверок** — отклонено: контракт
  несёт только реально используемые решения ([Q10](../questions/Q10.md)) и не
  описывает типы/схему колонок.
- **Хардкодить фиксированный словарь решений в ядре** — отклонено: набор
  решений задаёт банк и он не ограничен ([Q10](../questions/Q10.md),
  [D21](D21-core-semantics-v01.md)); в MVP — демо-конфиг.
- **Подсказывать типы полей в MVP** — отклонено: явной схемы нет, строгая
  типизация — целевая траектория ([Q9](../questions/Q9.md)); типы проверяются на
  исполнении.
- **Заложить trait-абстракцию источника данных и/или векторную БД сейчас** —
  отклонено: YAGNI; `evaluate_rule` работает с `HashMap` напрямую, переход на
  БД — отдельная задача после MVP.
