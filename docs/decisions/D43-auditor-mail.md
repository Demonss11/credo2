# D43: Отчёт `auditor` — в ленту задачи (право `edit .opencode/mail/**`)

- **Статус:** accepted
- **Дата:** 2026-09-28
- **Resolves:** [Q48](../questions/Q48.md)

- **Affects:** [`auditor.md`](../../.opencode/agents/auditor.md) (права, тело);
  [`AGENTS.md`](../../AGENTS.md) §«Рабочая группа агентов» (карта ролей);
  [`findings-registry.md`](../analysis/findings-registry.md) (F16)
- **Tasks:** — (см. «Сверка с кодом»)

## Контекст

Аудит T-04 (Run 5) стал P2-находкой F16: `auditor` не смог дописать отчёт в
ленту — права позволяли `edit` только `.opencode/memory/auditor.md`. Канон
(`AGENTS.md` §«Память и почта») требует, чтобы роли дописывали отчёт в ленту
задачи сами. Полный контекст — [Q48](../questions/Q48.md);
меморандум W8, том 2 §2 (F16), §4.1, §4.2 (архив — git).

## Решение

1. В `permissions` роли `auditor` добавлено
   `- { action: edit, resource: ".opencode/mail/**", effect: allow }` — append
   отчёта в ленту задачи `.opencode/mail/<T-XX>.md`; при аудите без задачи — в
   служебную ленту.
2. Тело роли (п. 5 «Рабочего цикла») дополнено: краткую версию отчёта роль
   дописывает в ленту задачи (формат — `AGENTS.md` §«Память и почта»).
3. Карта ролей в [`AGENTS.md`](../../AGENTS.md): колонка «Пишет в» у `auditor` —
   «своя память, лента задачи».
4. Бюджетное исключение (F24): разрешено повторное чтение одного файла для
   пропуска среза `token-guard` и проверки своей правки.

## Следствия

- `auditor` фиксирует отчёт в ленте сам; релей `lead` перестаёт быть нормой
  (допустим лишь как вынужденный обход до вступления правки; первый аудит
  канон-пакета, которым вносится право, снова пройдёт релеем).
- Права приведены в соответствие с каноном почты; независимость отчёта аудита не
  зависит от пересказа `lead`.

28.09.2026.

## Альтернативы

- **Оставить релей `lead`** (вариант (а) [Q48](../questions/Q48.md)) —
  расходится с каноном почты, отчёт аудита не принадлежит автору. Отклонено.
- **Отдельный артефакт-отчёт вне ленты** (вариант (в)) — дублирует ленту и ломает
  единый формат почты. Отклонено.
