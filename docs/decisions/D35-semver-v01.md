# D35: Semver v0.1 — числовое сравнение pre-release и build вне идентичности версии

## Контекст

`deferred.feature` фиксировала лексикографическое сравнение идентификаторов
pre-release (`rc2`/`rc10`) как текущее, `core.rs` уже сравнивал их численно;
`semver.feature` ожидала `1.2.3+build` валидной, а `storage_paths.feature` и код
убирали build из пути. Открытым оставался и дубликат `1.0.0+a`/`1.0.0+b`.
Полный контекст — [Q18](../questions/Q18.md).

## Решение

1. **Сравнение версий — по семантике semver** (semver 2.0.0): pre-release
   сортируется ниже release; идентификаторы pre-release сравниваются слева
   направо, числовые — как числа (`1.0.0-rc2` < `1.0.0-rc10`),
   буквенно-цифровые — лексикографически; ошибка парсинга при сравнении —
   ошибка, а не `0.0.0`.
2. **Build-метаданные не входят в идентичность версии.** При парсинге `+build`
   сохраняется (диагностика, `Display`), но `PartialEq`/`Ord` его игнорируют:
   `1.0.0+a == 1.0.0+b`.
3. **При записи в реестр build отбрасывается** (`as_storage`): путь и
   `meta.version`/`contract.version` — без `+build`
   (`checks/{name}/{X}/{Y}/{Z}/`); отдельная связь с исходной строкой версии не
   требуется.
4. **Повторная публикация базы с другим build запрещена:** `1.0.0+a` и
   `1.0.0+b` — один слот версии `1.0.0`; вторая публикация отклоняется как
   обычный дубль — `publish_failed` (§4.5, Q29).
5. **Публикация pre-release остаётся вне MVP** (Q32 п. 8); сравнение из п. 1
   нормативно уже сейчас, публикация `1.0.0-rc.1` вернётся в v0.2 (вариант
   пути — `checks/{name}/{X}/{Y}/{Z-prerelease}/`).

## Следствия

- Семантика сравнения зафиксирована в одном месте и совпадает с semver 2.0.0;
  устаревшая лексикографическая сортировка снята.
- Build — диагностическое расширение, не часть идентичности: `as_storage`
  отбрасывает его при записи, повтор публикации базы отклоняется.
- Правки — `deferred.feature` (сценарий числовой сортировки удалён, 6 → 5),
  `semver.feature` (добавлены 4 сценария, 4 → 8), `storage_paths.feature`
  (комментарий про Q18); разноска статусов/счётчиков — в `features/README.md`
  (зона `docs-writer`).

## Сверка с кодом

Вердикт: ✅ **соответствует** — поведение `src/core.rs` совпадает с решением,
изменений в коде не требуется.

Что проверено (чтением кода и юнит-тестов, 29.09.2026), чем подтверждено:

- **Числовое сравнение pre-release — ✅:** [`src/core.rs`](../../src/core.rs)
  `compare_pre` (381–397) и `compare_ident` (399–412): числовые идентификаторы
  сравниваются как числа, числовой < буквенно-цифрового, буквенно-цифровые —
  лексикографически; `Ord` для `Semver` (415–426) сортирует pre ниже release
  (421–422). Тесты `prerelease_numeric_ordering` (658–663),
  `prerelease_sorts_below_release` (630–634),
  `numeric_identifier_below_alphanumeric` (665–669),
  `more_prerelease_fields_have_higher_precedence` (671–675).
- **Build вне идентичности — ✅:** `PartialEq for Semver` (272–279) игнорирует
  `build`; `Ord::cmp` (415–426) его не учитывает. Тест
  `eq_ignores_build_metadata_consistent_with_ord` (651–656);
  `build_metadata_preserved` (647–649) фиксирует сохранение при `Display`
  (354–365).
- **Отбрасывание build при записи — ✅:** `as_storage` (343–351) не включает
  `build`; тест `as_storage_drops_build` (699–708). Публикация использует
  `version.as_storage()` как `vstr` (`src/lib.rs:329-332`).
- **Дубль базы с другим build — ✅:** [`src/lib.rs`](../../src/lib.rs)
  `publish` (344–351) сравнивает storage-версии в `main` и отклоняет
  существующий слот; ошибка отображается в `publish_failed`
  ([`src/mcp.rs`](../../src/mcp.rs) `ErrorCode::PublishFailed` 59/103–104;
  `publish` 319–324). Оговорка решения («обёртка с кодом `publish_failed` —
  часть Q29») в коде уже выполнена; остаточное покрытие схем успеха — за
  [T-05](../tasks/T-05-mcp-success-schemas/README.md), **known**, новых задач не
  порождает.
- **Публикация pre-release вне MVP — ✅ (не требуется в v0.1):** `Semver`
  парсит pre, но `publish` не ограничивает его; сценарий публикации
  pre-release — v0.2.

`cargo` не запускался (§5.3, [D50](D50-dod-by-package-scope.md)): сверено
чтением кода и юнит-тестов; адресный прогон не требуется.

**Задач не требуется:** поведение уже реализовано и покрыто юнит-тестами;
правок кода решение не порождает. Отмеченное известное место (обёртка
`publish_failed` при дубле build) покрыто Q29/[T-05](../tasks/T-05-mcp-success-schemas/README.md).

## Альтернативы

- **Лексикографическое сравнение идентификаторов** (как в `deferred.feature`)
  — отклонено: расходится с semver 2.0.0 и с уже работающим кодом.
- **Build как часть идентичности версии** — отклонено: `1.0.0+a`/`1.0.0+b`
  превращались бы в разные версии и дублировали слот; build — диагностика.
- **Хранить build в пути/`meta.version`** — отклонено: build не влияет на
  идентичность и не должен попадать в реестр.
- **Ошибку сравнения трактовать как `0.0.0`** — отклонено: маскирует
  невалидную версию; сравнение выполняется по разобранным `Semver`.
