# T-26. Дизайн process-MCP: 6–10 инструментов (storage + validation + query)

- **Статус:** ⬜
- **Приоритет:** P1 (продолжение программы [`T-15`](../T-15-mcp-ready-process/README.md),
  категория «контракты»; старт гейтится заморозкой процесса — фаза D)
- **Зависит от:** заморозка процесса (фаза D [`T-15`](../T-15-mcp-ready-process/README.md));
  вход — подготовленный B2 ([D94](../../decisions/D94-b2-profile-flag.md), `B2_PROFILE`)
- **Источник:** [D95](../../decisions/D95-phase-e-mcp-design.md) (Q92),
  [D78](../../decisions/D78-t15-mcp-ready-program.md) (программа T-15)

## Контекст

Программа [T-15](../T-15-mcp-ready-process/README.md) (D78) ведёт процесс
агентного контура к «сериализации» в MCP-сервер: **storage + validation + query**
над состоянием прогона, **без принятия решений** (записка
[`mcp-ready-process.md`](../T-15-mcp-ready-process/mcp-ready-process.md) §0, §3).
Фаза E карточки [`T-15`](../T-15-mcp-ready-process/README.md)
(`:161-164`) сформулирована как «дизайн MCP-сервера — 6–10 инструментов по списку
операций; storage + validation + query; решений не принимает; отдельная задача
(после заморозки)». Решением владельца 03.10.2026 (сервисная операция r17) фаза E
открыта как отдельная задача `T-26`; предмет — **только process-MCP**; git-MCP
(Приложение A записки) — отдельный горизонт, позже
([D95](../../decisions/D95-phase-e-mcp-design.md), [Q92](../../questions/Q92.md)).

Класс/маршрут априори **L** (контракты/новая подсистема); финально фиксирует
`analyst` при взятии.

## Что сделать

1. **Дизайн 6–10 MCP-инструментов** process-MCP по списку операций записки §5.4
   (`≤10`): `append_progress`, `set_next_action`, `set_current_state`,
   `register_receipt`, `register_re_raise`/`resolve_re_raise`,
   `record_dispatch_metrics`, `add_deferred`/`resolve_deferred`,
   `checkpoint_session`; возможно слияние части операций — до 6–10 инструментов
   (границы — записка §3: storage + validation + query, без решений).
2. **Контракты инструментов** — входы/выходы/ошибки (JSON-схемы, стабильные
   коды ошибок), идемпотентность по ключам операций (§5.4), инварианты §5.3;
   референс — Semantic Anchors (контракты).
3. **Validation-слой** — проверки схемы состояния и инвариантов (§5.1–§5.3);
   референс — BRHP (validation signals).
4. **Query-слой** — метрики и очереди из состояния без ручной сборки (§7);
   референс — Telemetry DB (query-слой).
5. **Traceability** — связь операций/инструментов с состоянием прогона; референс —
   kibi (traceability).
6. **Дизайн-документ** — единый артефакт с контрактами, границами (что не берёт
   MCP), зависимостями и референсами; согласование владельцем.

## Критерий готовности

Дизайн-документ process-MCP: 6–10 инструментов с контрактами (входы/выходы/
ошибки), покрытие storage + validation + query, референсы (kibi, Semantic
Anchors, BRHP, Telemetry DB); согласование владельцем.

## Примечания

- **Предмет — только process-MCP.** git-MCP (Приложение A записки) в задачу не
  входит — отдельный горизонт, позже ([D95](../../decisions/D95-phase-e-mcp-design.md)).
- **Зависимость старта** — заморозка процесса (фаза D
  [`T-15`](../T-15-mcp-ready-process/README.md)); до неё задача ⬜.
- **Вход** — подготовленный B2 ([D94](../../decisions/D94-b2-profile-flag.md),
  `B2_PROFILE`).
- **Класс** — априори L; фиксирует `analyst` при взятии.
- **Дизайн не принимает решений** — исполняет уже принятое (границы процесса;
  записка §3).
- Точные строки/символы — снимок на 03.10.2026; ссылки — по символам, не по
  номерам строк (антипаттерн [§8](../../../.opencode/rules/journal.md)).
