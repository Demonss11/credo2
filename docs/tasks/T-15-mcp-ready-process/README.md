## Контекст

Целевая картина владельца — «сначала процесс, потом MCP»: процесс должен
стать контрактом на операции над состоянием (storage + validation + query),
пригодным для кристаллизации в MCP-сервер. По оценке записки у процесса три
свойства отсутствуют и три — частично (схема, операции, идемпотентность,
трассируемость, разделение слоёв, запрашиваемость). Улики Run 4: F13 (ручное
восстановление записи), F14 (формулировка `expect`), F15 (дрейф `iteration`).

Класс задачи — **L** (канон агентов, права, контракты, несколько подсистем):
полный маршрут, аудит `auditor` до коммита, `researcher` при внешних
зависимостях (MCP-стандарт). Канон агентов правит **сервисная сессия** по
протоколу: журнал → правки → аудит → приёмка → коммит.

## Критерий готовности

- журнальные Q/D заведены и связаны с карточкой;
- схема и операции зафиксированы в каноне; `validate-state.mjs` зелёный в
  pre-flight и на приёмке;
- session-commit и правило останова проверены имитацией обрыва сессии;
- re-raise используется; метрики выводятся из состояния без ручного труда;
- чек-лист готовности закрыт; аудит `auditor` — без расхождений
  «инструкция ↔ права»; отчёт `validator`; статусы и CHANGELOG обновлены;
- пакет закоммичен (одна задача — один коммит; при серии фаз — модель
  коммитов зафиксировать до старта).

## Черновик команды-фасада (создать в фазе C)

`.opencode/commands/git/checkpoint.md`:

```md
---
description: Process-commit прогона (лента, память, снапшот state) по «постоянному» пакету
agent: git
subagent: true
---

Выполни `checkpoint_session` текущего прогона по «постоянному» пакету,
подтверждённому `lead` (одно подтверждение на прогон — запись в ленте и
state; без записи верни «нужно подтверждение», изменяющих команд не
выполняй). Идемпотентно, по одной команде: сверка `git status`/`git log`;
`add` только process-путей пакета; `commit -m "chore(process): runN sM"`;
`push origin process/runN` (таймаут ≥ 5 мин). Продуктовые изменения не
входят; shell-блоки не использовать. Отчёт — в ленту задачи и память; верни
хеши.
```
