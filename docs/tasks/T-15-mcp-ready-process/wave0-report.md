## 3. Выводы

1. **Гипотеза §3.5 подтверждена: deny снимает схему инструмента из запроса**
   (встроенные `skill`/`webfetch`/`execute` — в репозитории;
   `<server>_<tool>` — в изолированном прогоне с `codemode:false`). Приоритет
   — **статике** (канон, права, аудит); плагин — для того, что статикой не
   выражается, или как пилот без правок канона.
2. В текущей конфигурации репозитория (`codemode` по умолчанию `true`)
   MCP-схемы **не** являются ключами `event.tools` — они в system-части
   Code Mode-каталога (29 207 Б). B2-префиксы — страховка (0 срабатываний);
   работающий рычаг по MCP — статические deny (см. §4).
3. **B1 работает на боевых потоках** (156,8 КБ срезов за сессию; крупнейшие —
   shell/webfetch/grep/read); DoD волной не затрагивался (нет правок
   `src/**`, `tests/**`); полная проверка среза `cargo test` — на первом
   тяжёлом прогоне `validator`.
4. Действующие deny-наборы ролей уже экономят ≈6,4–6,9 КБ схем на сессию
   (docs-writer/git/analyst против базы) — статика работает как «схемный
   фильтр» и без плагина.
