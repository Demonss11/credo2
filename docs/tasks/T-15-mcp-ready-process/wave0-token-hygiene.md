## 1. Цель и границы

Цель — снизить расход токенов на прогон **без правок канона** и без потери
качества приёмки (DoD `validator` остаётся зелёным).

**Входит:**

- конфиг OpenCode: форматтер `rustfmt`, чистка мёртвого поля `instructions`;
- локальный плагин-пилот `.opencode/plugins/token-guard.ts` (обрезка выводов
  инструментов; обрезка tool-схем по агентам);

**Не входит (канон — отдельным пакетом, фаза C):**

- сплит `AGENTS.md` на вложенные (ленивая загрузка) — правка канона;
- правки `dispatch-loop.md` / `git-workflow.md`, статические `permissions`
  агентов;

**Принцип:** сначала измерить — потом закреплять; откат волны тривиален
(конфиг/плагин).

## 3. Состав wave 0

### 3.1. A. Конфиг (правки `opencode.json`)

1. `"formatter": true` — реально включится `rustfmt` (`.rs`); `prettier` /
   `biome` / `oxfmt` не активируются без `package.json`, markdown и JSON не
   тронуты; `shfmt` / `clang-format` — только для расширений, которых в
   задаче нет.
2. Убрать `"instructions": ["AGENTS.md"]` — V2 не резолвит поле (инструкции
   идут через `AGENTS.md` автоматически).

Проверка: правка 1–2 `.rs` → автоформат сработал; markdown не изменён.
Оговорка для аудита: форматтер запускает харнесс, а не роль — это не
расширение прав роли.

### 3.2. B. Плагин `token-guard.ts` (пилот)

Место: `.opencode/plugins/token-guard.ts` (автозагрузка; правки могут
требовать `opencode service restart`).

**B1. Обрезка выводов** (`ctx.tool.hook("execute.after")`):

- лимит результата ~12 КБ (голова + хвост);
- **всегда сохранять** строки с `error` / `warning` / `FAILED` / `failed` /
  `passed`;
- удалять ANSI; для `read` — пометка «остаток опущен (offset/limit)»;
- счётчики экономии (байты, число срезов) — в `ctx.storage`, вывод в отчёт.

**B2. Обрезка tool-схем** (`ctx.session.hook("context")`):

- по имени агента удалять ненужные ключи `event.tools`;
- черновые правила (включать после сверки с брифами и `review.md`):

| Агент | Снять префиксы |
|---|---|
| `docs-writer` | `rust-analyzer*`, `credo*` |
| `git` | `rust-analyzer*`, `credo*` |
| `analyst` | `rust-analyzer*` (credo — по нужде) |
| `lead` | не трогать до сверки |
| остальные | без изменений |

- не менять tools при `kind != "primary"`; не трогать инструменты, которыми
  роль пользуется по брифу.

**Правила безопасности:** откат — выключить плагин; при сомнении — только B1;
изменения эффективных прав (сужение) — показать `auditor` при переходе из
пилота в норму.

### 3.3. C. Дисциплина (без правок канона)

- Сплит ленты при ~300+ строках (правило уже есть — соблюдать; вести
  `T-XX-rN.md` со ссылкой);
- не читать артефакты целиком там, где есть карта заголовков;
- фиксировать в ленте T-15 тяжёлые чтения/выводы — для замера.

### 3.4. Замер до/после

- штатные счётчики сессий/стоимости OpenCode + счётчики плагина;
- метрики: токены и стоимость на сопоставимом сценарии, число tool-вызовов,
  число сессий, байты срезов;
- критерий успеха: снижение расхода при зелёном DoD; иначе — доработка/откат.

### 3.5. Статические permissions и policies (кандидаты; вне пилота B1/B2)

- **Per-agent permissions** (`.opencode/agents/**` — канон, фаза C с аудитом):
  в V2 действия включают `<server>_<tool>` для каждого MCP-инструмента и
  `execute` (Code Mode). Запрет даёт жёсткое «нельзя», но **не декларировано**,
  что он убирает схему инструмента из промпта: проверить в пилоте B2
  (сравнение до/после); если убирает — приоритет статике, плагин — для
  остального.
- **`execute` (Code Mode):** для ролей без сценарных вызовов — кандидат на
  статический запрет/снятие схемы (крупная фикс-статья каталога); проверка —
  тем же сравнением.
- **Policies** (`experimental.policies` в `opencode.json` — служебная зона):
  жёсткие запреты, никогда не «ask», перекрывают разрешения и approvals;
  кандидаты-страховки к канону: `shell:*--force*`, `shell:*reset --hard*`,
  `read:*/.ssh/*`. Раздел экспериментальный — следить за изменениями V2;
  список согласовать до включения.

### 3.6. References — рассмотрено, вне волны

References дают доступ к каталогам **вне проекта** (локальным или git): в
инструкции агента попадают только алиас, путь и `description` (строка —
оплачивается каждой сессией), содержимое читается по требованию; права —
обычные `external_directory`/`read`, ссылки прав не дают. Для экономии
токенов wave 0 не применяем (наши доки и так в проекте читаются по мере
надобности), но фиксируем как кандидат «после демо»: управляемый доступ к
внешним источникам — DAR-доки рабочего пространства (`../..`), архив внешних
обзоров; включать вместе с правами (внешние рамки AGENTS.md).

### 3.7. Skills — рассмотрено (вне волны; микро-рычаг в фазе C)

Скиллы (`SKILL.md` в `.opencode/skills/`) — «контекст по требованию»: в каждый
запрос попадают только ID/имя/`description`; тело грузится вызовом `skill` по
ID; поддерживающие файлы (`scripts/`, `references/`, шаблоны) читаются по
ссылке. Право `skill` (ресурс — ID, эффекты allow/ask/deny) скрывает скилл от
модели (`deny`) и настраивается по агентам. Для wave 0 изменений нет; кандидат
фазы C — сузить объявление `rust-skills` профильными ролями (`rust-expert`,
при нужде `coder`/`tester`); на будущее — скиллы как носители
чек-листов/шаблонов/скриптов и HTTP-каталог для общих плейбуков.

## 4. Порядок исполнения

1. A (конфиг) → smoke-проверка форматтера;
2. B1 (обрезка выводов) → наблюдение на ближайших задачах;
3. B2 (обрезка схем; заодно — сравнение со статическими запретами
   `<server>_<tool>`/`execute`) — после сверки правил с ролями, отдельным
   шагом;
4. отчёт wave 0 → решение: канон (фаза C) либо оставить пилотом.

## 5. Риски

| Риск | Митигация |
|---|---|
| Обрезка срежет нужное | сохранять error/warning-строки; лимит настраиваемый; пере-запуск команды с фильтром |
| Pruning сломает роль | правила только после сверки с брифами; быстрый откат; начинать с `docs-writer` / `git` |
| Форматтер против канона «роль не запускает инструменты» | запускает харнесс, не роль; отметить в аудите |
