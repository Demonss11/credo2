# T-16. check.test на stale-черновике: исполнение по тексту файла rules/{name}.dar

- **Статус:** ⬜ открыта
- **Приоритет:** P1 (контракт `check.test`, до демо)
- **Зависит от:** — (T-01 закрыт, поле `stale` есть)
- **Источник:** Q12 (и сценарий `../../features/test_draft.feature`; связано:
  Q29, T-01); найден пилотом T-11 (H7 реестра).

## Контекст

Пилот T-11 (находка **H7** реестра находок) выявил расхождение канона и кода:
при устаревшем черновике `check.test` исполняет **текст черновика**, тогда как
канон требует исполнять текст **файла** `rules/{name}.dar`.

- Канон — [`Q12`](../../questions/Q12.md): «при расхождении (файл изменён
  вручную, черновик устарел) выигрывает файл; черновик помечается `stale`»;
  сценарий `../../features/test_draft.feature` («Тестирование устаревшего
  черновика», строки 48–54): «тестирование выполняется по тексту файла
  `rules/МинимальныйВозраст.dar`».
- Код — `src/mcp.rs:235`: `evaluate_rule(&d.rule, …)` исполняет текст черновика
  (при этом `is_stale` — `src/lib.rs:811-822`).
- Приёмка T-01 зафиксировала расхождение вне объёма T-01; тест
  `stale_true_when_dar_hash_differs_q29_inv3` (`src/mcp.rs:799-826`) проверяет
  `stale = true` и что тест не блокируется, но не проверяет источник исполнения.

## Что сделать

- В `test(...)` (`src/mcp.rs`): если черновик **stale** (файл
  `rules/{name}.dar` есть и его хэш ≠ `source_hash`; см. `is_stale`,
  `src/lib.rs:811-822`) — исполнять правило, разобранное из текста файла;
  иначе (нет файла / не stale) — текущее поведение (текст черновика).
- Ответ — по контракту §4.5 от исполненного текста.
- Интеграционный тест с реальным stdio (`tests/mcp_draft.rs`) + юнит-тест в
  модуле.

## Уточнить при реализации

Без новых Q/D (в рамках D40):

- поведение при нечитаемом/невалидном файле (код ошибки);
- что фиксировать в `last_test_checksum`/`tested_at` при тесте stale-черновика;
- совместимость с тест-гейтом T-02.
