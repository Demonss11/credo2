# T-01. Черновик: `source`, `source_hash`, `stale`, `test_valid`

- **Статус:** ✅ сделана
- **Приоритет:** P1
- **Зависит от:** —
- **Источник:** Q12 (черновик — производное состояние), Q29 (инварианты 2–5 §4.5).
- **Отчёт приёмки:** [`../../reviews/T-01-2026-09-26.md`](../../reviews/T-01-2026-09-26.md).

## Что сделать

- `Draft` (`src/lib.rs`) хранит `source: String` и `source_hash`
  (sha256 текста), а не только распарсенный `Rule`.
- `check.get_draft`/`check.list_drafts` отдают рендеренные строки
  (`source`, `condition`, `decision`, `reason`); внутренний `Rule` не
  публикуется.
- Вычисляемые поля:
  - `stale` — файл `rules/{name}.dar` существует и его хэш ≠ `source_hash`
    черновика;
  - `test_valid` — `last_test_checksum == source_hash`.

## Критерий готовности

Сценарии `../../features/draft.feature` («Получение списка черновиков»,
«Получение содержимого черновика», «Черновик из буфера редактора»,
«Черновик — производное от .dar-файла», «Устаревший черновик помечается
stale», «Черновик без .dar-файла не помечается stale») и
`../../features/test_draft.feature` («Успешный check.test фиксирует метку»);
`cargo fmt --check` / `clippy -D warnings` / `cargo test`.
