# T-24. Интеграционный тест CLI-контура REST на реальном бинарнике

- **Статус:** ⬜ открыта
- **Приоритет:** P3 (после демо, v0.1.x — гигиена тестов; поведение не меняется)
- **Зависит от:** —
- **Источник:** Q22, [D26](../../decisions/D26-rest-auth-x-api-key.md)
  (связано: Q27, [D27](../../decisions/D27-rest-launch-address.md))

## Контекст

Решение [D26](../../decisions/D26-rest-auth-x-api-key.md) (Q22) задаёт REST-аутентификацию:
ключ через `--api-key`/`CREDO_API_KEY` (заголовок `x-api-key`), при
отсутствии ключа API открыт (режим демо); запуск REST — флагами
`--rest`/`--addr`/`--no-rest` (D27, Q27). Продуктовый код соответствует
решению; существующие тесты `tests/rest.rs` строят `AppState` напрямую и
**не покрывают CLI-контур**: флаги бинарника и способы задания ключа (аргумент
и переменная окружения) тестами не запускаются — в `tests/common/mod.rs`
встречается только `--no-rest`. Остаток покрытия — этот тест.

## Что сделать

1. **Интеграционный тест CLI-контура REST** — запуск реального бинарника через
   `env!("CARGO_BIN_EXE_credo2")` (процессом, а не `AppState` напрямую):
   - **Запуск и готовность:** `--rest` / `--addr 127.0.0.1:<свободный порт>`
     поднимают сервер — проверка через `GET /health`; ожидание готовности —
     поллинг порта/эндпоинта.
   - **Ключ через `--api-key`:** без заголовка `x-api-key` → `401`; с
     корректным заголовком → `200`.
   - **Ключ через env `CREDO_API_KEY`:** тот же контракт (`401` без заголовка,
     `200` с ним).
   - **Открытый режим:** без ключа (ни флага, ни env) API открыт (демо) —
     запрос без заголовка отвечает `200`.
   - **Конфликт флагов:** `--no-rest` вместе с `--rest` отклоняется (отказ
     `clap`).
2. **Не ослаблять существующие проверки:** поведение `src/**` не меняется —
   это тестовая задача.

## Критерий готовности

Тест зелёный в `cargo test --all`; существующее поведение не изменено;
DoD задачи ([`../README.md`](../README.md) §«DoD для любой задачи»).
