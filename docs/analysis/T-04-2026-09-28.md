## Scope-разбор (участок №3): `check.delete_draft` по отсутствующему черновику

- **Спор:** план Run 5 требовал ошибку `draft_not_found`; `coder` оставил
  идемпотентный успех и вернул вопрос. Анализ (строго по канону):
- `draft.feature` стр.44–49 («Удаление черновика»): `deleted:true`, а стр.49
  («обращение к черновику возвращает ошибку `draft_not_found`») относится к
  **доступу** к уже удалённому черновику (`get_draft`), а **не** к повторному
  `delete_draft`.
- `draft.feature` стр.51–55 («Повторное удаление … не является ошибкой»):
  пустая песочница → `deleted:false`, идемпотентность. Это **отдельный
  сценарий**, а не исключение.
- `docs/SPECIFICATION.md` стр.531: успех `check.delete_draft` — `ok`
  (`deleted: bool`); стр.504–508 — `draft_not_found` для отсутствующего
  объекта доступа.
- `docs/OPEN_QUESTIONS.md` Q29 §5 (стр.1253–1257): `deleted:true` при успехе;
  «черновика не было — `deleted:false`; отсутствие черновика не является
  ошибкой (идемпотентность)».
- `tests/mcp_draft.rs::delete_is_idempotent` (стр.366–384): повторное удаление
  обязано быть **не** ошибкой (зона `tester`).
- **Вердикт:** требование плана противоречило канону; поведение `coder`
  канонично. Требование **снимается**, канон восстанавливается правкой плана

  `get_draft`/`test`/`publish` по отсутствующему черновику.
