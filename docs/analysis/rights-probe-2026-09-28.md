# Пробы прав 2026-09-28 — `git -C` (F38) и deny `execute` (смоук)

> Улика, не канон (Q41). Задача: закрыть перепроверку F38 и проверить критерий
> приёмки deny `execute` (§4.11 меморандума W8 т. 2). Проведено после
> канон-пакета 28.09.2026; правок в репозиторий в ходе проб не вносилось.
> Связано: [memorandum-W8-run5.md](memorandum-W8-run5.md) (F35/F36/F38, §4.11,
> §4.16), [rights-matching-2026-09-27.md](rights-matching-2026-09-27.md) (T-13),
> разбор сессии [`tester`](T-04-run5-tester-session.md) §3.

## 1. F38 — матчинг `git -C`

**Вопрос.** В Run 5 (`tester`) команды `git -C <путь> diff …` прошли, а
`git -C <путь> status -sb` — отклонена; канон T-13: «`-C` не покрыт ни одним
паттерном». Требовалось установить фактическое поведение.

**Метод.** Дочерняя сессия роли `tester` (права роли: `git status *`,
`git diff *`; `log`/`rev-parse` в allowlist нет) — 10 команд по одной, без
изменений в репозитории.

| № | Команда | Результат |
|---|---|---|
| 1 | `git status -sb` | выполнена |
| 2 | `git diff --stat` | выполнена |
| 3 | `git -C <abs POSIX> status -sb` | **отклонена** (`permission.rejected: shell`) |
| 4 | `git -C <abs POSIX> diff --stat` | **отклонена** |
| 5 | `git -C <abs POSIX> log -1 --oneline` | отклонена |
| 6 | `git -C <abs POSIX> rev-parse HEAD` | отклонена |
| 7 | `git -C . status -sb` | отклонена |
| 8 | `git -C . diff --stat` | отклонена |
| 9 | `git -C <abs Windows> status -sb` | отклонена |
| 10 | № 3 повтор | отклонена (воспроизводимо) |

**Вывод.** Матчинг **однороден**: `-C` в любом виде (абсолютный POSIX/Windows,
относительный `.`) отклоняется; команды без `-C` проходят. Канон T-13
подтверждён; наблюдение Run 5 («`diff` с `-C` прошёл») **не воспроизводится** —
вероятнее всего, неточность записи разбора сессии (либо команда фактически шла
через `workdir`). Правило в силе: `git -C` не использовать, рабочая
директория — полем `workdir`; запись добавлена в память `tester`.

*Оговорка:* проба выполнена дочерней сессией с профилем прав роли (`status`/
`diff` разрешены, `log`/`rev-parse` — нет), что соответствует фронтматтеру
`tester`; результат представителен.

## 2. Смоук deny `execute` (§4.11)

Критерий приёмки правки: живой вызов роли после deny `execute` — доступный
инструментарий работает.

| Роль | Проверки | Результат |
|---|---|---|
| `docs-writer` | shell `rg -n "Гигиена и чтение" AGENTS.md`; read 6 строк | обе выполнены |
| `git` | `git status -sb`; `git branch -vv`; `git remote -v` | все три выполнены |

Правок в репозиторий не вносилось. Вывод: deny `execute` не ломает
read/shell-путь ролей; `git branch -vv` (новая строка allowlist, F19) работает.

*Хвост:* edit-путь смоуком не проверялся (файлы не менялись) — покрывается
штатной работой ролей.
