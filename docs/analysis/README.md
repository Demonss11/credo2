# analysis — досье решений `analyst`

Досье задачи — **улики решения, не канон** (Q41): здесь `analyst` фиксирует
срез, на котором принимал решение, и обоснование плана. Канон — журнал
(`questions/`, `decisions/`), требования — [`../features/README.md`](../features/README.md);
досье на них ссылается и не дублирует.

Решение и права роли — [D39](../decisions/D39-loop-dispatcher.md) (Q44),
правило цикла — [`../../.opencode/rules/dispatch-loop.md`](../../.opencode/rules/dispatch-loop.md).

## Правила

- **Один файл на задачу:** `analysis/<T-XX>-<дата>.md` (`T-12-2026-09-27.md`);
  повторный вызов `analyst` по той же задаче файл **обновляет**, а не плодит
  копии (дата в имени — дата заведения).
- **Зона записи** — только `analyst` (одно решение за вызов): остальные роли
  досье читают, не правят.
- **Объём** — кратко: до 40 строк для класса S, до 80 для M/L; пересказ
  канона не переносится — ссылки вместо копий.
- **Статус** — рабочий артефакт задачи: живёт, пока задача идёт; после
  закрытия остаётся следом решения, но каноном не становится.

## Пункты досье

| Пункт | Что содержит |
|---|---|
| Цель | результат задачи в одну-две строки |
| Источник | `Dn`/`Qn` журнала и карточка `tasks/T-XX/` |
| Скоуп | что входит в работу |
| Границы | что явно не трогаем (и почему) |
| Открытые вопросы | что требует `Qn`/`Dn` до исполнения |
| Класс | S/M/L и обоснование (максимум из объёма и риска) |
| Риски | что может сорвать задачу и как проверяется |
| Критерии приёмки | по чему `validator` закрывает задачу |
