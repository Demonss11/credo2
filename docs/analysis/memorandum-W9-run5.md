## 2. Разбор находок

### F15. `iteration` — чистая проверка (W8, черновик)

**Наблюдение.** Run 5: старт `iteration: 1`, rework не было, приёмка с первого
раунда → `iteration` остался `1` на всех участках; номера участков шли через
`progress_marker` (`run5_t04_plan` → … → `run5_t04_finalize`), не через
`iteration` (`next_action.yaml`, `current_state.yaml`, лента).

**Оценка.** Дрейфа нет — норма W8 §4.2 соблюдена. Механика инкремента при
`rework` **не проверялась** (условие не возникло) — честная пометка для
чек-листа §12 (п. 2).

**Решение.** Внести F15 в реестр (долг W8); чистую проверку инкремента
выполнить на первом `rework` (кандидат — Run 6/T-02 при возврате).

### F16. `auditor` не может дописать отчёт в ленту (P2 аудита)

**Наблюдение.** `auditor` при аудите T-04 получил `permission.rejected` на
`edit .opencode/mail/T-04.md`; его фронтматтер разрешает `edit` только
`.opencode/memory/auditor.md` (`.opencode/agents/auditor.md:8-9`). Отчёт внесён
релеем `lead` (запись в ленте от 28.09.2026); по канону (`AGENTS.md` §«Память и
почта») роли дописывают отчёт в ленту сами.

**Оценка.** Расхождение «инструкция ↔ права» (класс Б). Следствие: лента задачи
без первичной записи аудита; релей `lead` — обход нормы. Решение владельца
28.09.2026: выдать право `edit .opencode/mail/**`.

**Решение.** §4.1 (права и тело роли) + §4.2 (`AGENTS.md`, «Пишет в») + драфт
§5.1. До внесения — релей `lead` остаётся допустимым (зафиксировано в ленте).

### F17. Бриф плана противоречил канону

**Наблюдение.** Бриф `coder` (участок №2) требовал: `check.delete_draft` по
отсутствующему черновику → ошибка `draft_not_found` (со ссылкой «канон
`draft.feature` стр.49/68»). `coder` вернул scope-вопрос: канон требует
идемпотентного успеха (`draft.feature` стр.51–55; SPEC §4.5; Q29 §5;
`tests/mcp_draft.rs::delete_is_idempotent`). Re-plan участка №3 снял требование
как ошибочное чтение канона (восстановление канона, не scope-решение).

**Оценка.** Класс Б: ошибка планирования, пойманная исполнителем — механизм
сработал (тихой правки не было). Но правило «что делать при расхождении брифа с
каноном» в каноне явно не записано.

**Решение.** §4.3 — правило в `dispatch-loop.md` (§«Hard rules»); драфт §5.2.

### F18. Упоры в лимит `steps`

**Наблюдение.** `tester` (28 шагов) упёрся в лимит дважды: первый раз — на
середине рефакторинга `tests/mcp_draft.rs` (файл в некомпилируемом состоянии,
без отчёта), второй — на завершении; оба продолжены тем же `sessionID` и
доведены. `coder` (44 шага) завершил правки, но не оставил текстового отчёта —
отчёт и чекпойнт получены продолжением сессии.

**Оценка.** Класс Б: потери не было (resume по состоянию сработал трижды), но
два обрыва у `tester` на одной задаче — сигнал малого запаса. Отчёт/чекпойнт до
длинной верификации (R5) снижает риск, но не заменяет запас шагов.

**Решение.** §4.4 — `tester` 28→36, `coder` 44→52; правило resume тем же
`sessionID` — норма (уже в `AGENTS.md` §«Лимиты шагов»), дополнить не требуется.

### F19. `git branch -vv` вне allowlist

**Наблюдение.** При `branch_start` проверка upstream командой `git branch -vv`
отклонена движком (нет в allowlist `git`); роль корректно сообщила и сверила
upstream по `push -u` и `git status -sb`.

**Оценка.** Класс В (P3): правка — одна строка; команда нужна для идемпотентной
проверки ветки.

**Решение.** §4.5; драфт §5.2.

### F20. Форматтер харнесса ≠ `cargo fmt`

**Наблюдение.** `tester`: автоформаттер при сохранении сортирует импорты иначе,
чем `cargo fmt` (style edition); пришлось избегать mixed-case списков импортов
(`use common::*;`, полное `serde_json::Value`) — `cargo fmt --check` при этом
зелёный. `Cargo.toml`: `edition = "2024"`; `rustfmt.toml` в репозитории нет.

**Оценка.** Класс А/конфиг: standalone-`rustfmt` без `rustfmt.toml` не знает
edition 2024 → расхождение с `cargo fmt` в деталях стиля; риск fmt-петель.

**Решение.** §4.6 — `rustfmt.toml` (`edition = "2024"`) + smoke-сверка.

### F21. `state/**`: конфиг и канон разошлись

**Наблюдение.** Владелец 28.09.2026 убрал `state/` из `.opencode/.gitignore`
(файл теперь не игнорирует `.opencode/state/**`; `git status` показывает `??`).
Канон в трёх местах говорит «вне git»: `AGENTS.md:27` (карта), `AGENTS.md:100`
(§«Память и почта»), `dispatch-loop.md` §«Git-пакет» (стр. 73).

**Оценка.** Класс В/дрейф: конфиг — источник поведения, канон обязан совпасть.
Связь: T-15 фаза C (session-commit, снапшоты состояния).

**Решение.** §4.7 — синхронизировать три текста; состояние включать в
процессные пакеты прогона (первый — пакет Run 5).
