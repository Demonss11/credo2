## 1. Схема

Всё общение ролей — **только через оркестратора** (ведущий контур; в Run 5 это
сервисная сессия, не отдельный `lead`). Каждая роль — отдельная сессия; результат
возвращается оркестратору; правки ролей живут в общем рабочем дереве.

```text
ВЛАДЕЛЕЦ
  │ ① «первым тяжёлым прогоном берём T-04»
  │ ② «волна 0: локальный merge exp→develop» (решение до старта)
  ▼
ОРКЕСТРАТОР (сервисная сессия, lead-контур)
  │
  ├─▶ analyst  ⓐ план T-04 → досье docs/analysis/T-04-2026-09-28.md, next_action, лента T-04.md
  │             класс L; «класс-спор» (в карточке T-15 — M-пилот) → на гейт
  │
  ├─▶ git      ⓑ w0_merge: R7-коммит на exp (ae2b62d) + merge exp→develop (0437799), без push
  │
  ├─▶ ВЛАДЕЛЕЦ ③ гейт 1: класс? пакет ветки? R7-файлы?  →  «L, полный пакет, оставить на ветке»
  ├─▶ git      ⓒ branch_start: feature/T-04-mcp-errors от develop (+push -u)
  ├─▶ docs-writer ⓓ ⬜→🚧 (карточка + реестр)
  │
  ├─▶ analyst  ⓔ re-plan №2: очередь coder → tester → validator
  ├─▶ coder    ⓕ конверт §4.5 (src/mcp.rs, src/lib.rs) — упор в лимит шагов (44)
  │      └─ resume тем же sessionID → отчёт + чекпойнт + scope-вопрос (delete_draft)
  │◀── возврат: scope-вопрос (бриф противоречил канону)
  ├─▶ analyst  ⓖ re-plan №3: вердикт «а» — канон требует идемпотентного удаления; Q/D не нужны
  ├─▶ tester   ⓗ интеграционные тесты — упор в лимит ×2; resume ×2 → fmt/check ok, отчёт
  ├─▶ validator ⓘ полный DoD: accepted 107/0, квитанция        ◀── ТОЧКА ВЕТВЛЕНИЯ
  │
  ├─▶ analyst  ⓙ re-plan №4 (закрытие): auditor → docs-writer → гейт
  ├─▶ auditor  ⓚ аудит: P1 нет; P2 — нет права писать в ленту → отчёт внесён релеем lead
  ├─▶ docs-writer ⓛ ✅ + CHANGELOG (features не менялся)
  │      └─ сверка снимка: 19 путей ⊆ package.add_paths
  ├─▶ ВЛАДЕЛЕЦ ④ гейт 2: полный пакет? push develop с волной 0?  →  «да, да»
  ├─▶ analyst  ⓜ re-plan №5: git + complete
  ├─▶ git      ⓝ branch_end: коммит 3545afa → merge cd845d4 → push develop → ветка удалена
  └─▶ complete: итог владельцу
```

## 3. Числа и правила

- **Вызовов субагентов: 17** (до прогона 2, в прогоне 15) в **14 сессиях**:
  `analyst` — 5 сессий (план + 4 re-plan), `git` — 3, `docs-writer` — 2,
  `coder` — 1 сессия (2 вызова: работа + resume), `tester` — 1 сессия (3 вызова),
  `validator` и `auditor` — по 1.
- **Точки ветвления** (D39): отчёт `validator` (accepted/rework), scope-вопрос,
  несовпадение `expect`, resume — каждый раз **re-plan `analyst`** новым вызовом
  (свежий контекст, не продолжение).
- **Гейты владельца**: 2 в прогоне (класс/пакет ветки; пакет завершения и
  публикация) + 2 решения до прогона (выбор T-04; merge волны 0). Всё — через
  `question`, ответы зафиксированы в ленте и `progress.yaml`.
- **Роли не общаются напрямую**: `coder` не «передаёт» `tester` — возвращает
  отчёт оркестратору, тот вызывает следующего.
- **Resume тем же `sessionID`** — только для продолжения оборванной сессии
  (`coder` 1×, `tester` 2×); re-plan — всегда новая сессия.
