  не коммитились; `docs/features/README.md` (не менялся) не расширял пакет.

  коммит) — дерево остаётся чистым, отчёт роли не разъезжается с коммитом.
- **Отчёт [22] полон:** хеши (`3545afa`, `cd845d4`), old→new push
  (`3eb0856..cd845d4`), состояние `develop`/ветки, особенность с `branch -d`.

- **Отмечано самой ролью:** в ленте/памяти хешей нет (запись дописана до

2. **Порядок удаления ветки в правиле расходится с практикой — 3/3 случая.**
   Факт: `git-workflow.md:81` предписывает `git branch -d` → `git push origin

   завершении; правка — одна строка. Предложение: в §«Завершение задачи»
   закрепить порядок `git push origin --delete` → `git branch -d` (с оговоркой
   «`branch -d` может отказать из-за устаревшего upstream — тогда сначала
   удалить remote»); кандидат F-записи (см. §8).
3. **Срезы `token-guard` задели оба стартовых чтения.** Факт: память (~45%) и

4. **Хеши — только в отчёте и `progress.yaml`.** Факт: запись в ленту/память
