## 3. Проблемы (с уликами)

1. **Упоры лимита `lead` ×4 (+3 «продолжай»).** 16 шагов на запуск; действий
   ~12; каждое действие ≈ вызов роли + 2 записи + чтения = 3–5 шагов.
   Сегменты 16/16/16/11/5. Данные F27/F58.
2. **«Толстый» `lead`: 46 чтений / 42 правки.** Чтения: лента T-24 17× (592
   строки), `next_action` 12×, `current_state` 6×, `progress` 3×, лента T-20 3×,
   канон 4 (dispatch-loop, state-schema, memory/lead, .gitignore). Правки:
   `progress` 22 + лента 20 — **по 2 записи на действие**; ~60% шагов сессий.
3. **8 вызовов `analyst`** (105 шагов, 205 инструментов, ~20 мин, $0.175):
   план + 3 resume-синка + rework + закрытие + финал + CCSN. Канон «re-plan
   всегда при resume» + короткая очередь (1–3 действия) → churn; каждый синк —
   свежий срез и перезапись плана.
4. **Лента T-24 — 592 строки; сплит порога 300 не выполнен** (канон: `analyst`
   проверяет порог на каждом re-plan). Следствие — тяжёлые повторные чтения
   ленты (17× у `lead`).
5. **~15 отклонённых команд (права ↔ потребности):** `lead` (`git rev-parse`,
   `agents-perms`, `git ls-remote`), `analyst` (`git branch`/`rev-parse` ×5,
   `Get-Content`), `git` (`git branch --list` ×2, `git ls-remote` ×3),
   `validator` (`tail`). Каждое — потерянный шаг; часть проверок осталась
   косвенной (например, отсутствие origin-ветки — без сетевой сверки).
6. **Модель `#max` у `lead`:** reasoning 112.6k (30% биллинга роли), $0.212 —
   при `#default` у всех ролей. Связь: F60 (атрибуция/модели).
7. **CCSN `git.push-delete`:** удаление origin-ветки только вручную → +2
   re-plan `analyst` (уборка, ожидание), эскалация владельцу, **прерванный
   вызов** `analyst` (записей нет), ручной шаг владельца; ~7 шагов `lead`.
8. **Stale state на старте:** сессия началась с T-20-снимка (гейт закрытой
   задачи); `lead` потратил seg0 (16 шагов, 160k симв. reasoning) на разведку

9. **`tester` не может запускать `clippy`** (права: `cargo check`, `cargo fmt`):

## 5. Предложения (вход C9/C12 и ревизия прав)

- **A. Цена шага `lead`:** одна запись на действие (`progress`); лента — отчёты
  ролей + сегментный итог `lead`; чтение только хвоста (offset/`rg`); запрет
  повторных чтений плана в одном действии. Цель — 2–3 шага на действие.
- **B. Лимит `lead` 16:** после A переоценить; при нехватке — вариант W8 §7(б)
  (16→24) либо правило останова (C9).
- **C. Политика re-plan:** план на весь участок до пакета (не 1–3 действия);
  resume-синк — только при расхождении (лёгкий чек `lead` без вызова
  `analyst`); закрытие+пакет+уборка — одним планом; лимит re-plan'ов на S.
- **D. Права:** `lead` + `git rev-parse --short HEAD`; `git` + `git branch
  --list *`, `git ls-remote --heads origin *`; `analyst` — не пытаться (или
  read-only branch/rev-parse); `validator` — без `tail` (есть `read`/`rg`);
  `tester` + `cargo clippy --all-targets -- -D warnings` (тест-пакеты).
- **E. CCSN-процедура:** в `git-workflow.md` §«Завершение задачи» — при блоке
  `git.push-delete`: владелец удаляет вручную, роль затем `branch -d`; без
  re-plan/эскалационного цикла (шаблон «хвост closeout»).
- **F. Сплит лент:** контроль порога 300 машинно (скрипт/`validate-state.mjs`)
  или чек-пунктом плана `analyst`.
- **G. State hygiene:** после `complete` — сброс/метка `idle`, чтобы новая
  сессия не разбирала stale-снимок.
- **H. Модель `lead`:** `#default` (или осознанное решение владельца — `#max`).
