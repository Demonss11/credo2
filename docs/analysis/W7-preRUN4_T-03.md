## 1. Доступы и команды (F4, A1–A5)

### 1.1. Research-шаг (обязателен до правок)

**Задача:** выяснить реальную семантику матчинга прав shell в OpenCode v2.
**Метод:** мини-эксперимент в песочнице, матрица «паттерн → команда → результат».
**Обязательные пары:**

| Паттерн | Проверяемые команды |
|---|---|
| `git diff *` | `git diff`, `git diff --stat`, `git diff -- *.rs`, `git diff HEAD~1` |
| `git ls-remote *` | `git ls-remote`, `git ls-remote origin` |
| `rg *` | `rg X`, `rg X \| head`, `rg X; echo Y` |
| `cargo check *` | `cargo check`, `cargo check --all-targets` |

**Выход:** таблица + вывод: «prefix-match по строке», «токенный матч», или «что-то иное».
**Куда:** `docs/analysis/rights-matching-<date>.md`, ссылка — в `dispatch-loop.md`.

### 1.2. Правило «узких команд» (до research — временное)

**Файл:** `dispatch-loop.md`, раздел «Hard rules».
**Текст:**

> Команды — одиночные, без `;`, `|`, `>`, `2>`, `&&`. Составные конвейеры не матчатся allow-паттернами и отклоняются движком прав. Если команда отклонена — сузить до ближайшего allow-паттерна. Если сужение невозможно — `surface_to_user`.

**Следствие:** это правило — для всех ролей, а не только `lead`. Нормализует A3/A4 из T-11 и F4 из Run 3.

### 1.3. Нормализация allow-листов (по результатам research)

**Кандидаты (по результатам 1.1):**
- `lead`: добавить `git ls-remote *`, `git diff --stat *`, `git log --oneline *`.
- `auditor`: заменить `rg *` на узкие формы, если после research видно, что `rg *` матчит только простые случаи.
- `validator`: проверить `git diff -- *` (в Run 3 отклонён).

**Правило «автопроверки»:** `auditor` — регулярный пункт «списки команд `review.md` ↔ фронтматтеры ролей» (это закрывает В1 из T-11, потеряно в меморандумах W6).

## 2. Mail и memory (структурное)

**Предлагаю (решение владельца):**

**Файлы:** `.opencode/.gitignore`, `AGENTS.md` §Память и почта, `git-workflow.md`, `dispatch-loop.md` (F9-сверка).

### 2.2. Разделить memory и working state

**Проблема.** Сейчас `memory/<role>.md` смешивает «чекпойнт текущей задачи» и «накопленный опыт роли». После T-03 `coder.md` будет говорить «current focus: T-03» и запутает при T-04.

**Предлагаю:**
- **Working state** — `state/current/*.yaml` (уже работает). Авторитет — `receipts.yaml`.
- **Role memory** — `memory/<role>.md`: только «что я знаю о своей роли» — паттерны, грабли, ссылки. Без задач.
- **Правило:** при взятии новой задачи роль читает `state` + mail, **не** memory как «где я остановился».

**Файлы:** `AGENTS.md` §Память и почта, `memory/*` (переписать шаблон), `analyst.md`.

### 2.3. Mail — cap и структура

**Проблема.** `T-XX.md` растёт по итерациям (в Run 3 — 10+ записей).

**Предлагаю:**
- Секции `## iteration N` — обязательны.
- При размере > ~150 строк `analyst` заводит `T-XX-rN.md` со ссылкой из основного.

### 8.1. Политика mail/memory (вопрос §7.1) — оставить текущую: оба трекаются

**Поправка предпосылки §2.1.** «D39 объявил их вне git» — неверно: вне git
только `state/`. Действующая политика (с T-11/v2.1) — mail и memory трекаются
как рабочие данные: `AGENTS.md` §Память и почта («живут в git»),
`git-workflow.md` («входят в коммит задачи по решению `lead`»),
`.opencode/.gitignore` (только `state/` + node-файлы). `ecebdee` не применял
`-f`: 7 путей почты/памяти были обычными `M`-файлами и видны в
`git status --porcelain` — сверка F9 работает и на них (именно так был пойман
пропуск `docs-writer.md`).

**Решение:**
1. Политику не менять (mail + memory в git, `state/` игнорируется).
2. §2.2 принять целиком (разделение «знание роли» ↔ рабочее состояние) — это
   снимает реальную проблему устаревших чекпойнтов; на F9 не влияет.
3. Вариант «memory игнорировать» — отклонить: противоречит v2.1, требует
   `git rm --cached`, теряет знание ролей при клоне; выгода (меньше шума) уже
   достигается §2.2 + `clean-logs`.

### 8.2. Scope-порог (вопрос §7.2) — узкий + триггер частичного покрытия

Чистый узкий (п. 3.3) теряет кейс, который T-11/T-03/memo-1 фиксировали как
долг C1; чистый широкий (memo-1) ловит всё подряд. Формула:

> **Scope-решение** (→ Q/D через `migrator` до исполнения; при обнаружении
> после — задним числом, со ссылкой на задачу) — когда `analyst`:
> **(а)** явно отверг альтернативу, допустимую каноном, **или**
> **(б)** оставил канонический сценарий/требование частично покрытым, если это
> не оговорено в карточке/источнике.
>
> **Унаследованные границы** (ссылочные, покрытие полное) —
> `inherited_boundaries: [Qn, Dn]` в досье, без Q/D.

T-03 → случай (б) → Q45/D40 (memo-1 §5.1) сохранить, переформулировав как
фиксацию частичного покрытия (не как «широкий порог»).
