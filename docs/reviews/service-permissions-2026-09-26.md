# Приёмка: права shell и инструкции о технических проблемах (service-permissions)

**Проверка:** (А) снимает ли добавленный шаблон `git diff -- *` / `git status -- *`
прежний отказ на `-- .opencode/…`; (Б) адресная приёмка изменения прав и
инструкций: узкие шаблоны, валидный YAML, отсутствие изменений кода/фич.
**Версия:** HEAD `2706f4c chore: git-workflow — служебный коммит очистки логов`
+ рабочее дерево; снимок 2026-09-26.
**Вердикт:** принято с замечаниями (P2 — заявленный эффект прав не подтверждён;
P3 — дублирование нормы о технических проблемах).

## Находки

**P1:** — критичных проблем нет.

**P2:** `.opencode/agents/validator.md:25` (`git diff -- *`) — заявленный эффект
не подтверждён: в проверенном состоянии `git diff -- .opencode/…` по-прежнему
отклоняется. Факты (проба А):
`git diff -- .opencode/rules/git-workflow.md`, `git diff -- .opencode/agents/git.md`,
`git status --porcelain -- .opencode` → `permission.rejected`; при этом
`git diff -- docs`, `git diff -- docs/README.md`, `git status --porcelain -- docs`,
`git diff -- src`, `git diff -- Cargo.toml` → выполнены; `git diff -- .github`
(скрытый путь) → отклонена. То есть отказ избирателен по признаку **`--` +
скрытый путь**, а не по отсутствию строки-шаблона: старый `git diff *` уже
пропускал `-- docs`. Последствие: приёмка сервисной зоны по-прежнему не может
адресно диффить `.opencode/…` через `--`; добавленный шаблон может дать ложную
уверенность, что проблема снята. Правка/шаги: выполнить `opencode reload` и
повторить три команды (А); если отказ сохранится — признать `-- *`-шаблоны
нерешающими и опираться на форму без `--` (`git diff .opencode/…` — выполняется),
закрепив её в инструкции; при необходимости — уточнить у владельца поведение
guard'а скрытых путей.

**P3:** `.opencode/agents/validator.md:108`, `.opencode/agents/auditor.md:124`,
`.opencode/agents/git.md:96` — норма о технических проблемах почти дословно
повторяет `.opencode/rules/review.md:90`. Это ровно тот случай «методика
продублирована в промпте и `rules`», который сам `auditor.md` (§Дубли и
противоречия) считает находкой. Последствие: дрейф формулировок и лишние
токены промпта. Правка: в ролях — короткая ссылка на `review.md`
(«Технические проблемы»), детали — в правиле (в `git.md` оставить только
git-специфику: состояние, запрет частичного завершения, листинг `rg --files`).

| 1 | `git diff -- .opencode/rules/git-workflow.md` | **отклонена** (`permission.rejected`) | ранее отклонялась — и сейчас |
| 2 | `git status --porcelain -- .opencode` | **отклонена** | то же |

Дополнительные пробы (локализация): `git diff -- docs`, `git diff -- docs/README.md`,
`git status --porcelain -- docs` — **выполнены**; `git diff -- .github` —
**отклонена**; `git diff -- src`, `git diff -- Cargo.toml` — **выполнены**;

**Вывод:** отказ **не снят** в проверенном состоянии. Признак — отдельный запрет
`--` + скрытый путь (`docs`/`src`/`Cargo.toml` после `--` проходят, `.opencode`/
`.github` — нет). Причина однозначно не установлена: либо права не перечитаны
без `opencode reload`, либо действует guard скрытых путей, который строковый
шаблон `git diff -- *` не побеждает. Обязательна повторная проба после reload.
