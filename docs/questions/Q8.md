# Q8: Отсутствующее поле: ошибка или `0`?

- **Статус:** resolved by [D21](../decisions/D21-core-semantics-v01.md)
- **Дата:** 2026-09-24
- **Приоритет:** 🔴 блокер — без решения движок подставлял отсутствующему полю
  `0.0`, из-за чего условие `< 21` срабатывало ложно (риск ложных отказов);
  решение меняет сигнатуру исполнения на
  `evaluate_rule -> Result<Explanation, EvalError>` и определяет поведение
  REST/MCP на ошибке

## Контекст

`errors.feature`, `test_draft.feature`, `explain_full.feature`, `batch.feature`
ожидают ошибку «Неизвестное поле». При этом `evaluate_rule` (`src/core.rs`)
подставлял для отсутствующего поля `0.0`, из-за чего условие `< 21` для
отсутствующего поля **срабатывало** ложно. `AGENTS.md` на тот момент фиксировал
текущее поведение (подстановку `0`) как особенность движка.

## Вопрос

Какое поведение канонично для v0.1 — ошибка при отсутствии поля или подстановка
`0`?

## Варианты

- (а) строго — ошибка при отсутствии поля;
- (б) мягко — `0`, но с предупреждением в объяснении;
- (в) явный `null`/`unknown`.

## Рекомендация

Вариант (а) — для `check.test` и REST, потому что иначе возможны ложные отказы;
ложные срабатывания опаснее падения.

**Обновить:** `core.rs::evaluate_rule`, `errors.feature`, фичи с этим ожиданием,
`AGENTS.md`.

## Итог

**Решение (2026-09-24):** вариант **(а) — строгая ошибка**. Разделение состояний
«нет параметра» и «есть параметр, но пустой» плановое (v0.2+, вместе со строгой
типизацией), но это не вопрос MVP.

- `core.rs`: `evaluate_rule` возвращает `Result<Explanation, EvalError>`;
  `EvalError::UnknownField(поле)` с русским сообщением «Неизвестное поле: …»
  (тексты согласованы с фичами, см. также [Q11](Q11.md)).
- `rest.rs`: ошибка исполнения → HTTP 422 `{ "error": "Неизвестное поле: …" }`.
- `mcp.rs::test`: ошибка исполнения → ошибка инструмента MCP.
- Фичи (`errors.feature`, `test_draft.feature`, `explain_full.feature`,
  `batch.feature`, `inline_execution.feature`) уже описывали строгое поведение —
  код приведён в соответствие, изменений в фичах не потребовалось.
- Тесты: `core::tests::missing_field_is_strict_error_q8`,
  `missing_field_does_not_trigger_false_positive_q8`.

Полный контекст решения, следствия, сверка с кодом и отклонённые альтернативы —
в [D21](../decisions/D21-core-semantics-v01.md); краткий канон —
`SPECIFICATION.md` §10, решение №21.
