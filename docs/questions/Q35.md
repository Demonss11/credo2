## Контекст

`notebook_ui.feature` создаёт `rules/` и `README.md` (после Q34/Q37 — без
`tables/` и `tests/`); содержание README и шаблона правила нигде не было
задано. Шаблон с плейсхолдерами (вроде `Поле < Значение`) regex-парсер v0.1
сразу пометил бы красной диагностикой, а README мог бы продублировать
файл-пример.

## Вопрос

Что именно создаёт новый workspace и какой шаблон получает новое правило,
чтобы он сразу парсился грамматикой v0.1?

## Варианты

- (а) оставить шаблон и README без описания (как было);
- (б) зафиксировать шаблон: файл-пример правила в workspace и парсящийся
  шаблон нового правила; `.gitignore` — по Q34/Q19.

## Рекомендация

Зафиксировать шаблон: файл-пример правила (`rules/Пример.dar`) и парсящийся
шаблон нового правила; `.gitignore` для `.credo/` и `.dar-notebook/` уже
добавлен по Q19/Q34. Обновить `notebook_ui.feature`, `file_management.feature`,
`SPECIFICATION.md` §4.3.

## Итог

**Решение (2026-09-26):**

1. **Новый workspace** создаёт: `rules/`, `rules/Пример.dar` (канонический
   пример из [`GRAMMAR.md`](../GRAMMAR.md) §1), `README.md` (структура, пример,
   шаги «создать → выполнить → опубликовать») и `.gitignore` с записями
   `.credo/` и `.dar-notebook/` ([Q19](Q19.md)). README ссылается на
   файл-пример, а не дублирует его.
2. **«Создать правило»** создаёт файл `rules/{Имя}.dar` с **парсящимся**
   шаблоном (никаких плейсхолдеров вроде `Поле < Значение` — regex-парсер v0.1
   сразу дал бы красную диагностику). Имя правила в шаблоне = имя файла; имя
   проверяется по грамматике v0.1 (буквы/цифры/`_`, включая кириллицу,
   [`GRAMMAR.md`](../GRAMMAR.md) §1).

   Канонический шаблон (`{Имя}` подставляется из диалога):

   ```dar
   // Новое правило: отредактируйте условие и решение
   Правило {Имя} {
     Если (Клиент.Возраст < 21) {
       Решение = Отказ;
       Причина = "Причина отказа";
     }
   }
   ```
3. **Черновик при создании файла не создаётся** — он появляется при
   сохранении/тестировании (draft-first, [Q33](Q33.md)); кнопка «Выполнить»
   активируется после появления черновика.
4. Шаблон согласован с [`GRAMMAR.md`](../GRAMMAR.md) v0.1: одно сравнение,
   `Решение = …;`, `Причина` — строка; допускается комментарий `//`.

- **Следствие:** `notebook_ui.feature` и `file_management.feature` уточнены
  (новых сценариев нет — шаги внутри существующих), `SPECIFICATION.md` §4.3
  дополнен деревом и заметкой; число сценариев не менялось (актуальные числа —
  в `features/README.md`).
