## Контекст

`lsp.feature` требовал подсказок `Клиент.Возраст`, `Клиент.Доход` **с типом
поля**; откуда берутся схемы полей и словари решений, ни `SPECIFICATION.md`, ни
фичи не говорили. Каталог `tables/` упоминался в SPEC §4.3 и
`notebook_ui.feature`, но формат таблиц не был определён, а
[`GRAMMAR.md`](../GRAMMAR.md) синтаксиса таблиц не вводил.

## Вопрос

Источник схемы полей для completion/hover: файл `tables/`, контракт
опубликованных проверок или конфиг workspace?

## Варианты

- (а) не подсказывать поля в MVP (только ключевые слова), при возврате — ввести
  `tables/` с форматом;
- (б) брать схему из файлов `tables/`;
- (в) брать схему из БД (пользовательские и системные таблицы).

## Рекомендация

Для MVP — не подсказывать поля (только ключевые слова); схему полей и словари
вести не в `.dar`-файлах, а в БД.

## Итог

**Решение (2026-09-26):** источник схемы полей и словарей — **БД**; каталог
`tables/` полностью исключён.

1. **Архитектурный источник схемы полей и словарей — БД** (пользовательские и
   системные таблицы). В MVP БД = `HashMap`, явной схемы нет. Векторная БД —
   отложена (после MVP).
2. **Каталог `tables/` — рудимент, полностью исключается:** данные приходят из
   БД, а не из `.dar`-файлов таблиц. Убран из `SPECIFICATION.md` §4.3,
   `notebook_ui.feature`, `lsp.feature`; синтаксис таблиц в `GRAMMAR.md` не
   вводится.
3. **Автодополнение MVP — два источника:** ключевые слова языка (`Правило`,
   `Если`, `Решение`, `Причина` — статический список из `GRAMMAR.md`) и
   эвристика по открытым файлам (все слова с точкой, например
   `Клиент.Возраст`, встреченные в тексте).
4. **Типы полей в MVP не подсказываются** (явной схемы нет). Целевая
   траектория — строгая статическая типизация; схема колонок — из БД
   ([Q9](Q9.md): в MVP типы проверяются на исполнении).
5. **Словарь решений** для автодополнения `Решение = ` — системная таблица
   решений банка в БД (пользователь расширяет свободно, набор не ограничен);
   в MVP — демо-конфиг, имитирующий эту таблицу; фиксированный набор в коде
   ядра **не хардкодится**.
6. **Векторная БД — отложена (после MVP).** Абстракция источника данных
   (trait) не закладывается; `evaluate_rule` работает с `HashMap` напрямую.
   Переход на БД — отдельная задача.

- **Следствие для кода:** правок не требуется — автодополнение — задача
  LSP/`lsp-dar` (Фаза 2, вне прототипа `credo2`); каталог `tables/` в коде не
  используется.
- **Обновлено (зона `docs-writer`):** `features/lsp.feature` (источники
  автодополнения, без типов полей, словарь решений — демо-конфиг),

  (заметки, строки); `SPECIFICATION.md` §4.3 и §10 (решение №33 — D-ссылка,
  2026-09-29); `DECISIONS.md` (ADR-002: БД как источник данных).
