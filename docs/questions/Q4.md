## Контекст

Фичи языка описывают ключевое слово `Приоритет: 100;`, которого прототип `credo2`
не поддерживает. На 2026-09-24 `parser.feature` (сценарий 2), `execution.feature`,
`explain.feature`, `editor.feature`, `lsp.feature` используют `Приоритет: 100;`;
`client_explanation.feature` требует сортировку причин «по приоритету правил»;
`features/README.md` (заметка 10) признаёт расхождение. Нужно решить, входит ли
`Приоритет` в MVP или убирается из фич.

## Вопрос

Реализуем `Приоритет` в MVP или убираем из фич?

## Варианты

- (а) реализовать `Приоритет` в MVP (парсер, исполнение, объяснение, LSP);
- (б) убрать `Приоритет` из фич MVP и вернуть вместе с конвейерами.

## Рекомендация

Если конвейер из нескольких правил не в MVP (см. Q38), убрать `Приоритет` из фич
MVP и вернуть вместе с конвейерами.

**Обновить:** все фичи с `Приоритет`, `SPECIFICATION.md` §7 (нумерация на
2026-09-24; сейчас — §10, решение №17).

## Итог

**Решение (2026-09-24):** `Приоритет` убран из MVP — ключевое слово не входит в
язык v0.1 ([`GRAMMAR.md`](../GRAMMAR.md) §4). В v0.1 одно правило = один файл
(SPEC §10 п. 14), конвейеров нет (Q36), поэтому конфликтующих правил не возникает
и порядок применения не требуется. Реализация вернётся в v0.2 вместе с
конвейерами. Фичи, использующие `Приоритет: 100;` (`parser.feature`,
`execution.feature`, `explain.feature`, `editor.feature`, `lsp.feature`,
`client_explanation.feature`), остаются целевым состоянием до переноса синтаксиса
в v0.2.

> **Примечание (2026-09-29):** архивный список фич устарел — фактически
> `Приоритет` есть в [`parser.feature`](../features/parser.feature),
> [`execution.feature`](../features/execution.feature),
> [`editor.feature`](../features/editor.feature),
