## Контекст

`inline_execution.feature` описывает кнопку «Выполнить» прямо под правилом;
`editor.feature` — диагностику из LSP; `agent_minimal.feature` — `check.test`
для черновика. LSP правила не исполняет, а источник данных для inline-запуска не
был определён (локальное ядро Tauri? MCP?).

## Вопрос

Какой движок исполняет код из редактора и как туда попадает правило
(сохранённый файл, черновик, несохранённый буфер)?

## Варианты

- (а) исполнять буфер через локальный `dar-core` (Tauri), без обязательного
  создания черновика;
- (б) единый механизм через MCP `check.test` на черновике (draft-first).

## Рекомендация

Исполнять **буфер** через локальный `dar-core` (Tauri), без обязательного
создания черновика; кнопку из `agent_minimal` не смешивать.

## Итог

**Решение (2026-09-26):** единый механизм исполнения — MCP `check.test` на
черновике; локального исполнения через Tauri `dar-core` нет; кнопка «Выполнить»
активна только при наличии черновика; draft-first (`check.create` из буфера,
файл `rules/{name}.dar` материализуется при публикации, Q12); опубликованная
версия — `check.run` (без черновика).

Следствие для кода: `check.run` в текущем `credo2` отсутствует — покрыт
[T-09](../tasks/T-09-check-run/README.md); материализация `rules/{name}.dar` при
публикации — [T-08](../tasks/T-08-materialize-source-file/README.md);
`check.test` уже работает.

Полный контекст решения, следствия, сверка с кодом и отклонённые альтернативы —
в [D30](../decisions/D30-execution-mechanism.md); краткий канон —
