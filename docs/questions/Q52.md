## Контекст

Два git-уточнения Run 5:

- **F37** — `git-workflow.md` предписывал `git branch -d` → `git push origin
  --delete`; в T-12/T-13/T-04 `branch -d` стабильно отказывал из-за устаревшего
  upstream (коммит задачи в ветку не пушился), роли инвертировали порядок вручную
  (3/3).
- **F38** — наблюдалось неоднородное поведение `git -C` (`diff` «прошёл»,
  `status` отклонён); канон T-13 говорит, что `-C` не покрыт ни одним паттерном.
  Требовалась перепроверка.

Плюс открытый вопрос о месте фиксации хешей closeout.

## Вопрос

Как завершать ветку при устаревшем upstream, что с матчингом `git -C` и где
фиксируются хеши closeout?

## Варианты

- (а) **оставить канон без изменений** — лишний шаг и импровизация в каждом
  завершении ветки; неопределённость `git -C` сохраняется;
- (б) **закрепить порядок `push --delete` → `branch -d`, подтвердить поведение
  `git -C` пробой, зафиксировать место хешей**;
- (в) **разрешить `git -C`** — пробы показали однородный отказ; расширение
  allow-листов без основания отклоняется.

## Рекомендация

Вариант (б): порядок удаления соответствует 3/3 фактам; поведение `git -C`
установлено пробой 28.09.2026; хеши фиксируются в отчёте `git` и `progress.yaml`.
