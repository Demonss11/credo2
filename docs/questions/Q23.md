## Контекст

Тексты ошибок были унифицированы русским каноном (Q11), но конверт не
определён: код возвращал плоский `{"error": "<сообщение>"}` без
машиночитаемого `code`, фичи структуру не описывали. Добавление `code` и
конверта — остаток, переданный из Q11.

## Вопрос

Единый конверт ошибки и набор стабильных кодов?

## Варианты

- (а) `{"error": {"code", "message"}}` — код латиницей, текст по-русски;
- (б) плоский `{"error": "<message>"}` — без машиночитаемого кода;
- (в) `problem+json` (RFC 7807) — стандартный формат.

## Рекомендация

Конверт `{"error": {"code", "message"}}`, тексты по-русски, коды латиницей
(`not_found`, `unauthorized`).

## Итог

**Решение (2026-09-25):** единый конверт ошибки для всех ответов REST с
ненулевым статусом (401/404/409/410/422) —
`{"error": {"code": "<стабильный код>", "message": "<русский текст>"}}`.
`message` — канонический русский текст по Q11; `code` — стабильный латинский
`snake_case`-идентификатор; необязательное поле `details` в v0.1 **не
вводится** (YAGNI). Стабильные коды: `unauthorized` (401), `check_not_found` /
`version_not_found` (404), `activation_unavailable` (409), `version_deprecated`
(410), `evaluation_failed` (422). `code` стабилен без major-версии API, текст
`message` может уточняться.

Полный контекст решения, следствия, сверка с кодом и отклонённые
альтернативы — в [D25](../decisions/D25-rest-error-envelope.md); краткий
канон — `SPECIFICATION.md` §10, решение №25.
