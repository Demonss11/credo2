# Q91: C11/B2 — профиль-флаг: подготовка без включения

- **Статус:** resolved by [D94](../decisions/D94-b2-profile-flag.md)
- **Дата:** 2026-10-03
- **Приоритет:** 🟡 важно — служебная зона (T-15, фаза C, строка `C11`),
  продуктового кода v0.1 не касается
- **Связано:** [T-15](../tasks/T-15-mcp-ready-process/README.md) (фаза C, строка
  реестра `C11`; фаза E — дизайн MCP-сервера);
  [D45](D45-wave0-quality-config.md) п.3 (B2 отключён: таблица
  `B2_PREFIXES` пуста; возврат при `codemode:false`);
  [`token-guard.ts`](../../.opencode/plugins/token-guard.ts) (B1-срез активен,
  B2-таблицы пусты, черновые правила — в комментарии);
  [F28](../analysis/findings-registry.md) (закрыт D45)

## Контекст

Волна 0 (T-15, фаза A) содержала B2 — снятие ненужных роли tool-схем из
исходящего запроса в хуке `session.context` плагина
[`token-guard.ts`](../../.opencode/plugins/token-guard.ts). Решением
[D45](D45-wave0-quality-config.md) п.3 B2 **отключён**: таблица `B2_PREFIXES`
пуста, логика хука не удалена; условие возврата — **прямая экспозиция MCP**
(`codemode:false`), тогда же — ревизия правил и тест (F28). Черновые правила
префиксов сохранены комментарием в файле плагина (`:132-133`): `docs-writer`/
`git` — `rust-analyzer`/`rust_analyzer`/`credo`; `analyst` —
`rust-analyzer`/`rust_analyzer`.

Строка `C11` карточки [T-15](../tasks/T-15-mcp-ready-process/README.md) —
«B2 — условие возврата (`codemode:false`)». Подготовить B2, **не включая**,
означает: иметь готовые правила обоих профилей и способ их активировать
сменой константы, а не правкой логики, — но так, чтобы в текущем режиме
(`codemode:true`) плагин оставался no-op. Вопрос механизма выбора профиля не
решён: хранение обоих наборов и точка переключения.

## Вопрос

Каким механизмом подготовить B2 «без включения»: где хранить правила профилей
(Code Mode и MCP) и как выбирать активный набор, чтобы включение при
`codemode:false` было минимальной правкой, а текущее поведение осталось no-op?

## Варианты

- **(A) Профиль-константа в файле.** В
  [`token-guard.ts`](../../.opencode/plugins/token-guard.ts) — константа
  `B2_PROFILE ∈ "off" | "codemode" | "mcp"` (по умолчанию `"off"`); таблицы
  правил обоих профилей рядом; активная выбирается по константе; `off` —
  no-op. Смена константы перезагружается watcher'ом; тест — служебный скрипт
  `.opencode/scripts/token-guard-test.mjs` на синтетике (профили Code Mode,
  MCP и `off`).
- **(B) Runtime-выбор (storage/env).** Профиль читается в рантайме из
  `ctx.storage`/переменной окружения; переключение без правки файла.
- **(C) Оставить прозу D45.** Никакого механизма: черновые правила остаются
  комментарием; подготовка откладывается до момента включения.

## Рекомендация

Вариант **(A)** — принят владельцем 03.10.2026 (сервисная операция r16):
**константа в файле**; тест профилей — **служебный скрипт**
`.opencode/scripts/token-guard-test.mjs`. Отклонены: runtime (вариант B —
лишняя поверхность настройки в служебной зоне при одноразовом включении) и
«оставить прозу» (вариант C — подготовка не выполнена, включение потребует
правки логики). Оформлено
[D94](../decisions/D94-b2-profile-flag.md).
