# Q73: Полнота реестра задач: как гарантировать видимость всех T-XX через TRACEABILITY?

- **Статус:** resolved by [D77](../decisions/D77-tasks-visibility-completeness.md)
- **Дата:** 2026-09-30
- **Приоритет:** ⚪ оформление — документация/процесс, кода не касается
- **Связано:** [Q59](Q59.md) ([D63](../decisions/D63-journal-index-lifecycle.md) —
  единая таблица связей), [Q60](Q60.md)
  ([D64](../decisions/D64-journal-integrity-test.md) — тест целостности журнала),

  один канон)

## Контекст

Сверка 30.09.2026: в реестре [`tasks/README.md`](../tasks/README.md) — **19 задач**
(T-01…T-19), из них **18** видны в [`TRACEABILITY.md`](../TRACEABILITY.md) (колонка
«Задачи»), статусы задач совпадают с реестром и карточками. Единственная задача
без пары Q/D и невидимая в таблице — [`T-15`](../tasks/T-15-mcp-ready-process/README.md)
(реестр: «Q/D — `migrator`»; карточка: «Журнальные `Qn`/`Dn` заводит `migrator` до
старта»). Преамбула реестра
([`tasks/README.md`](../tasks/README.md)) декларирует «У каждой задачи есть поле
«Источник»; задач «из воздуха» здесь нет», однако требования **полноты
представления** — что каждая задача видна через [`TRACEABILITY.md`](../TRACEABILITY.md) —
канон не содержит. Дыра `T-15` возникла именно по этой причине.

## Вопрос

Как гарантировать, что **все** задачи реестра видны через
[`TRACEABILITY.md`](../TRACEABILITY.md) и не теряются (в т.ч. при заведении новых
`T-XX` и при сверке реестра с таблицей)?

## Варианты

- **(а) Журнал первичен:** каждая задача реестра имеет источник Q/D и присутствует
  хотя бы в одной строке [`TRACEABILITY.md`](../TRACEABILITY.md) (колонка «Задачи»);
  задача без пары — черновик, в работу не берётся, пара заводится `migrator` до
  старта; машинная проверка — дополнение `tests/docs_journal.rs` (T-18).
- **(б) Строки/секция задач без Q/D в таблице:** вести задачи в
  [`TRACEABILITY.md`](../TRACEABILITY.md) отдельно от пар Q→D.
- **(в) Точечный фикс без правил:** завести пару только для `T-15`, требование
  полноты в каноне не фиксировать.

## Рекомендация

Вариант **(а)** — решение владельца 30.09.2026; оформлено
[D77](../decisions/D77-tasks-visibility-completeness.md). Требование полноты
фиксируется в преамбуле [`tasks/README.md`](../tasks/README.md), машинная
проверка — добором в карточку [`T-18`](../tasks/T-18-docs-journal-test/README.md);
ретро-фикс дыры `T-15` — следующей записью ([Q74](Q74.md)/[D78](../decisions/D78-t15-mcp-ready-program.md)).
Дыра возникла именно в отсутствие правила (вариант (в) не защищает от повторения);
вариант (б) ломает D63 «строка = пара Q→D» и возвращает задачи без источника.
