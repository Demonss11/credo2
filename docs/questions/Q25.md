## Контекст

`client_explanation.feature` не говорит, куда обращаться (REST? MCP?), какие
поля, откуда берётся «основание — политика кредитования» и порядок причин «по
приоритету».

## Вопрос

Определить эндпоинт/инструмент и схему.

## Варианты

- (а) MCP-инструмент `check.explain_client` для v0.1, шаблон текста — из
  контракта;
- (б) REST-рендер клиентского текста;
- (в) вне MVP — сырьё (`Explanation`) отдаётся как есть, рендер — задача
  потребителя.

## Рекомендация

MCP-инструмент `check.explain_client` для v0.1, шаблон текста — из контракта.

## Итог

**Решение (2026-09-26):** клиентское объяснение — **вне MVP**, пост-MVP/v0.2.

Обоснование (зависимости сценариев):

- **шаблон и «основание — политика кредитования»** — банковский юридический
  текст; источника нет ни в `CheckContract` (`description` — техническая строка
  «Если … → …», `decisions` — только id решений), ни в SPEC; в целевом
  состоянии — БД/справочники (Q37) или расширение контракта;
- **«Заявка одобрена»** — клиентская формулировка, отображаемая из
  `decision`-id; словарь решений задаёт банк (Q10), фиксированного маппинга в
  ядре нет;
- **несколько причин и порядок по приоритету** — конвейеры и `Приоритет`, вне
  MVP (Q4/Q36);
- **потребителя в MVP нет**: оператора колл-центра в продукте нет, Notebook —
  для риск-технологов; агент в чате пересказывает `Explanation` и без
  отдельного инструмента (Q31).

Направление на v0.2 (если вернёмся): MCP-инструмент `check.explain_client` для
оператора (шаблоны и «политика» — из БД/справочников, Q37), маппинг `decision`
→ клиентская формулировка — банковский словарь (Q10), мультипричины и порядок —
конвейеры (Q4/Q36); для внешнего конвейера возможен REST-рендер — решить тогда.
«Шаблон из контракта» в текущем виде невозможен: требует расширения схемы
`CheckContract` — отдельное решение v0.2.

Следствие: в `mcp.rs`/`rest.rs` ничего не добавляется; MVP-сырьё для
клиентского текста — `Explanation` (Q42, русские `decision`/`reason`), рендер —
задача потребителя; `client_explanation.feature` остаётся целевым состоянием с
шапочным комментарием об отсрочке; число файлов и сценариев не меняется
(3 сценария, backend), меняется только статус/приоритет файла в README.

Полный контекст решения, следствия, сверка с кодом и отклонённые альтернативы —
в [D37](../decisions/D37-client-explanation-deferred.md); краткий канон —
`SPECIFICATION.md` §10, решение №37.
