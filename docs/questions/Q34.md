## Контекст

Формулировки о тестах расходились. SPEC §1.2 заявлял, что `.dar` —
одновременно и тест; §4.3 описывал каталог `tests/` с `*.тест` (принцип
code=doc); `inline_execution.feature` сохранял последние входные данные и
несколько наборов тестов в `.dar-notebook/results-cache.json`, то есть вне git.
Неясно было, где канонические тесты и можно ли их версионировать.

## Вопрос

Где живут канонические тесты и можно ли их версионировать?

## Варианты

- (а) тесты внутри `.dar` (SPEC §1.2: «`.dar` — одновременно тест»);
- (б) каталог `tests/` с `*.тест` (SPEC §4.3, принцип code=doc);
- (в) локальный кэш `.dar-notebook/results-cache.json`
  (`inline_execution.feature`) — вне git.

## Рекомендация

Для MVP — тесты в `.dar-notebook/` (локально), формат `tests/*.тест` не
вводить; принцип «тест в файле» перенести в целевую версию. Обновить
`SPECIFICATION.md` §1.2/§4.3 и `inline_execution.feature`.

## Итог

**Решение (2026-09-26):**

1. **В MVP тесты живут только в локальном кэше Notebook:**
   `.dar-notebook/results-cache.json`. Они не версионируются в git.
2. **«Быстрые прогоны»** (ввёл JSON в UI → нажал «Выполнить») сохраняются в
   кэш для удобства повторного запуска. Это черновики тестов.
3. **Канонические файлы тестов** (формат `tests/*.тест`, принцип code=doc) —
   вне MVP, возвращаются в v0.2.
4. **Готовность правила к публикации** проверяется не наличием файла теста, а
   фактом успешного `check.test` на черновике ([Q16](Q16.md)): сервер хранит
   `last_test_checksum` и `tested_at`, публикация без успешного теста
   отклоняется.
5. **`.dar-notebook/` — в `.gitignore`**, не попадает в
   workspace-репозиторий.

- **Следствие для кода:** учёт `last_test_checksum`/`tested_at` и проверка при
  публикации в `credo2` — отдельная задача
  [T-02](../tasks/T-02-test-gate/README.md); в этих правках код не менялся.
- **Обновлено:** `features/inline_execution.feature` (кэш
  `.dar-notebook/results-cache.json`, вне git), `features/publish.feature`
  (`last_test_checksum`/`tested_at`, гейт публикации),
  `features/test_draft.feature` (метка тестирования),
  `features/notebook_ui.feature` (структура workspace без `tests/`,
  `.gitignore`), `features/README.md` (счётчики, заметки),
  `SPECIFICATION.md` §1.2/§4.2/§4.3 и §10 (решение №32);
  `OPEN_QUESTIONS.md` [Q16](Q16.md) (закрыт в рамках Q34).
