# Q82: «Сверка с кодом» D-файлов — датированный снимок или живой канон для запретов D64/D65?

- **Статус:** resolved by [D85](../decisions/D85-sverka-snapshot-scope.md)
- **Дата:** 2026-10-02
- **Приоритет:** 🟡 важно — процессная гигиена журнала, кода не касается
- **Связано:** [Q60](Q60.md)/[D64](../decisions/D64-journal-integrity-test.md)
  (тест целостности, запреты п.1.7–1.8),
  [Q61](Q61.md)/[D65](../decisions/D65-reference-policy.md) (политика ссылок,
  «время жизни адреса», `F47`),
  [T-18](../tasks/T-18-docs-journal-test/README.md) (карточка, §Примечания),
  [D82](../decisions/D82-traceability-lifecycle-waves.md) (жизненный цикл)

## Контекст

Тест [`tests/docs_journal.rs`](../../tests/docs_journal.rs) (задача
[T-18](../tasks/T-18-docs-journal-test/README.md)) проверяет запреты
[D64](../decisions/D64-journal-integrity-test.md) п.1.7–1.8 /
[D65](../decisions/D65-reference-policy.md) п.4. Функция `live_text`
(строки 641–654) вырезает секцию `## Сверка с кодом` из `D`-файла перед
проверкой **номеров строк** («датированные свидетельства — аналог исторических
зон», комментарий теста; вызов — только в
`no_line_number_addresses_in_live_journal`). Адресный гейт
`no_addresses_to_removable_or_session_data` работает по **сырому** тексту
(`removable_addresses`, строки 754–812): исключения для «Сверки с кодом» там нет.

Карточка [T-18](../tasks/T-18-docs-journal-test/README.md) §Примечания называет
историческими зонами только `docs/reviews/**` и `docs/analysis/**`; «Сверку с
кодом» (секцию канонического `docs/decisions/**`) не называет.
[D64](../decisions/D64-journal-integrity-test.md) п.1.7 запрещает номера строк
«вне исторических зон», п.1.8 (адреса) зон не оговаривает;
[D65](../decisions/D65-reference-policy.md) п.3/п.4 прямого ответа о секции
«Сверка с кодом» не дают. Итог — **частичное покрытие канона, не оговорённое
карточкой**: тест де-факто вводит третью зону-снимок (секцию «Сверка с кодом»
`D`-файла), но только для номеров строк. Обнаружено при исполнении T-18
(`tester` остановлен лимитом шагов до прогона; факты — память `tester`,
досье аналитика (зона `docs/analysis/**`), участок №3).

## Вопрос

Считать ли секцию «Сверка с кодом» `D`-файла датированным снимком, исключённым
из запретов D64/D65 (подтвердить carve-out теста), или живым каноном, к
которому применяются запреты полностью (ужесточить гейт и вычистить секции)?

## Варианты

- **(а) Подтвердить carve-out как снимок для обоих гейтов.** «Сверка с кодом»
  — датированное свидетельство; номера строк и адреса в ней не гейтятся.
  Требует правки теста: применить `live_text` и в адресном гейте. Расширяет
  «исторические зоны» D64 на секцию канонических `docs/decisions/**` и оставляет
  в каноне адреса на удаляемые данные (`F47`) — противоречит D65 п.4.
- **(б) Подтвердить carve-out для номеров строк, адреса — строго.** Номера строк
  в «Сверке» — снимок (датированное свидетельство; расширение «исторических
  зон» D64 п.1.7), адреса на удаляемые/сессионные данные не допускаются и в
  «Сверке»: D64 п.1.8 / D65 п.4 строги (F47 — «время жизни адреса», а не
  устаревание навигации). Совпадает с реализацией теста; требует снять
  существующие адреса-нарушители в `D`-файлах.
- **(в) Ужесточить полностью:** убрать `live_text`, гейтить и номера строк внутри
  «Сверки». Требует вычистить ~15 номерных адресов в 9 `D`-файлах
  (D14, D22, D30, D35, D54, D56, D57, D58, D60) — удаление датированного
  провенанса при нулевой продуктовой пользе.

## Рекомендация

Вариант **(б)** — минимальный, не противоречит канону и совпадает с уже
реализованным тестом: «Сверка с кодом» — датированный снимок для **номеров
строк** (запрет D64 п.1.7 действует «вне исторических зон», секция приравнена к
снимку по природе — датированное свидетельство); **адреса** на удаляемые/
сессионные данные остаются строгими (D64 п.1.8/D65 п.4), существующие
нарушители снимаются. Оформлено [D85](../decisions/D85-sverka-snapshot-scope.md).
