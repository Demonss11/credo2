# Q74: T-15: как оформляем программу «процесс, готовый к MCP»?

- **Статус:** resolved by [D78](../decisions/D78-t15-mcp-ready-program.md)

- **Приоритет:** 🟡 важно — P1-программа процесса; без пары задача невидима (D77)
  и не стартует по своему критерию
- **Связано:** карточка [`T-15`](../tasks/T-15-mcp-ready-process/README.md), записка

## Контекст

Карточка [`T-15`](../tasks/T-15-mcp-ready-process/README.md) («Процесс, готовый к
MCP») требует в критерии готовности: «журнальные Q/D заведены и связаны с
карточкой», но до сих пор пары не было — «Q/D заводит `migrator` до старта».
Часть программы уже исполнена: волны W0 (A) — токен-гигиена, B0 — инструментальная
обвязка пилотов, C13 — хвостовые записи пакета (F43); входы — записка
[`mcp-ready-process.md`](../analysis/mcp-ready-process.md) (фазы A–G),
[D45](../decisions/D45-wave0-quality-config.md), D42–D48. Правило видимости задач —
[Q73](Q73.md)/[D77](../decisions/D77-tasks-visibility-completeness.md).

## Вопрос

Как журнально оформить программу [`T-15`](../tasks/T-15-mcp-ready-process/README.md) —
**одной парой** на всю программу или **по паре на каждую фазу** (A–G)?

## Варианты

- **(а) Одна программная пара** Q74/D78: программа ведётся по записке (фазы A–G);
  фазовые решения — отдельными `Dn` по ходу исполнения (прецедент — D42–D48 для
  цикла агентов, D38/D39).
- **(б) Пара на каждую фазу сейчас:** завести Q/D под каждую из фаз A–G
  до их исполнения.
- **(в) Не оформлять:** оставить [`T-15`](../tasks/T-15-mcp-ready-process/README.md)
  без пары Q/D.

## Рекомендация

Вариант **(а)** — решение владельца 30.09.2026; оформлено
[D78](../decisions/D78-t15-mcp-ready-program.md). Одна программная пара делает
задачу видимой (требование [D77](../decisions/D77-tasks-visibility-completeness.md)),
фазовые решения будут приниматься по мере исполнения (прецедент D42–D48).
Вариант (б) избыточен — большинство фаз ещё ⬜ и их решения не приняты; вариант
(в) нарушает правило D77 и критерий готовности карточки.
