# Q48: Как `auditor` фиксирует отчёт в ленте задачи, если права разрешают запись только в свою память?

- **Статус:** resolved by [D43](../decisions/D43-auditor-mail.md)
- **Дата:** 2026-09-28
- **Приоритет:** 🟡 важно
- **Связано:** [D43](../decisions/D43-auditor-mail.md);
  [`auditor.md`](../../.opencode/agents/auditor.md);
  [`AGENTS.md`](../../AGENTS.md) §«Рабочая группа агентов»;
  [`review.md`](../../.opencode/rules/review.md)
- **Источник:** Run 5 (T-04) — P2 аудита: `auditor` получил
  `permission.rejected` на `edit .opencode/mail/T-04.md`

## Контекст

При аудите T-04 (Run 5) роль `auditor` не смогла дописать отчёт в ленту задачи:
её фронтматтер разрешал `edit` только `.opencode/memory/auditor.md`. Отчёт был
внесён релеем `lead`. По канону ([`AGENTS.md`](../../AGENTS.md) §«Память и
почта») роли дописывают отчёт в ленту задачи **сами** — то есть «инструкция ↔
права» разошлись (находка F16).

## Вопрос

Как `auditor` фиксирует отчёт в ленте задачи, если права разрешают запись только
в свою память?

## Варианты

- (а) **оставить релей `lead`** — канон говорит «роль дописывает сама»; релей
  расходится с каноном и искажает авторство/независимость отчёта;
- (б) **право `edit` на ленту задачи** — `edit .opencode/mail/**` (append в ленту
  задачи; вне задачи — в служебную), синхронизация тела роли и `AGENTS.md`;
- (в) **отдельный артефакт-отчёт аудита** вне ленты — дублирует ленту, ломает
  единый формат почты задачи.

## Рекомендация

Вариант (б): он приводит права в соответствие с уже принятой нормой
«роль дописывает отчёт в ленту сама» и минимален (одна строка прав + синхронизация
двух текстов).
