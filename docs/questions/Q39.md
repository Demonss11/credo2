## Контекст

[`SPECIFICATION.md`](../SPECIFICATION.md) §10 п. 6 фиксировал «Нет fallback
при падении LSP; перезапуск sidecar», а
[`lsp_notebook.feature`](../features/lsp_notebook.feature) обещал
автоперезапуск + уведомление + «состояние открытых файлов восстанавливается».
Было неясно, что значит «нет fallback» (есть ли второй движок в UI) и что
именно восстанавливается — диагностики, позиция курсора, несохранённые правки.

## Вопрос

Что значит «нет fallback» и что восстанавливается при падении LSP
(диагностики? позиция курсора?).

## Варианты

- (а) встроенный fallback в UI (второй движок диагностики без LSP);
- (б) второго движка нет: при недоступности LSP редактор работает как обычный
  текстовый, после перезапуска восстанавливается серверная сессия.

## Рекомендация

Переформулировать §10 п. 6: «перезапуск и повторная синхронизация открытых
документов; деградация — без подсветки».

## Итог

**Решение (2026-09-26):** принимается рекомендация с уточнениями.

1. **«Нет fallback» — нет второго движка.** При недоступности sidecar функции
   LSP (диагностика, автодополнение, семантическая подсветка) недоступны;
   редактор работает как обычный текстовый. Встроенной в UI альтернативы нет:
   `dar-core` доступен только через LSP (согласуется с Q33 — локального
   исполнения в UI нет).
2. **Восстанавливается серверная сессия, а не «состояние» файлов.** Буферы,
   курсор, скролл и undo — клиентские (CodeMirror), падение sidecar их не
   теряет. После перезапуска клиент выполняет `initialize` и повторный
   `didOpen` по всем открытым документам с текущим текстом (включая
   несохранённые правки); сервер заново публикует диагностику.
3. **Ограничение автоперезапуска.** Автопопытки подряд ограничены (канон —
   три); после их исчерпания автоперезапуск прекращается, пользователь видит
   уведомление «Сервер языка недоступен» и может перезапустить сервер вручную.
   Бесконечный цикл падений исключён.
4. **Деградация не блокирует работу.** Во время недоступности LSP
   редактирование и сохранение продолжаются, буферы и несохранённые правки
   сохраняются; выполнение правила (`check.test` через MCP, Q33) от LSP не
   зависит.

- **Следствие для кода:** правок не требуется — `lsp-dar` и Notebook не
  реализованы (Фаза 2–3, [Q38](Q38.md)); LSP-поведение — вне кода прототипа
  `credo2`.
