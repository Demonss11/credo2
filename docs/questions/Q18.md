## Контекст

`deferred.feature` фиксировала лексикографическое сравнение идентификаторов
pre-release (`rc2` vs `rc10`) как текущее; `core.rs` уже сравнивал их численно.
`semver.feature` ожидала `1.2.3+build` как валидную версию, а
`storage_paths.feature` и код убирали build из пути. Формулировки расходились и
не отвечали на вопрос о дубликате `1.0.0+a`/`1.0.0+b`.

## Вопрос

Числовое сравнение pre-release — норматив? Что с двумя публикациями `1.0.0+a`
и `1.0.0+b` (дубликат по базе)?

## Варианты

- (а) лексикографическое сравнение идентификаторов (как в `deferred.feature`);
- (б) семантика semver 2.0.0: числовые идентификаторы численно; build не входит
  в идентичность, отбрасывается при записи, повтор публикации базы запрещён (как
  в коде).

## Рекомендация

Принять (б): числовое сравнение как в semver; build отбрасывать и явно
запрещать повторную публикацию базы.

## Итог

**Решение (2026-09-26):** принимается рекомендация.

1. **Сравнение версий — по семантике semver** (semver 2.0.0): pre-release
   ниже release; идентификаторы сравниваются слева направо, числовые — как
   числа (`1.0.0-rc2` < `1.0.0-rc10`), буквенно-цифровые — лексикографически;
   ошибка парсинга при сравнении — ошибка, а не `0.0.0`.
2. **Build-метаданные не входят в идентичность версии:** `+build` сохраняется
   при парсинге (`Display`), но `PartialEq`/`Ord` его игнорируют
   (`1.0.0+a == 1.0.0+b`).
3. **При записи в реестр build отбрасывается** (`as_storage`): путь и
   `meta.version`/`contract.version` — без `+build`
   (`checks/{name}/{X}/{Y}/{Z}/`).
4. **Повторная публикация базы с другим build запрещена:** `1.0.0+a` и
   `1.0.0+b` — один слот версии `1.0.0`; вторая публикация отклоняется как
   обычный дубль — `publish_failed` (§4.5, Q29), сообщение «версия уже
   существует».
5. **Публикация pre-release остаётся вне MVP** (Q32 п. 8): сравнение из п. 1
   нормативно уже сейчас, публикация `1.0.0-rc.1` вернётся в v0.2 (вариант
   пути — `checks/{name}/{X}/{Y}/{Z-prerelease}/`).

Полный контекст решения, следствия, сверка с кодом и отклонённые альтернативы —
в [D35](../decisions/D35-semver-v01.md); краткий канон — `SPECIFICATION.md`
§10, решение №35.
