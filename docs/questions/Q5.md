## Контекст

`features/README.md` использует ✅/🟡/⬜/⏸ (реализовано/расходится/план/
отложено), `SPECIFICATION.md` §6.2 — 🔴/🟡/🟢/⏳ (обязательные/желательные/
вау/отложенные). Один и тот же файл получает разные метки (например,
`rest_api.feature` — ✅ и 🔴). Нужно устранить мнимое противоречие «✅ vs 🔴»
и определить, где живёт канон меток.

## Вопрос

Какая система меток одна? Что означает «сделано»?

## Итог

**Решение (2026-09-24):** приняты **две независимые оси** с одним каноном —
[`features/README.md`](../features/README.md):

- **статус реализации** (✅/🟡/⬜/⏸) — что уже работает в `credo2`;
- **приоритет MVP** (🔴/🟡/🟢/⏳) — что и когда нужно демо.

У каждого файла в сводных таблицах README теперь обе колонки.
[`SPECIFICATION.md`](../SPECIFICATION.md) §6.1 удалил дублирующую таблицу и
ссылается на README, §6.2 оставляет только смысл уровней и привязку к фазам.

- **«Сделано» (✅):** поведение реализовано, сценарии не противоречат коду;
  backend покрыт автотестом либо явно помечен «ручной прогон» (см.
  «Соответствие коду» в README), UI проверяется вручную по сценарию.
  🟡 — расхождение зафиксировано в `OPEN_QUESTIONS.md`; ⬜ — план; ⏸ — вне MVP.
- **Приоритеты** файлов перенесены из SPEC §6.1; файлы, которых там не было,
  размечены по здравому смыслу: `lexer` ⏳; `parser`, `execution`, `explain`,
  `errors`, `semver`, `storage_paths`, `manifest`, `mcp_tools`, `testing`,
  `lsp_notebook` 🔴; `immutability`, `manifest_sync`, `deprecation` 🟡.
- **Следствие:** [Q6](Q6.md) закрыт попутно (таблица §6.1 не пересчитывается,
  а удалена).

Полный контекст решения, следствия, сверка с кодом и отклонённые альтернативы —
