# Q83: Схема состояния процесса: место и модель (F15)

- **Статус:** resolved by [D86](../decisions/D86-state-schema.md)
- **Дата:** 2026-10-02
- **Приоритет:** 🟡 важно — канон процесса (T-15), кода v0.1 не касается
- **Связано:** [Q47](Q47.md)/[D42](../decisions/D42-expect-iteration.md) —
  `iteration` только rework-раунд, участок — `progress_marker`/`resume_hint`;
  F15 в [`findings-registry.md`](../analysis/findings-registry.md) — дрейф
  `iteration`; [T-15](../tasks/T-15-mcp-ready-process/README.md) — фаза C, задача
  C1; [D78](../decisions/D78-t15-mcp-ready-program.md) — программа

## Контекст

F15 (реестр находок): `iteration` в `next_action`/`current_state` нёс номер
участка плана при `rework: 0`. Данные прогона 02.10.2026 подтвердили дрейф:
`iteration` = номер участка `1→2→3→4` при `rework=0`; раунды `-r1/-r2/-r3` при
`iteration 1`. [D42](../decisions/D42-expect-iteration.md) закрепил: `iteration`
— только rework-раунд (`rework = iteration − 1`), адрес участка —
`progress_marker`/`resume_hint`; отдельное поле участка не вводится.

Проектная записка [`mcp-ready-process.md`](../tasks/T-15-mcp-ready-process/mcp-ready-process.md)
§5 содержит схему состояния (поля артефактов, инварианты, каталог операций) как
**проект к утверждению**. Фактический формат `state/current/*.yaml` и канон
[`dispatch-loop.md`](../../.opencode/rules/dispatch-loop.md) схему в цельном виде
не фиксируют.

Развилка вынесена владельцу на гейте открытия 02.10.2026 (сервисная операция,
лента r8): место схемы и модель `iteration`/участка.

## Вопрос

Где фиксировать схему состояния процесса (отдельный канон-файл или раздел
`dispatch-loop.md`) и по какой модели адресовать `iteration`/участок — по D42
или через новое поле `section`?

## Варианты

- **(A) Модель D42 + отдельный канон-файл.** `iteration` — только rework-раунд,
  участок — `progress_marker`/`resume_hint`; схема (поля, типы, инварианты,
  писатель/читатель) — новый канон `.opencode/rules/state-schema.md`, ссылка из
  `dispatch-loop.md`, карта репозитория в `AGENTS.md`.
- **(B) Поле `section` и/или раздел в `dispatch-loop.md`.** Ввести новое поле
  адреса участка в состояние; схему разместить разделом действующего канона
  цикла.

## Рекомендация

Вариант **(A)** — принят владельцем на гейте 02.10.2026 (лента r8): модель
[D42](../decisions/D42-expect-iteration.md) без нового поля `section`; место
схемы — отдельный канон `.opencode/rules/state-schema.md` со ссылкой из
`dispatch-loop.md`. Оформлено [D86](../decisions/D86-state-schema.md).
