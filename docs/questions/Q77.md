## Контекст

Черновик владельца `.opencode/scripts/pm/mine_agents.py` (557 строк, вне git) —
постфактум-анализ агентского процесса: он читает `state/current/*`
(`progress.yaml`/`receipts.yaml`/`next_action.yaml`), но **не читает `mail/`** —
реальный event log вызовов ролей (кейс = лента `T-XX`). Известные дефекты и
несоответствия (полный список — в досье):

- очередь `next_action` лежит в ключе **`next`**, а черновик ищет
  `queue`/`actions` → `queue_length` всегда пуст;
- приёмка учитывает только `accepted`, игнорируя **`accepted_with_notes`** →
  `acceptance_rate` занижен;
- `case_id` при неизвестной задаче падает на `next_action.task` → неизвестные
  кейсы сваливаются в текущую задачу;
- `at` в `progress`/`receipts` — **дата без времени** → выводы о секундных
  задержках (`avg_delta_seconds`, `bottlenecks`) недостоверны;
- тяжёлые импорты на уровне модуля (`pandas`/`networkx`/`matplotlib`/`plotly`/
  `seaborn`) → CLI падает без viz-зависимостей; `seaborn` не нужен; `to_csv` без
  BOM ломает Excel-RU; `summary.md` не формируется; `variants` может терять
  порядок.

Зависимости черновика (pandas/networkx/matplotlib/plotly/pm4py) под **Python 3.14** —
риск отсутствия колёс. У ролей нет прав `uv` (и `node`) — инструмент принадлежит
служебной зоне; роли читают лишь готовые отчёты. Прецедент хелпера в служебной
зоне — [D75](../decisions/D75-git-lean-workflow.md) (git-хелпер + allowlist),
гигиена инструментов процесса — [D51](../decisions/D51-agent-tools-token-hygiene.md).

## Вопрос

Нужен ли и в какой форме инструмент **постфактум-анализа процесса** (DFG переходов
между ролями, варианты маршрутов, метрики приёмки/rework) агентского процесса
CREDO2 поверх `state/current/*` и `mail/`?

## Варианты

- **(а) Python uv-проект** `.opencode/scripts/pm`: пакет `src/pm_agents/`, CLI
  `pm-agents`, `pyproject.toml` + `uv.lock` (в git), `tests/` (pytest), README;
  зависимости слоями (`pyyaml` core; extra `viz`; extra `pm4py`). Решение команды
  по досье.
- **(б) Расширение `session-analysis` (Node)** — переиспользование конвенций
  готового инструмента служебной зоны.
- **(в) Оставить черновик как есть.**

## Рекомендация

Вариант **(а)** — оформлено [D81](../decisions/D81-pm-process-mining.md): uv-проект
в `.opencode/scripts/pm` со слоёными зависимостями (риск колёс Python 3.14 снят:
core без viz), `mail/` как tolerant-enrichment, приёмка с `accepted_with_notes`,
`unknown-<idx>` вместо подстановки текущей задачи, артефакты вне репозитория.
Вариант (б) отклонён: другой домен (транскрипты сессий, не state-лог) и
дублирование; вариант (в) отклонён: черновик не читает `mail`, не парсит `next`,
занижает приёмку и несёт риск колёс.
