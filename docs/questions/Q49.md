## Контекст

Run 5 выявил серию процессных расхождений канона (F17/F18/F19/F24/F25/F32/F34/
F35/F36): бриф плана противоречил канону (F17/F32); роли упирались в лимит
`steps` (F18); команда `git branch -vv` оказалась вне allowlist `git` (F19);
срезанный вывод не имел протокола для ролей (F24); правило сплита лент не
сработало (F25); бюджет чтения `analyst` упёрся в границу (F34); память `coder`
противоречила канону роли (F35); не было протокола эскалации при затыке (F36).

## Вопрос

Что делать при расхождении брифа с каноном и при затыке (права/инструмент),
каких запасов `steps` требуют роли и как работать со срезанными выводами и
растущими лентами?

## Варианты

- (а) **точечные правки по факту** — разрозненные правки канона без свода,
  повторение расхождений;
- (б) **единый пакет уточнений Run 5** — один `D` + правки `dispatch-loop.md`,
  `AGENTS.md`, ролей и `review.md`;
- (в) **ничего не менять, только реестр** — расхождения воспроизведутся, у ролей
  не будет протокола на затык.

## Рекомендация

Вариант (б): все пункты относятся к одному канону цикла диспетчера, их источник —
один прогон; точечные правки без свода плодят дрейф «инструкция ↔ права».
