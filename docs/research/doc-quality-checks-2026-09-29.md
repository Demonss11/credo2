## Вопрос

1. Чем ценен композитный doc-gate `lint → size → spell → links` и какова его цена?
2. Где наши инструменты пересекаются с планом T-18 (дубль link-check) и кто должен
   быть единым владельцем?
3. Что из комплекта: брать / адаптировать / позже / отклонить?
4. Как встроить: место, охват и исключения, лимиты, гейт, поэтапность, риски.
5. Коротко — внешние ориентиры и пилот до включения.

## Что нашли

**Подход соседа (факт, по дайджесту).** Один композитный `npm run check`
прогоняет четыре независимые проверки и останавливается на первой упавшей:
`markdownlint-cli2` (правила MD001/025/040/047; MD013/033/041/060 off) → лимит
строк на документ (дефолт 300, `MAX_DOC_LINES`/argv) → `cspell` (en+ru,
`project-words.txt`) → `markdown-link-check` (glob-цели, относительные ссылки;
`https?://`, `mailto:`, `tel:`, `^#` игнорируются, конкурентность 4). Плюс
`generate_changelog.mjs` (коммиты `[компонент] тип:`) — вне гейта.

**Чем хорош (интерпретация).** Дешёвые проверки идут раньше дорогих — быстрый
фидбек; каждая проверка изолирована и конфигурируема; конфиги лежат рядом с
инструментами, роль-владелец указана в README. Это ровно тот шаблон, который
советуют docs-as-code-гайды: «начинать с 5–8 high-impact правил», «ошибка vs
предупреждение», «локально раньше, чем CI», «в CI — только изменённые файлы»
([Docsie](https://www.docsie.io/blog/glossary/documentation-linting/),
[Fern](https://buildwithfern.com/post/docs-linting-guide)).

**Где цена.** (а) ещё один toolchain (Node+npm) рядом с Rust-DoD; (б)
исторический корпус при включении даёт лавину нарушений — нужны зоны-исключения;
(в) `project-words.txt` — вечно растущий ручной словарь (у соседа 66 строк, и там
даже «бриф/брифе», т.е. он обслуживает падежи русской прозы); (г)
`markdown-link-check` проверяет **только относительные** ссылки, то есть закрывает
ту же зону, что обещает T-18 v0.2; (д) внешние ссылки не проверяются вообще
(`ignorePatterns ^https?://`), значит «ссылки живые» — это узкое утверждение.

## Применимо к CREDO

| Тулсет | Наш аналог / план | Пересечение |
|---|---|---|
| `check-links.mjs` + `markdown-link-check` | T-18 v0.2 «полный link-check относительных ссылок» (Rust, std-only) | **дубль**: оба про относительные ссылки; у T-18 уже есть whitelist исторических зон |
| `check-doc-size.mjs` | ручной опыт 29.09: сжатие BRIEF 395→304; запрета нет | нет дубля; дополняет |
| `markdownlint-cli2` | нет; грамматику/структуру журнала проверяет T-18 (v0.1) | слабое: T-18 — про ID/таблицы, не про markdown-форму |
| `cspell` | нет | нет дубля; но тяжело для русской прозы |
| `generate_changelog.mjs` | `docs/CHANGELOG.md` — рукописный канон; конвенция коммитов `docs(Qn):`/`feat:` (D46) | конфликт, не дубль |

**Владелец link-check — один: Rust-тест T-18.** Обоснование: DoD уже
`cargo test --all` ([`AGENTS.md`](../../AGENTS.md) §Сборка), новых toolchain нет;
тест и так знает whitelist и зоны-снимки (`reviews/`, `analysis/`), а
`markdown-link-check` — относительные ссылки, найденные регулярками, т.е. **те же
данные тем же способом**. Два инструмента с одной зоной ответственности — это
дубликат канона (политика Q41). Node-скрипт как постоянный гейт — отклонить; до
закрытия T-18 v0.2 допустим разовый `git grep` из `BRIEF.md` §7 или временный
пилот-скрипт (без права быть гейтом).

## Не применимо и почему

- **Внешние ссылки.** Ни тулсет, ни T-18 их не проверяют; `markdown-link-check`
  с их конфигом игнорирует `https?://`. Не позиционировать как «нет битых
  ссылок». Если понадобится — отдельный инструмент (`lychee`, Rust, 4k★) и
  отдельное решение, не в v0.1.
- **Конфиг правил «как у них» целиком.** MD013 (длина строки) у нас осознанно
  свободная (длинные таблицы/ссылки), MD033 (инлайн HTML) — в наших доках
  встречается; MD041 (H1 первой строкой) — не для всех артефактов. Их `off`-набор
  случаен для нас.
- **Автогенерация CHANGELOG.** Пишет в канон-файл автоматически → нарушает «один
  писатель на файл» и владение `docs-writer`; наш CHANGELOG содержит решения и
  обоснования, не выводимые из subject'ов; конвенция коммитов иная (D46).
- **`--fix` в пилоте.** Правка canon-файлов линтером без ревью — вне границ
  `researcher`; и в целом это отдельное решение.

## Рекомендации

| Элемент | Вердикт | Обоснование |
|---|---|---|
| **size-check** | **Адаптировать** | Самый дешёвый и детерминированный (ms, нулевые зависимости); прямо адресует переросший BRIEF. Свой скрипт `.opencode/scripts/doc-checks/check-doc-size.mjs`; лимит — на канон, исключения списком (SPEC/CHANGELOG/индексы); принимает argv-файлы → режим «только изменённые» |
| **markdownlint** | **Адаптировать** | Узкий ruleset: MD001/025/040/047 + MD024 `siblings_only`; off: 013/033/041/060. Охват — только канон и `.opencode/agents|rules`; конфиг рядом со скриптами (`.markdownlint-cli2.jsonc` в папке инструмента, запуск с явным `--config`) |
| **cspell** | **Позже** (пилот → решение) | Польза только на латинице/техтерминах; русская проза с падежами даёт шум, словарь — вечная ручная работа. Пилот на одной зоне (`docs/decisions/**`), `--words-only --unique` для замера, решение по порогу ложных срабатываний |
| **links (markdown-link-check)** | **Отклонить** | Дубль T-18 v0.2, относительные-только, npm-зависимость, вялая поддержка (718★/14 issue). Владелец — Rust-тест; временный `git grep` из BRIEF §7 |
| **changelog-gen** | **Отклонить** | Конфликт с рукописным каноном и владением `docs-writer`; конвенция коммитов не совпадает |
| **композит/порядок** | **Брать (идею)** | «Быстрые раньше»: size → lint → (spell) — как порядок в гипотетическом `check:docs`; единый вход, exit-code |

## Архитектура внедрения

- **Место:** `.opencode/scripts/doc-checks/` (рядом с `clean-logs.mjs`,
  `agents-perms.mjs`) + конфиги там же; точка входа `check-doc-quality.mjs`
  (argv: список файлов или `--all`). Не Rust-код → D50 (cargo только при
  изменениях кода) не задет. Пакет — `.opencode/package.json` (там уже `npm ci`);
  зависимости фиксировать lock-файлом.
- **Охват (включаем):** `AGENTS.md`, `docs/*.md`, `docs/questions/**`,
  `docs/decisions/**`, `docs/tasks/**/README.md`, `docs/features/README.md`,
  `docs/README.md`, `.opencode/agents/**`, `.opencode/rules/**`.
- **Исключения (снимки/сессионное/сгенерированное):** `docs/reviews/**`,
  `docs/analysis/**`, `docs/research/**`, `docs/tasks/T-15-*/wave*.md`,
  `.opencode/mail/**`, `.opencode/memory/**`, `.opencode/state/**`, `target/`,
  `.credo/`, `.git/`. `.feature` — вне markdown-проверок (это Gherkin, не md).
- **Лимиты:** дефолт 300–350 строк; **исключения поимённо** —
  `SPECIFICATION.md` (~890), `CHANGELOG.md` (~500), индексы-сводки
  (`decisions/README.md`, `questions/README.md`, `TRACEABILITY.md`,
  `features/README.md`, `tasks/README.md`) — расти им предстоит; исключение
  оформляется записью, не молча.
- **Гейт:** сначала локально у ролей-писателей документов (`docs-writer`,
  `migrator`, `validator`) — команда в их DoD-чеклисте; затем отдельный CI-job
  `docs` в `.github/workflows/ci.yml` (`npm ci` в `.opencode` + прогон). Не
  смешивать с job `test`: доки не должны ломать Rust-DoD.
- **Поэтапность:** 0) сухой прогон на текущем корпусе → baseline и список
  исключений; 1) size-check — включаем гейтом; 2) markdownlint узким ruleset;
  3) cspell-пилот; link-check — не этап, а T-18 v0.2.
- **Риски:** шум на истории (лечится зонами-исключениями, не массовой
  правкой); npm supply-chain и дрейф версий (lock + pin); поддержка словаря
  (цену признать заранее); соблазн «проверка = качество» (линтер не заменяет
  §7 журнала и правила ролей); дубль с T-18 (закрыт единым владельцем).

## Пилот (до включения)

1. **Разведка, без гейта и без `--fix`.** Временные конфиги, прогон с корня,
   отчёт-счётчики; ничего не блокирует.
2. **size:** посчитать строки по охвату, получить список превышений → утвердить
   таблицу лимитов/исключений (SPEC/CHANGELOG/индексы).
3. **markdownlint:** прогон по канону, счётчики по правилам; правила с шумом > 0
   на каноне — либо отключить, либо разово исправить (отдельной задачей, не в
   пилоте).
4. **cspell:** `cspell --no-progress --words-only --unique` по `docs/decisions/**`
   с `ru_ru` + временным словарём; замер «уникальных неизвестных слов на 1000
   слов». Порог для решения предлагает `lead`/владелец; выше порога — отложить.
5. **Режим «только изменяемые»:** скрипт принимает список файлов в argv; в
   пилоте — вручную (`git diff --name-only`), в CI — тем же входом. Это снимает
   и риск шума на истории.
6. **Критерий выхода пилота:** прогон с корня даёт 0 нарушений на включённом
   охвате, исключения документированы, время прогона — секунды.
