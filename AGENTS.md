# AGENTS.md — репозиторий прототипа CREDO

Инструкция для агентов, работающих в **этом репозитории**: `prototypes/credo2` —
корень проекта и агентных сессий. Продуктовые DAR-документы — уровнем выше
(см. «Внешние рамки»).

## Что это за проект

**CREDO** — прототип DAR: минимальный язык банковских правил + MCP-сервер
(черновики в песочнице, публикация версий в git, опциональный REST).

- Продуктовая рамка — **DAR** (декларативный DSL кредитного конвейера).
- Исторический прототип `prototypes/credo` (in-memory песочница, инструменты
  `rule_*`/`db_*`) лежит рядом (`../credo`) и не развивается.

## Рабочая группа агентов

Сессия по умолчанию стартует с **`lead`** (оркестратор); роли команды:

| Агент | Роль | Пишет в |
|---|---|---|
| `lead` | декомпозиция, вызовы ролей, приёмка отчётов, вопросы пользователю | — |
| `migrator` | ведёт журнал Q/D: перенос `Qx` из архива, новые Q/D, сверка с кодом, задачи | `docs/questions/**`, `docs/decisions/**`, `docs/tasks/**`, `docs/TRACEABILITY.md`, `docs/OPEN_QUESTIONS.md`, `docs/SPECIFICATION.md` (§10) |
| `docs-writer` | документация: требования, SPEC, GRAMMAR, BRIEF, README, CHANGELOG, `AGENTS.md`; закрытие статусов задач | `docs/**` (кроме журнала), `AGENTS.md` |
| `coder` | задача кода `T-XX`: правки `src/`, юнит-тесты, DoD | `src/**`, `tests/**`, `Cargo.toml` |
| `tester` | независимая проверка задачи: DoD, тесты, сценарии `features/` | `tests/**` |
| `validator` | приёмка: DoD, трассируемость, канон Q41; read-only | — |
| `git` | git-операции и коммиты (изменяющие — с подтверждением) | — |

Маршруты: журнал (`Qx` — перенос или новая запись) → `migrator` → `validator`;
доработка `T-XX` → `coder` → `tester` → `validator` → `docs-writer` (закрытие
статусов задачи) → `git`; документы → `docs-writer` → `validator`.
`.opencode/**` и `opencode.json` — служебная зона: её меняет владелец, роли туда
не пишут.
Процесс ведения журнала — `docs/BRIEF.md`; реестр задач — `docs/tasks/README.md`.

## Как вызывать инструменты CREDO

Инструменты доступны агенту в Code Mode через `execute`; в каталоге имена идут с `_`
вместо точек: `tools.credo.check_create({ source })`.

| Инструмент | Назначение |
|---|---|
| `tools.credo.check_create({ source })` | Создать/перезаписать черновик из текста правила |
| `tools.credo.check_list_drafts()` | Список черновиков |
| `tools.credo.check_get_draft({ name })` | Показать черновик |
| `tools.credo.check_test({ name, input })` | Исполнить черновик на входных данных |
| `tools.credo.check_delete_draft({ name })` | Удалить черновик |
| `tools.credo.check_publish({ name, version, published_by? })` | Опубликовать версию: создаёт ветку `publish/{name}-{version}` |
| `tools.credo.check_deprecate({ name, version, reason })` | Пометить версию deprecated (пишет в `main`) |
| `tools.credo.check_list_published()` | Список опубликованного из `main` |
| `tools.credo.check_rebuild_manifest()` | Пересобрать `manifest.json` в `main` и перезагрузить кэш |

### Пример полного цикла

```js
const source = `Правило МинимальныйВозраст {
  Если (Клиент.Возраст < 21) {
    Решение = Отказ;
    Причина = "Возраст меньше 21";
  }
}`;

await tools.credo.check_create({ source });
await tools.credo.check_test({
  name: "МинимальныйВозраст",
  input: { "Клиент.Возраст": 19 },
});
// => { rule_name: "МинимальныйВозраст", condition: "Клиент.Возраст < 21",
//      matched: true, decision: "Отказ", reason: "Возраст меньше 21", actual_value: 19 }

// Публикация создаёт ветку publish/МинимальныйВозраст-1.0.0, но `main` не меняет.
// Merge ветки в `main` — git-командой из поля `next_step` ответа, затем:
await tools.credo.check_publish({ name: "МинимальныйВозраст", version: "1.0.0" });
await tools.credo.check_rebuild_manifest();
```

## Синтаксис правила

```dar
Правило ИмяПравила {
  Если (Поле < Значение) {
    Решение = Отказ;
    Причина = "текст причины";
  }
}
```

Поддерживаются:

- имя правила — одно слово (буквы/цифры/`_`, включая кириллицу);
- условие — **ровно одно сравнение**: `<`, `>`, `==`, `!=`;
- поле — любое имя, точки допускаются (`Клиент.Возраст`, `БКИ.Просрочки_12м`);
- значение — число (`21`, `3.5`) или строка;
- решение — одно слово (`Отказ`, `Одобрено`, ...);
- причина — строка в двойных кавычках (необязательна).

Строковые значения сравниваются только через `==` и `!=`.

## Важные особенности и подводные камни

1. **Состояние персистентно.** Черновики — `.credo/sandbox.json` в корне репозитория;
   опубликованные версии — bare-git `.credo/published-repo`, источник истины — ветка `main`.
   Перезапуск сервера состояние не теряет (в отличие от исторического `prototypes/credo`).
2. **Публикация — через ветку.** `check.publish` создаёт `publish/{name}-{version}` и не трогает
   `main`; до merge версия не видна ни REST, ни манифесту. Merge ветки в `main` — командой из поля
   `next_step` ответа; выполняет его человек (git-роль агентов ветки публикаций не мержит).
   После merge — `check.rebuild_manifest` (либо подождать: кэш REST обновится за ~2 с).
3. **Правила semver при публикации.** Дубликат версии и downgrade отклоняются; изменение входов
   контракта требует поднять MAJOR.
4. **Отсутствующее поле — строгая ошибка (Q8), а не `0`.** Несовместимые типы — тоже ошибка
   (Q9). В MCP это `isError`, в REST — 422 `evaluation_failed`. На вход подавайте реальные поля.
5. **Deprecated-версия не исполняется:** REST — 410 `version_deprecated`; active-эндпоинт при
   отсутствии active-версии — 409 `activation_unavailable`; в манифесте `active` — пустая строка,
   если все версии deprecated.
6. **Язык правил намеренно минимален.** Нет `И`, `Или`, `Но`, ветвлений, вложенных условий,
   списков, приоритетов и политик. Если задача требует этого — сначала расширьте
   `parse_rule`/`evaluate_rule` в `src/core.rs`, потом меняйте правила.
7. **Парсер — на регулярных выражениях**, не полноценный грамматический разбор. Формат нужно
   соблюдать буквально (ключевые слова, скобки, `;`).
8. **Обработка запросов конкурентна.** Сервер может ответить не в порядке отправки. Если нужна
   строгая последовательность — делайте вызовы последовательно (`await` один за другим), не пачкой.
9. **REST включается флагами** `--rest` / `--addr <ADDR>` (по умолчанию — только MCP/stdio;
   приоритет `--no-rest` > `--addr` > `--rest`). Адрес по умолчанию `127.0.0.1:8080`,
   Swagger — `/docs`, спека — `/openapi.json`. Ключ — `--api-key`/`CREDO_API_KEY` (заголовок
   `x-api-key`); без ключа API открыт (режим демо).

## Гигиена и чтение

- Обход дерева — по правилу `.opencode/rules/workspace.md`: узкие `glob`/`rg`
  по `src/`, `tests/`, `docs/`; не обходить `target/`, `node_modules/`,
  `.credo/`, `.git/`.
- Большие документы (`docs/OPEN_QUESTIONS.md`, `docs/SPECIFICATION.md`) читать
  по карте заголовков (`rg -n "^#{1,3} " <файл>`) и точечно, а не целиком.
- Методика ревью и приёмки — `.opencode/rules/review.md`.
- Быстрая проверка относительных ссылок — `docs/BRIEF.md` §9.

## Сборка, тесты и пересборка

```sh
cargo build --release

# DoD прототипа (из корня репозитория):
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test --all
```

После пересборки `credo2.exe` MCP-сервер нужно переподключить (перезапустить службу,
`opencode service restart`), иначе будет работать старая версия.

## Git

- Конвенции коммитов — `.opencode/rules/git-workflow.md`; git-операции выполняет
  роль `git`, изменяющие команды — с подтверждением пользователя.
- Коммит — после успешной приёмки (`validator`), одна запись/задача — один коммит.

## rust-analyzer

В `opencode.json` настроен MCP-сервер `rust-analyzer` с workspace — этот репозиторий.
Если инструмент падает с `rust-analyzer exited before responding`, проверьте, что установлен компонент:

```sh
rustup component add rust-analyzer
```

## Внешние рамки

- DAR-документы (`concept.md`, `SCOPE.md`, `NON_GOALS.md`, `ROADMAP.md`,
