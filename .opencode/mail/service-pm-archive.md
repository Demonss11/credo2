# Сервисная лента: service-pm-archive (доработка `pm`: `output/`, архив событий, снимок в clean-logs)

**Назначение:** доработка инструмента `pm` по запросу владельца (30.09.2026):
артефакты — в `.opencode/scripts/pm/output/` (одна папка, перезапись; вне git);
накопительный архив событий `output/events.jsonl` без дублей, устойчивый к
очистке лент `clean-logs.mjs`; best-effort снимок лент в архив перед удалением
в самом `clean-logs.mjs`.

**Решение владельца (30.09.2026, гейт планирования):**

1. папка результатов — `output/` внутри `pm/` (имя из открытого пункта досье
   `pm-tool-design`; локальный `.gitignore` уже содержит `output/`);
2. раскладка — одна папка, файлы прогона перезаписываются (история — в архиве,
   любой срез восстанавливается повторным прогоном);
3. связка с `clean-logs.mjs` — снимок перед удалением лент по умолчанию
   (best-effort, с предупреждением при сбое; `--no-snapshot` — opt-out).

**Маршрут службы:** `migrator` («Обновление 30.09.2026» в D81) → сервисная
сессия (код, тесты, README, `AGENTS.md`, `clean-logs.mjs`) → `auditor`
(аудит канон-правки) → `validator` (приёмка) → `git` (пакет по гейту).

**Границы:** `.opencode/scripts/**`, `AGENTS.md` (строка `clean-logs`);
`src/**`, `tests/**` (Rust), `Cargo.toml`, `state/current/*` не трогаются;
`cargo` не запускается (D50).

Формат записей — `AGENTS.md` §«Память и почта».
