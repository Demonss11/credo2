# Правила: общие для документов

**Когда читать:** перед оформлением или правкой любого документа, который
ведёт `@tech-writer`. Затем — правило конкретного типа документа.

## Область

Документы `@tech-writer`: ADR, Design Doc, Roadmap, ТЗ/ФТ, RFC, User
Stories. Код, `README.md`, `AGENTS.md` и `.gitverse/ТЕХДОЛГ.md` — не сюда.

## Принципы

- Один документ — одна тема. Идеи, решения и задачи не смешивать.
- Источник истины — документ, а не пересказ. Не дублировать одно правило в
  двух местах; при повторе — ссылка на канон.
- Менять минимально: не переписывать соседние разделы «заодно».
- Не добавлять пустые разделы-заглушки ради структуры.

## Объём и границы

- Целевой размер документа — не более 300 строк; лимит проверяет
  `npm run check:size`.
- Признаки разрастания: раздел-свалка, повторы, «история изменений» внутри
  текста, несколько тем в одном файле.
- Признак сработал — дели документ по темам или выноси часть в отдельный
  документ со ссылкой; не дописывай в конец «ещё немного».
- Не дублируй содержимое другого документа — ссылайся на канон.

## Язык

- Текст, заголовки, комментарии — на русском; идентификаторы, пути, имена
  полей — латиницей.
- Термины употреблять в одном значении; новое понятие — определить при
  первом использовании.
- Активный залог, повелительное наклонение в требованиях.
- Запрещены «очевидно», «просто», «легко», «в принципе», вода и
  прилагательные без факта.

## Структура

- `#` — один заголовок документа; далее иерархия `##` / `###`.
- После заголовка — метаданные списком: `- Статус:`, `- Дата:` (ISO
  `ГГГГ-ММ-ДД`), `- Связано:` (относительные ссылки).
- Перечисления — маркированные списки; сравнения и поля — таблицы.
- Примеры — в блоке кода с указанием языка; пример должен быть рабочим.

## Ссылки и графика

- Ссылки только относительные и на существующие файлы; проверяй путь.
- Диаграмма (Mermaid) — только если текст не справляется; подпись с `alt`.
- Якорь для ссылки внутри документа — короткий и стабильный.

## Статусы

Единый набор там, где применимо:
`черновик` | `предложено` | `принято` | `устарело` | `заменено`.
Значение статуса задаёт правило конкретного документа.

## Проверка и приёмка

- После правок отдай документ `@secretary`: он прогоняет `npm run check`
  (markdownlint + размер + cspell + ссылки). Сам проверки не запускай.
- `@tech-writer` — автор. Статус `принято` ставит пользователь или `@pm`.
- Битые ссылки чинятся, слова добавляются в `.gitverse/tools/project-words.txt`.

## Чтение и правка больших файлов

Не читай документ целиком, если правила — на пару мест:

1. Карта заголовков: `rg -n "^#{1,3} " <file>`.
2. Точечное чтение: `read` с `offset`/`limit` по нужному разделу.
3. Правка: `edit` по короткому уникальному якорю с 2–3 строками контекста.
4. После правки файл не перечитывай.

## Экономия контекста

Читай только правило нужного типа документа, а не весь каталог. Не
дублируй сюда содержимое `doc-*.md`.
