# Правила: ТЗ / ФТ

**Когда читать:** оформление технического задания или функциональных
требований.

## Термины

- **ТЗ** — задание целиком: зачем, для кого, границы.
- **ФТ** — функциональные требования: что система делает.
- **НФТ** — нефункциональные: производительность, надёжность,
  безопасность, совместимость.

## Расположение

- `docs/**` или `.gitverse/docs/**`; конкретный путь задаёт бриф.
- Общее — `doc-common.md`.

## Структура

```md
# <Название>: техническое задание

- Статус: <черновик | принято>
- Дата: <ГГГГ-ММ-ДД>

## Назначение

## Область и границы

## Роли и сценарии использования

## Функциональные требования

| ID | Требование | Приоритет | Проверка |
|----|------------|-----------|----------|
| FR-1 | … | must | … |

## Нефункциональные требования

| ID | Требование | Метрика |
|----|------------|---------|
| NFR-1 | … | … |

## Критерии приёмки

## Трассируемость
```

## Правила требований

- Требование нумеруется (`FR-N` / `NFR-N`), атомарно и проверяемо.
- Одно требование — одно утверждение; не соединять «и», «или».
- Формулировка — в повелительном наклонении, без «быстро», «удобно» без
  метрики.
- У каждого `must`-требования есть способ проверки.

## Чек-лист

- [ ] Заданы назначение и границы.
- [ ] Требования пронумерованы и атомарны.
- [ ] У `must`-требований есть проверка.
- [ ] Критерии приёмки и трассируемость заполнены.
