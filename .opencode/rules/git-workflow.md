# Правило: git-workflow (credo2)

**Когда читать:** перед любой работой с git.

## Роли

- `@git` — единственная роль, выполняющая git-команды: read-only — свободно,
  изменяющие и сетевые — с подтверждением пользователя.
- Остальные роли git не трогают: они готовят файлы, коммит делает `@git`.

## Ветки

- `master` — рабочая ветка (trunk); remote `origin` — GitHub.
- Отдельные ветки — только для крупных изменений по согласованию; git-flow
  (`develop`/`release/*`) не используется.

## Формат коммитов

| Префикс | Когда | Пример |
|---|---|---|
| `docs(Qn): …` | перенос вопроса в журнал | `docs(Q2): перенос в журнал` |
| `docs(Dn): …` | решение, структура документации | `docs(D15): ссылки и трассировка` |
| `code(T-XX): …` | задача кода | `code(T-10): workspace dar-core + credo-server` |
| `chore: …` | конфиг, агенты, служебное | `chore: рабочая группа агентов` |

- Одна запись журнала — один коммит (`docs/BRIEF.md` §5.7); одна задача — один коммит.
- Описание — по-русски, кратко, без «WIP».

## Ограничения

- `git add` — точными путями, не «`git add -A` по привычке».
- Подтверждение — **пакетное**: после приёмки `lead` передаёт список коммитов,
  пользователь подтверждает один раз; роль `git` выполняет пакет шаг за шагом.
- Идемпотентность: перед каждым шагом проверь состояние (`git status`,
  `git log -1`) — уже сделанное (коммит есть, ветка создана) пропусти и продолжай.
- `git push` — с таймаутом не менее 5 минут; обрыв — повторить статус и продолжить,
  не переписывая историю.
- Ветки публикаций CREDO (`publish/{name}-{version}` в `.credo/published-repo`)
  агент не мержит: merge в `main` делает человек.
- Запрещены `--force`, `push --force`, `reset --hard`, `rebase` и любое
  переписывание опубликованной истории.
- Push — только после подтверждения пользователя.
- Коммит — после успешной приёмки (`validator`), не раньше.
- `target/`, `.credo/`, `node_modules/` не коммитятся (см. `.gitignore`).
- Память и почта ролей (`.opencode/memory/**`, `.opencode/mail/**`) — вне git:
  операционные данные, не канон.
