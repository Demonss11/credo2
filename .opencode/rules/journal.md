# journal — правила ведения журнала Q/D

**Статус:** канон процесса журнала Q/D прототипа `credo2` (перенесено из
`docs/BRIEF.md` — решение [D71](../../docs/decisions/D71-journal-rules-relocation.md)).
Карта документации — `docs/README.md`; связи и жизненный цикл —
`docs/TRACEABILITY.md` (D63).

## 1. Принципы

- **Один факт — один канон** (D60); «ссылка, не копия» и «время жизни адреса»
  (D65) — без копий формулировок и без ссылок на удаляемые данные.
- ID стабильны и не переиспользуются; записи не удаляются — меняется статус
  (`dropped`, `superseded`).
- У каждого решения есть вердикт «Сверка с кодом» (документные — ⚪).
- Журнал — единственный источник контекста «вопрос → решение»; `SPECIFICATION.md` —
  целевая архитектура без дублей решений.

## 2. Идентификаторы

- Вопрос — `docs/questions/Qn.md`; номер `Qn` сквозной.
- Решение — `docs/decisions/Dn-<слаг>.md`; номер `Dn` **сквозной** (исторически
  совпадал с № строки `SPECIFICATION.md` §10; таблица §10 упразднена — D70).
- Слаг — kebab-case, не переименовывается. Ссылки — по ID и файлу, не по номеру
  строки.

## 3. Жизненный цикл

- Q: `open` → `resolved by Dn` | `dropped`.
- D: `accepted` → `superseded by Dm` | `rejected`.
- Задача `T-XX`: ⬜ → 🚧 → ✅ (канон статусов — `docs/tasks/README.md`).
- Сводный жизненный цикл — `docs/TRACEABILITY.md`: `open` · `resolved` ·
  `in work` · `done` · `dropped`.

## 4. Шаблоны

### Вопрос (Qn)

`# Qn: <формулировка>`; поля — Статус / Дата / Приоритет / Связано; разделы —
Контекст · Вопрос · Варианты · Рекомендация.

### Решение (Dn)

`# Dn: <формулировка>`; поля — Статус / Дата / Resolves / Спека / Affects /
Tasks; разделы — Контекст · Решение · Следствия · Сверка с кодом · Альтернативы ·
Ссылки. Поле «Спека» — только уточняемые разделы `SPECIFICATION.md` в актуальной
нумерации; иначе `—`.

## 5. Рецепты

### 5.1 Завести вопрос

1. Возьми следующий свободный `Qn`.
2. Создай `docs/questions/Qn.md` (статус `open`) по шаблону §4.
3. Занеси строку в `docs/TRACEABILITY.md`.
4. Если вопрос — расхождение документа с кодом: понизь статус затронутого
   требования до 🟡 в `docs/features/README.md` (зона `docs-writer`).

### 5.2 Принять решение

1. Возьми следующий свободный `Dn` (сквозная нумерация).
2. Создай `docs/decisions/Dn-<слаг>.md` по шаблону §4.
3. Выполни сверку с кодом (§5.3).
4. Заведи задачу `T-XX` или зафиксируй «задач не требуется».
5. Смени статус вопроса на `resolved by Dn`.
6. Обнови `docs/questions/README.md`, `docs/decisions/README.md`,
   `docs/TRACEABILITY.md`.
7. Если `Affects` не пуст — обнови требования/фичи и обратные ссылки
   (зона `docs-writer`).

### 5.3 Сверка решения с кодом

Карта зон — `docs/features/README.md` («Соответствие коду»). Читай код и тесты;
**`cargo` не запускается**: адресный прогон выполняет `validator`. Вердикты:
✅ соответствует · 🟡 расхождение (→ задача) · ⬜ не реализовано (→ задача) ·
⚪ не применимо (документы/процесс).

### 5.4 Снять вопрос (`dropped`)

Статус Q — `dropped`; сделка в `TRACEABILITY.md`; D-файл не заводится.

### 5.5 Заменить решение (`superseded`)

Новое решение — новый `Dn`; у старого статус `superseded by Dm`; номера не
переиспользуются.

### 5.6 Решение меняет поведение (feature)

`docs-writer` дополняет или меняет требования `docs/features/**` и обратную
пометку `# Dn (Qx): …` в шапке фичи.

### 5.7 Чек-лист перед коммитом

Прогоны и DoD — `AGENTS.md` §Сборка (D50); одна запись журнала — один коммит;
ссылки живые; статусы и сводки синхронны; номера не переиспользованы.

## 6. Связи

`docs/TRACEABILITY.md` — единая таблица `Q | D | Жизненный цикл | Задачи |
Реализация`; таблица — **представление**: статусы задач и требований берутся из
своих канонов (`docs/tasks/README.md`, `docs/features/README.md`) и не
дублируются (D63).

## 7. Целостность

Основной механизм — тест `tests/docs_journal.rs` (`T-18`, решение D64):
уникальность ID, парность Q↔D, записи в каталогах, вердикт сверки,
согласованность `TRACEABILITY`, запрет номеров строк и миграционных маркеров,
«время жизни адреса». Вспомогательно — ручной мини-чек битых относительных
ссылок.

## 8. Антипаттерны

- Ссылки на номера строк; ссылки канона на удаляемые/сессионные данные
  (`.opencode/mail/**`, `.opencode/state/**`) — «время жизни адреса» (D65).
- Копии формулировок решений вместо ссылок; дубли правил между документами.
- Q без D (кроме `dropped`); D без записи в каталоге; D без «Сверки с кодом».
- Задача без источника `Dn`/`Qn`; переписывание принятых решений «задним числом».
- Ретро-D без пометки «до-журнальное, оформлено ретроспективно».
