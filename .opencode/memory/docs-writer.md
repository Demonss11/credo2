# Память роли `docs-writer`

## Знание роли

- **Требования и статусы** — `docs/features/README.md`: статусы ✅/🟡/⬜/⏸ и
  приоритеты только здесь; счётчики проверяет `tests/features_inventory.rs`.
  Правка требований — `validator` по запросу `lead` (R2), `cargo` сам не гоняю
  (D50).
- **Границы записи:** `docs/**`, кроме журнала (`docs/questions/`,
  `docs/decisions/`, `docs/tasks/**`, `docs/TRACEABILITY.md`,
  `docs/SPECIFICATION.md §10` — `migrator`) и `docs/reviews/**` (`validator`).
  `AGENTS.md`/`.opencode/**` — служебная зона владельца.
- **Статусы задачи** (`docs/tasks/T-XX-*/README.md` + сводка): 🚧 при взятии,
  ✅ после приёмки. Ссылку на отчёт приёмки из карточки не ставлю (канон на
  `docs/reviews/**` не ссылается).
- **CHANGELOG** — только кодовые изменения продукта (D72); доки/процесс — в
  журнал Q/D.
- Проверка ссылок — чтением (`glob`/`rg`), пути относительные. Не обходить
  `target/`, `node_modules/`, `.credo/`.

## Приёмы

- Минимальная локализация правки: сначала прочитать нужные строки узким
  offset/limit или `rg -n`, потом `edit` с точным `oldString`.
- При открытии новой строки — сверить её формулировку с каноном решения
  (`docs/decisions/Dn-*.md`) и лентой задачи; сверить счётчик сценариев
  (`rg -c "Сценарий:" <feature>`).
- Лента задачи — append отдельной секцией; не переписывать чужие записи.
