# Функциональные требования к DAR Notebook (UI) в формате Gherkin 📋

Ниже — полный набор `.feature` файлов для UI-части DAR Notebook. Эти сценарии дополняют backend-требования и формируют **целостную картину продукта**.

---

## 📁 `features/notebook_ui.feature` — Основной интерфейс приложения

```gherkin
# language: ru
Функция: Основной интерфейс DAR Notebook
  Как риск-технолог
  Я хочу видеть все компоненты в одном окне
  Чтобы не переключаться между редактором, терминалом и git-клиентом

  Сценарий: Трёхколоночный layout при запуске
    Дано DAR Notebook запущен
    Когда окно приложения открывается
    Тогда левая панель содержит файловое дерево
    И центральная панель содержит редактор кода
    И правая панель содержит чат с агентом
    И все три панели видны одновременно

  Сценарий: Открытие workspace из файловой системы
    Дано пользователь выбирает папку "consumer-credit"
    Когда workspace загружается
    Тогда файловое дерево отображает все .dar файлы из папки
    И файлы сгруппированы по подпапкам (rules, tables, tests)
    И статус git отображается в заголовке

  Сценарий: Создание нового workspace
    Дано пользователь нажимает кнопку "Новый workspace"
    Когда пользователь выбирает пустую папку
    Тогда создаётся структура папок (rules, tables, tests)
    И создаётся файл README.md с инструкциями
    И workspace отображается в файломом дереве

  Сценарий: Командная палитра (Cmd+P)
    Дано DAR Notebook открыт
    Когда пользователь нажимает Cmd+P
    Тогда появляется модальное окно с командами
    И список команд включает "Создать правило", "Выполнить", "Опубликовать"
    И выбор команды исполняет соответствующее действие

  Сценарий: Сохранение изменений при закрытии
    Дано пользователь изменил файл "МинимальныйВозраст.dar"
    И изменения не сохранены
    Когда пользователь закрывает приложение
    Тогда появляется диалог "Сохранить изменения?"
    И выбор "Сохранить" записывает изменения в файл
```

## 📁 `features/editor.feature` — Редактор .dar файлов

```gherkin
# language: ru
Функция: Редактирование .dar файлов с подсветкой синтаксиса
  Как риск-технолог
  Я хочу редактировать правила с подсветкой и автодополнением
  Чтобы писать код быстрее и с меньшим количеством ошибок

  Сценарий: Открытие файла в редакторе
    Дано в файловом дереве существует файл "МинимальныйВозраст.dar"
    Когда пользователь кликает на файл
    Тогда содержимое файла загружается в центральную панель
    И синтаксис подсвечивается (ключевые слова, числа, строки)
    И курсор устанавливается в начало файла

  Сценарий: Подсветка синтаксиса DAR
    Дано открыт файл с текстом:
      """
      Правило МинимальныйВозраст {
        Приоритет: 100;
        Если (Клиент.Возраст < 21) {
          Решение = Отказ;
          Причина = "Возраст меньше 21";
        }
      }
      """
    Тогда слово "Правило" подсвечивается как ключевое слово
    И слово "Если" подсвечивается как ключевое слово
    И число "21" подсвечивается как число
    И строка "Возраст меньше 21" подсвечивается как строка

  Сценарий: Автодополнение ключевых слов
    Дано пользователь вводит "Пр"
    Когда пользователь нажимает Ctrl+Space
    Тогда появляется список автодополнения
    И список содержит "Правило", "Приоритет", "Причина"
    И выбор "Правило" вставляет слово в редактор

  Сценарий: Диагностика ошибок в реальном времени
    Дано пользователь вводит некорректный синтаксис:
      """
      Правило {
        Если (Клиент.Возраст < 21)
      """
    Тогда под строкой с ошибкой появляется красная волнистая линия
    И при наведении показывается сообщение "Ожидалось имя правила"
    И ошибка обновляется при каждом изменении текста

  Сценарий: Сохранение файла при Ctrl+S
    Дано пользователь изменил текст в редакторе
    Когда пользователь нажимает Ctrl+S
    Тогда изменения записываются в файл на диске
    И индикатор "изменён" в заголовке исчезает
    И файловое дерево обновляет статус файла

  Сценарий: Индикатор несохранённых изменений
    Дано файл "МинимальныйВозраст.dar" открыт в редакторе
    Когда пользователь вносит изменения
    Тогда в заголовке появляется индикатор "●"
    И в файловом дереве файл помечается как изменённый
    И при закрытии файла запрашивается подтверждение

  Сценарий: Открытие нескольких файлов в табах
    Дано открыт файл "МинимальныйВозраст.dar"
    Когда пользователь кликает на "Просрочки.dar" в дереве
    Тогда файл открывается в новой вкладке
    И обе вкладки видны в панели вкладок
    И переключение между вкладками загружает соответствующий файл
```

## 📁 `features/inline_execution.feature` — Инлайн-исполнение правил

```gherkin
# language: ru
Функция: Исполнение правил и отображение результатов в редакторе
  Как риск-технолог
  Я хочу видеть результат исполнения прямо под кодом
  Чтобы быстро проверять гипотезы без публикации

  Сценарий: Кнопка исполнения под правилом
    Дано открыт файл с правилом "МинимальныйВозраст"
    Когда редактор загружает файл
    Тогда под блоком правила появляется кнопка "▶ Выполнить"
    И кнопка находится сразу после закрывающей скобки правила

  Сценарий: Ввод тестовых данных перед исполнением
    Дано пользователь нажал кнопку "▶ Выполнить"
    Когда появляется диалог ввода данных
    Тогда пользователь может ввести JSON:
      """
      {"Клиент.Возраст": 19}
      """
    И диалог содержит примеры полей из правила
    И кнопка "Выполнить" становится активной после ввода данных

  Сценарий: Отображение результата под правилом
    Дано пользователь ввёл данные "Клиент.Возраст = 19"
    Когда правило исполняется
    Тогда под кнопкой появляется блок результата
    И блок содержит "❌ Отказ"
    И блок содержит "Причина: Возраст меньше 21"
    И блок содержит "Правило: МинимальныйВозраст"
    И блок содержит "Приоритет: 100"

  Сценарий: Обновление результата при изменении входных данных
    Дано результат показывает "Отказ" для возраста 19
    Когда пользователь меняет входные данные на "Клиент.Возраст = 25"
    Тогда результат обновляется автоматически
    И блок показывает "✓ Правило не сработало"
    И обновление происходит без перезагрузки страницы

  Сценарий: Отображение ошибки исполнения
    Дано правило обращается к полю "Клиент.Несуществующее"
    Когда правило исполняется на пустых данных
    Тогда блок результата показывает ошибку
    И ошибка содержит "Неизвестное поле: Клиент.Несуществующее"
    И ошибка подсвечивается красным цветом

  Сценарий: Сохранение последних входных данных
    Дано пользователь ввёл данные для теста
    Когда пользователь закрывает и открывает файл
    Тогда последние входные данные сохраняются в .dar-notebook/
    И при следующем исполнении показываются сохранённые данные

  Сценарий: Множественные тесты для одного правила
    Дано пользователь хочет протестировать три сценария
    Когда пользователь добавляет три набора входных данных
    Тогда под правилом отображаются три блока результата
    И каждый блок показывает свой набор данных и результат
    И блоки можно сворачивать/разворачивать
```

## 📁 `features/git_integration.feature` — Git-интеграция в UI

```gherkin
# language: ru
Функция: Визуальная работа с git из интерфейса
  Как риск-технолог
  Я хочу видеть статус изменений и публиковать правила без командной строки
  Чтобы сосредоточиться на бизнес-логике, а не на git-командах

  Сценарий: Отображение git status в заголовке
    Дано workspace содержит git-репозиторий
    Когда пользователь открывает workspace
    Тогда в заголовке отображается текущая ветка
    И рядом отображается количество изменённых файлов
    И индикатор показывает, есть ли несохранённые коммиты

  Сценарий: Визуальный diff для изменённого файла
    Дано файл "МинимальныйВозраст.dar" изменён
    Когда пользователь кликает на индикатор изменений
    Тогда открывается панель diff
    И слева показана старая версия (из git)
    И справа показана новая версия (из редактора)
    И изменения подсвечиваются цветом (добавлено/удалено)

  Сценарий: Commit через UI
    Дано есть несохранённые изменения в файлах
    Когда пользователь нажимает кнопку "Commit"
    Тогда появляется диалог с полем для сообщения коммита
    И список изменённых файлов с чекбоксами
    И после ввода сообщения и нажатия "Commit" изменения сохраняются в git

  Сценарий: Публикация правила через UI
    Дано файл "МинимальныйВозраст.dar" сохранён и закоммичен
    Когда пользователь нажимает кнопку "Опубликовать"
    Тогда появляется диалог с полем версии (1.0.0)
    И после ввода версии вызывается MCP-инструмент check.publish
    И в правом нижнем углу появляется уведомление "Опубликовано v1.0.0"

  Сценарий: История версий файла
    Дано файл "МинимальныйВозраст.dar" имеет несколько версий в git
    Когда пользователь открывает панель истории
    Тогда отображается список коммитов с датами и авторами
    И каждый коммит можно открыть для просмотра diff
    И можно откатиться к любой предыдущей версии

  Сценарий: Индикатор deprecated версии
    Дано версия "0.9.0" правила помечена как deprecated
    Когда пользователь открывает историю версий
    Тогда deprecated версии помечены иконкой ⚠️
    И при выборе deprecated версии показывается предупреждение
```

## 📁 `features/agent_minimal.feature` — Минимальный чат с агентом

```gherkin
# language: ru
Функция: Чат с AI-агентом для создания и модификации правил
  Как риск-технолог
  Я хочу описывать требования естественным языком
  Чтобы агент создавал правила через MCP-инструменты

  Сценарий: Открытие панели агента
    Дано DAR Notebook открыт
    Когда пользователь кликает на иконку чата в правой панели
    Тогда открывается панель с историей диалога

    Дано пользователь вводит сообщение:
      """
      Создай проверку: если возраст клиента меньше 21, то отказ с причиной "Возраст меньше 21"
      """
    Когда агент обрабатывает сообщение
    Тогда агент вызывает MCP-инструмент check.create
    И в чате появляется ответ "✅ Черновик 'МинимальныйВозраст' создан"
    И в файловом дереве появляется новый файл

  Сценарий: Тестирование правила через чат
    Дано существует черновик "МинимальныйВозраст"
    Когда пользователь вводит "Протестируй на клиенте 19 лет"
    Тогда агент вызывает MCP-инструмент check.test
    И в чате появляется ответ "❌ Отказ: Возраст меньше 21"
    И ответ содержит фактическое значение (19)

  Сценарий: Публикация правила через чат
    Дано черновик успешно протестирован
    Когда пользователь вводит "Публикуй версию 1.0.0"
    Тогда агент вызывает MCP-инструмент check.publish
    И в чате появляется ответ "✅ Опубликовано v1.0.0"
    И в заголовке появляется уведомление

  Сценарий: Отображение вызванных инструментов в чате
    Дано агент вызывает MCP-инструмент
    Когда инструмент выполняется
    Тогда в чате появляется блок с именем инструмента
    И блок содержит параметры вызова
    И блок содержит результат выполнения
    И блок можно свернуть/развернуть

  Сценарий: Обработка ошибок в чате
    Дано пользователь запрашивает несуществующее правило
    Когда агент пытается выполнить check.test
    Тогда в чате появляется сообщение об ошибке
    И сообщение содержит понятное объяснение
    И агент предлагает исправить проблему

  Сценарий: Сохранение истории диалога
    Дано пользователь провёл диалог с агентом
    Когда пользователь закрывает и открывает приложение
    Тогда история диалога восстанавливается из .dar-notebook/
    И пользователь может продолжить диалог с того же места
```

## 📁 `features/lsp.feature` — Language Server Protocol

```gherkin
# language: ru
Функция: LSP-сервер для DAR {} файлов
  Как разработчик или риск-технолог
  Я хочу получать подсказки, диагностику и навигацию в любом редакторе
  Чтобы писать правила быстрее и с меньшим количеством ошибок

  Сценарий: Инициализация и рукопожатие с клиентом
    Дано клиент отправляет запрос "initialize" с параметрами:
      | capabilities | { "textDocument": { "completion": {}, "hover": {} } } |
    Когда LSP-сервер обрабатывает запрос
    Тогда ответ содержит "capabilities" сервера
    И ответ содержит "serverInfo" с именем "dar-lsp"
    И сервер поддерживает синхронизацию документов
    И сервер поддерживает диагностику
    И сервер поддерживает автодополнение

  Сценарий: Открытие документа и первичная диагностика
    Дано клиент отправляет уведомление "textDocument/didOpen" с текстом:
      """
      Правило МинимальныйВозраст {
        Приоритет: 100;
        Если (Клиент.Возраст < 21) {
          Решение = Отказ;
          Причина = "Возраст меньше 21";
        }
      }
      """
    Когда сервер парсит документ
    Тогда публикуется уведомление "textDocument/publishDiagnostics"
    И список диагностик пуст (ошибок нет)

  Сценарий: Диагностика синтаксической ошибки
    Дано клиент открывает документ с текстом:
      """
      Правило {
        Если (Клиент.Возраст < 21) {
          Решение = Отказ;
        }
      }
      """
    Когда сервер парсит документ
```
